# 행정동 분석 보고서

실행 입력과 이전 작업의 원본은 State의 작업 이력이다. 요청 월과 동을
변경하지 않는다. 분석 결과의 수정 시각을 보고서 생성 시각과 구분한다.

## 시각화 선정과 근거 확보

데이터 조회·가공 도구로 상세 뷰의 설명에 필요한 근거를 확보한다.
EmbedDetailV01~08 중 데이터에 적합한 서로 다른 3개를 고른다.
각 뷰에 선정 이유와 검증된 조회·가공 기록의 ID를 연결한다.
확보한 관측에서 설명할 현상을 정하고, 이를 직접 보여주거나 해석 범위·배경을
보완하는 뷰를 고른다. 변화가 작은 뷰도 비교 범위를 좁히는 근거가 될 수 있다.
동일한 조합을 다시 선정할 수 있다.
원지표를 점수 기여도로 바꾸거나 계산되지 않은 비교값을 만들지 않는다.

V01·V07의 추세 범위는 요청 월을 포함한 최근 6개월이다.
나머지 뷰는 요청 월을 기준으로 하며, 전월 비교에 필요한 이전 자료는 조회한다.
선정·선정 검토에서는 이미 확보한 근거로 각 뷰가 설명에 더하는 내용을 판단한다.
고정된 조합이나 모든 비교 항목의 확보를 요구하지 않으며 도구를 호출하지 않는다.

## 뷰별 설명 작성

검증된 선정 결과와 연결된 근거만 사용한다. 뷰별로 한 단락, 최대 3문장이다.
뷰에서 표현하는 대상·수치·기간·비교 범위를 준수한다.
관측 사실과 해석 가능한 범위를 구분하고 없는 수치나 원인을 만들지 않는다.
해당 뷰와 연결된 근거에서 핵심 관측이 무엇을 의미하는지 설명한다.
다른 뷰의 근거를 끌어와 설명 범위를 넓히지 않는다.

## 퀵 인사이트 작성

검증된 뷰별 설명과 근거만 요약한다. 항목당 한 문장, 총 3~4개다.
문장 사이를 줄바꿈한다. 내용 중복과 새로운 주장을 넣지 않는다.
설명에서 확인한 변화·유지의 의미와 검토할 지점을 우선 요약한다.
새 계산·지역 맥락·해석 후보를 추가하지 않는다.

## 자기 검토

작성과 별도의 호출에서 초안을 근거와 대조한다. 작성·검토에서는 도구를 호출하지 않는다.
설명은 수치·기간·비교의 일치, 뷰의 표현 범위, 한 단락·최대 3문장을 검사한다.
핵심 관측의 의미가 근거와 연결되는지 공통 분석 해석 기준으로 검토한다.
퀵 인사이트는 3~4개 한 문장, 검증된 설명과의 일치, 중복·새 주장 여부를 검사한다.
부적합이면 재작성에 사용할 구체적인 이유를 reason에 쓴다.
초안을 직접 수정하지 않고 accepted와 reason을 반환한다.
재작성은 이전 초안과 부적절 사유를 입력으로 받아 해당 사유를 해결한다.
각 항목은 최초 작성 뒤 최대 3회 수정·재검토한다.
검토를 통과하지 못한 항목은 최종 보고서에서 NULL로 처리한다.
