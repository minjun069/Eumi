# 시각화 작업 선택

적용 대상: 사용자 요청 처리 Agent, 데이터 시각화 Agent의 작업 목적 파악·작업 선택. 지침 ID: `visualization-selection`, 버전: `3`, 시행일: 2026-11-06.

## 목적과 선택 기준

게시된 Tableau 뷰를 선택하고 해당 뷰의 표시 조건을 정한다. `visualization_catalog.views`의 `purpose`로 목적을 비교하고 `limitations`로 표현 가능한 범위를 확인한다. 뷰 목록·설명의 원본은 `tools/tableau_catalog.json`이며 이 지침에 뷰별 설명을 중복해서 정의하지 않는다.

지도의 색상·위험 단계·배경 취약성·행동 이상을 같은 지표로 취급하지 않는다. 가구 구성 비율을 위험 점수로 바꾸어 설명하지 않는다. 한 지역의 결과로 개인을 진단하거나 방문 우선순위를 확정하지 않는다.

## 조건 결정

`allowed_visualization_views`는 호출 측이 이번 실행에 허용한 뷰 목록이다. 선택 카탈로그에는 이 범위의 뷰·입력 프로필만 제공된다. 목록이 비면 시각화를 제공할 수 없다고 설명한다. 사용자 발화·이벤트 이름·이전 호출 이력으로 허용 범위를 넓히거나 다른 뷰를 추측해 호출하지 않는다. 기존 시각화의 재사용도 같은 범위를 따른다.

1. 현재 요청·화면·대화에서 확인한 조건을 우선 사용한다. 후속 요청은 기존 산출물의 조건 중 변경되지 않은 조건을 명시적으로 이어받는다.
2. 작업 선택 시 뷰의 `input_profile`로 `visualization_catalog.input_profiles`를 참조한다. 등록된 매개변수·필터만 사용하며 다른 뷰의 입력을 섞지 않는다. 날짜 값은 `YYYY-MM-DD`이고 모든 값은 문자열이다.
3. 매개변수는 `allowed`와 표시 이름 `labels`를 확인한다. 기본값 없는 매개변수는 필수다. 날짜 간 선후 관계는 `date_orders`를 따른다. 날짜가 없는 뷰에 기간을 추가하지 않는다.
4. 필터의 `allowed`는 허용값, `depends_on`은 허용값이 달라지는 매개변수다. 이미 확인된 조건의 상세 목록은 `selected[뷰 식별자]`에 있다. 상세 목록이 없으면 사용자가 명시한 값을 그대로 검증하고, 부적합 시 도구가 반환한 허용값을 사용한다. 허용 목록을 추측하거나 누락된 목록을 지원하지 않는 필터로 해석하지 않는다.
5. 각 뷰의 시간 의미·비교 한계를 지킨다. 일부 지역의 결과를 전체 지역의 결과라고 설명하지 않는다.
6. 요청 의미에 필수인 정보가 없으면 질문할 정보를 반환한다. 사용자가 기본 화면을 요청했으면 등록 기본값을 사용할 수 있으며 실제 적용 조건을 설명한다. 지원하지 않는 값을 가까운 값으로 임의 변경하지 않는다.

## 도구와 완료 기준

- 시각화는 `validate_visualization`을 호출한다. 사용 방법은 `visualization-tool.md` 지침을 따른다. 등록된 Tableau 뷰를 표시하는 데 원자료 조회·가공은 필수가 아니다.
- 수치·원인·비교 해석이 함께 필요하면 별도의 조회·해석 근거를 확보한다. 설정 검사 통과는 수치 조회·실제 화면 표시·자료 존재 확인이 아니다.
- 게시되지 않은 지표·임의 계산 결과·새 차트 유형·색상·축·정렬을 요청하면 현재 뷰로 표현할 수 없는 항목을 설명한다. 비슷한 다른 지표의 뷰로 요청을 대체하지 않는다. HTML 생성 도구로 우회하지 않는다.
- 응답 작성은 유효한 도구 산출물을 선택하고 적용 조건·한계를 설명한다. `valid=true`이면 등록 설정 검사를 통과한 것이며, 사용자 브라우저에서 렌더링됐다고 단정하지 않는다.
- 기존 차트의 설명만 요청하면 재생성하지 않고 기존 산출물을 유지한다. 조건 변경이 있으면 전체 조건으로 다시 검증한다.

근거: 현재 업무 범위·기능 명세·State·작업 지침 및 2026-11-02 사용자의 Tableau Public 게시 뷰 활용·결정론적 검증 결정. 뷰의 지원 조건은 등록 시 실제 Embedding API로 확인하고, 요청 중에는 네트워크·브라우저를 실행하지 않는다.
