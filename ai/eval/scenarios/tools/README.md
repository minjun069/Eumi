# 도구 평가 시나리오

수정일: 2026-11-11.

[도구 평가 기준](../../docs/tools.md)에 따라 데이터 검색 및 조회·데이터 가공·시각화 검증의 입력 처리와 반환 결과를 검사한다. 이 문서는 도구별 사례 구성, 생성·실행 방법, 검증 결과를 다룬다. 노드·런타임 평가 시나리오는 별도로 작성한다.

현재 제공 사례는 합성자료와 고정한 등록 설정을 사용하는 단위 평가다. 실행기·채점 로직의 검증 범위는 [실행기의 평가 범위와 한계](../../docs/runner.md#평가-범위와-한계)를 따른다.

## 1. 사례 구성

| 도구 | 평가 ID | 실행 대상 | 사례 수 |
| --- | --- | --- | ---: |
| 데이터 검색 및 조회 | T01 | `query_data` | 100 |
| 데이터 가공 | T02 | `process_data` | 110 |
| 시각화 검증 | T03 | `validate_visualization` | 100 |

사례 1건은 실행 입력과 그에 대한 기대 결과의 한 쌍이다. 아래 28개 평가 항목을 각각 최소 10건인 10의 배수로 구성했다. 등록 뷰·연산·오류 종류를 유지하면서 조회 범위·자료원·반올림 자릿수·연산 순서·이벤트와 표시 조건을 바꾼다. 모든 입력 조합을 포함하는 것은 아니다. 전체 310건을 필수로 지정하고 같은 조건에서 각 3회 반복하며, 반복 횟수는 사례 수에 포함하지 않는다.

각 사례의 `assessment`에는 독립 기준·기대값·적용 검사·필수 여부를 기록한다. 적용 검사는 입력 처리 적합성(T-I.1), 처리 결과 정확성(T-O.1), 처리 상태 구분(T-O.2), 출처 정보 정확성(T-O.5)이다. 적용하지 않는 검사는 제외하거나 비적용 사유를 기록한다. 검사별 성공 기준은 [기능 평가](../../docs/tools.md#2-기능-평가)를 따른다.

### 1.1 데이터 검색 및 조회

조회 조건에 맞는 자료 반환, 잘못된 입력 거부, 권한·읽기 장애의 구분을 검사한다. 두 사례 파일은 모두 데이터 검색 및 조회 도구를 평가한다.

[기준 자료](query-data.json)는 지역·월·연령대별 36행, 페이지 검사 101행, 다른 자료원 검사 3행의 합성자료다. 기대 행·순서·건수를 미리 지정하고 별도 SQLite 조회로 정상 사례를 대조했다. 이 SQLite 대조는 기대값 검증용이며 평가 대상 도구의 DB 연결을 시험한 것은 아니다.

#### 조건·결과·입력 오류

[query.json](query.json)은 정상 34건과 거부 26건이다.

| 평가 항목 | 변형 조건 | 기대 결과 | 사례 수 |
| --- | --- | --- | ---: |
| 조회 조건 | 조건 생략, 같음·다름, 문자열 포함, 참·거짓, 결측, 수치 범위·월·연령 복합 조건 | 조건에 맞는 행 반환 | 10 |
| 정렬·반환 열 | 수치·논리값의 오름·내림·다중 정렬, 단일·역순 열 선택, 반환하지 않는 열로 정렬 | 동률·결측 처리와 행·열 순서 일치 | 10 |
| 조회 건수·페이지 | 일치 자료 없음, 최소·기본 한도, 처음·중간·끝·범위 밖 페이지, 필터·정렬 후 페이지 | 정상 0건 구분, 반환 건수·다음 페이지 일치, 기본 100행 제한 적용 | 10 |
| 시점·버전 검사 | 단독·동시 일치, 일반·페이지 조회의 불일치와 필수 버전 누락 | 일치 시 반환, 불일치·필수 버전 누락 시 거부 | 10 |
| 입력 오류 처리 | 미등록 자료, 없는·빈 열, 연산자·자료형·범위·중복 위반, 추가 SQL 항목 | 입력 보정 없이 해당 위반 사유 반환 | 20 |

| 자료원 간 격리 | 장애 자료원과 조회 자료원을 바꾸고 행·열·정렬·페이지 조건 지정 | 조회한 자료원의 정상 데이터 반환 | 10 |
| 사례 간 격리 | 장애 설정이 있는 사례 이후 같은 자료원의 전체·조건·페이지 조회 | 이전 장애 설정의 영향 없이 정상 데이터 반환 | 10 |

오류 결과와 함께 자료원 호출 이름·횟수·실행 추적을 대조한다. 미등록 자료 오류와 자료원 장애를 구분하며, 시간 초과 사례는 예외 변환만 검사한다. 장시간 호출의 강제 중단은 검사 범위에 포함하지 않는다.

### 1.2 데이터 가공

[process.json](process.json)은 계산·집계·결합 결과와 잘못된 연산의 거부를 검사하며, 정상 62건과 거부 48건으로 구성한다.

[기준 자료](process-data.json)는 연산·오류 조건별 합성자료 22개다. 계산식·결측·결합 규칙으로 기대값을 작성하고, 정상 사례는 별도 Decimal 계산과 SQLite 조회로 대조했다. 거부 사례는 지정한 오류 조건을 확인했다. 수치는 허용 오차 없이 정확히 비교한다.

| 집계 | 합계·평균·최솟값·최댓값·개수의 그룹별·전체 집계 | 값·행 수 일치 | 10 |

| 분모 0 처리 | 네 계산 방법, 분자·분모 동시 0, 0분모 행 제외 후 계산 | 차이와 0분모 제외 후 계산은 반환, 0으로 나누는 계산은 거부 | 10 |

### 1.3 시각화 검증

[visualization.json](visualization.json)은 T03의 [등록 설정 검사](../../docs/tools.md#13-시각화-설정-검사)와 프론트 전달용 산출물 반환을 평가하며, 적합 51건과 부적합 49건으로 구성한다.

[기준 자료](visualization-catalog.json)는 등록 설정 `tableau-public-20261110-v4`의 사본이다. 서비스의 등록 설정이 바뀌어도 평가 기준까지 자동으로 바뀌지 않도록 고정한다. 이 사본의 뷰별 입력 규칙과 이벤트별 허용 범위에서 기대 판정·사유·산출물을 작성했다. 부적합 사례는 정상 입력의 검사 조건을 하나씩 바꿔 구성한다.

| 평가 항목 | 변형 조건 | 기대 결과 | 사례 수 |
| --- | --- | --- | ---: |
| 등록 뷰별 산출물 | 사용자 요청의 등록 뷰 15개와 기간·지역·필터 조합 | 뷰·표시 조건에 맞는 산출물 반환 | 20 |
| 이벤트별 뷰 허용 | 분석 완료 이벤트의 허용·비허용 뷰, 같은 표시 조건의 사용자 요청·분석 완료 이벤트 비교 | 허용 뷰는 산출물 반환, 비허용 뷰는 부적합 판정 | 20 |
| 미등록 뷰 처리 | 두 이벤트에서 미등록 이름·번호, 대소문자 변경, 표시명·URL로 뷰 요청 | 미등록 뷰의 부적합 판정 | 10 |
| 필터 생략 | 뷰·도시·기간을 달리하고 필터 생략 또는 빈 객체 지정 | 전체 선택을 적용한 산출물 반환 | 10 |
| 필터 순서 | 뷰·도시·기간·지역 집합별 동일 필터 값의 순서 변경 | 비교 기준 사례와 동일 산출물 식별자 반환 | 10 |
| 입력 형식 검사 | 필수 항목·자료형·목록 구조 위반 | 입력 보정 없이 형식 위반 사유 반환 | 10 |
| 등록 조건 검사 | 등록 이름·허용값·기간·필터 조건 위반 | 해당 등록 조건의 위반 사유 반환 | 10 |
| 매개변수 누락 | 입력 프로필 2종의 개별 누락 6건·전체 생략 및 빈 객체 4건 | 기본값 보충 없이 `missing_parameter` 반환 | 10 |

입력 프로필은 뷰에 적용하는 매개변수 규칙의 묶음이며, 두 종류 모두 매개변수가 3개다. 모든 부적합 사례는 `valid=false`와 `artifact=null`을 반환해야 한다. 적합 산출물은 뷰·주소·시트·매개변수·필터·한계·출처·등록 설정 버전을 대조한다.

## 2. 생성·실행·채점

생성기는 스크립트에 미리 작성한 시험 입력·기대값과 고정 자료를 조합해 사례 JSON을 재생성한다. 같은 스크립트와 자료로 같은 데이터셋을 만들며, 도구 실행 결과에서 정답을 만들지 않는다. `arguments`와 필요한 `initial`은 도구에 전달할 입력이며, 평가 기준은 `assessment`에 분리한다. 상세 입력 구조와 저장 형식은 [단위 평가 실행기](../../docs/runner.md)를 따른다.

| 도구 | 사례 파일 | 생성기 |
| --- | --- | --- |
| 데이터 검색 및 조회 | [조건·결과·입력 오류](query.json) | [generate_query.py](generate_query.py) |
| 데이터 검색 및 조회 | [권한·읽기 장애 및 설정 격리](query-provider-failures.json) | [generate_query_provider_failures.py](generate_query_provider_failures.py) |
| 데이터 가공 | [process.json](process.json) | [generate_process.py](generate_process.py) |
| 시각화 검증 | [visualization.json](visualization.json) | [generate_visualization.py](generate_visualization.py) |

명령은 `ai/`에서 실행한다. 아래 예시의 파일명과 생성기를 평가 대상에 맞게 바꾼다. 데이터 검색 및 조회는 두 사례 파일을 모두 실행한다. 실제 도구에 준비한 자료를 제공하며 모델·운영 데이터베이스·외부 Tableau 호출은 없다.

```powershell
uv run python eval/scenarios/tools/generate_query.py --check
uv run python -m eval validate eval/scenarios/tools/query.json
uv run python -m eval run eval/scenarios/tools/query.json --repeat 3 --output eval/outputs/evaluations
uv run python -m eval score eval/outputs/evaluations/<묶음-ID>
```

생성기는 항목별 사례 수를 검사하고, `--check`는 저장 JSON과 재생성 결과의 일치를 검사한다. 생략하면 JSON을 재생성하며, 배포 설정을 변경해도 기준 사본·정답은 자동 갱신하지 않는다.

조회·가공의 입력 거부와 자료원 장애는 실행 상태가 `error`다. 시각화 부적합은 `returned` 상태로 `valid=false`와 `artifact=null`을 반환한다. 기능 통과 여부는 기대 사유·증거를 대조한 `score`의 판정으로 확인한다.

시각화의 [추가 검증](verify_visualization.py)은 저장된 반환 결과에서 산출물 ID가 비어 있지 않은지, 같은 조건의 반복 실행이나 필터 값의 순서만 바꾼 요청에서 ID가 같은지 확인한다. 개별 결과와 기대값을 대조하는 채점에 더해 여러 실행 사이의 일관성을 검사한다.

```powershell
uv run python eval/scenarios/tools/verify_visualization.py eval/outputs/evaluations/<묶음-ID>
```
