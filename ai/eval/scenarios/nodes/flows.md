# 시나리오별 노드 흐름

수정일: 2026-11-12.

[기본 데이터셋](README.md)의 21개 시나리오를 에이전트 진입부터 반환까지 정리했다. 아래 순서는 [시나리오 목록](scenarios.json)에 연결된 개별 파일의 `steps`와 대응하며, 모두 정상 완료로 반환한다. 이전 대화는 시작 State에 포함하며 이전 실행을 다시 수행하지 않는다.

해석·시각화 에이전트는 사용자 요청 처리 에이전트가 호출한다. 두 역할의 독립 사례 8개는 **상위의 목적 파악 → 판단 → 전문 역할 호출을 먼저 실제 실행**하고, 그 호출에서 만든 하위 State부터 평가한다. 표의 상위 준비 3개 노드는 `entry_transition.parent_steps`에, 하위 평가 노드는 `steps`에 보관한다. 준비 24회는 평가 노드 수에 합산하지 않는다. ‘이전 대화 없음’도 상위가 받은 대화의 조건이며 직접 사용자 진입을 뜻하지 않는다.

표의 **목적 파악**은 `interpret`, **판단**은 `decide`, **실행**은 `act`, **작성**은 `compose`다. 실행 뒤 괄호는 호출할 작업이다. **반환**은 종료 또는 상위로 복귀하는 표시이며 노드 수에 포함하지 않는다. 보고서의 작성·검토는 하나의 작성 노드 안에서 수행하며 별도 노드로 세지 않는다. 노드 역할은 [공통 실행 흐름](../../../docs/agent/workflow.md#2-에이전트-공통-실행-흐름)을 따른다.

## 1. 사용자 요청 처리

현재 요청과 앞 대화로 필요한 작업을 구분한다. 새 비교는 해석 역할에, 지도 생성은 시각화 역할에 위임한다. 기존 정의·한계의 표현만 수정하는 요청은 대화에 있는 내용으로 직접 답한다.

| 시나리오 ID | 시작 조건 | 전체 노드 흐름 | 노드 실행 수 |
| --- | --- | --- | ---: |
| `basic-request-none` | 이전 대화 없음 | **상위:** 목적 파악 → 판단 → 실행(해석 호출)<br>**하위 해석:** 목적 파악 → 판단 → 실행(12월 점수 조회) → 판단 → 실행(11월 점수 조회) → 판단 → 실행(두 결과 결합·점수 차이 계산) → 판단 → 작성 → 상위로 반환<br>**상위 재개:** 판단 → 작성 → 반환 | 14 |
| `basic-request-new_topic` | 이전 점수 설명을 마치고 도곡1동 12월 상세 지도 요청 | **상위:** 목적 파악 → 판단 → 실행(시각화 호출)<br>**하위 시각화:** 목적 파악 → 판단 → 실행(상세 지도 설정 검사) → 판단 → 작성 → 상위로 반환<br>**상위 재개:** 판단 → 작성 → 반환 | 10 |
| `basic-request-revision` | 이전 점수 정의·한계의 뜻을 유지하며 짧게 수정 | 목적 파악 → 판단 → 작성 → 반환 | 3 |
| `basic-request-clarification_complete` | AI가 물은 지역·월을 모두 답함 | **상위:** 목적 파악 → 판단 → 실행(해석 호출)<br>**하위 해석:** 목적 파악 → 판단 → 실행(12월 점수 조회) → 판단 → 실행(11월 점수 조회) → 판단 → 실행(두 결과 결합·점수 차이 계산) → 판단 → 작성 → 상위로 반환<br>**상위 재개:** 판단 → 작성 → 반환 | 14 |

비교 위임은 상위 5개와 하위 해석 9개를 합쳐 14회, 지도 위임은 상위 5개와 하위 시각화 5개를 합쳐 10회다. 하위 실행은 이 시나리오에 포함되며 별도 시나리오로 더 세지 않는다. 문장 수정에는 새 자료나 하위 작업이 필요하지 않으므로 실행 노드를 거치지 않는다.

## 2. 데이터 분석 결과 해석

상위가 실제 점수 조회·계산·해석이 필요하다고 판단하고 위임한 요청을 받는다. 두 달 비교에는 각각의 점수와 차이 계산이 필요하고, 현재 월 점수만 묻는 요청은 한 번의 조회로 충분하다. 수정 사례는 기존 정의·한계에 새 비교 근거를 추가하는 요청이다.

| 시나리오 ID | 상위가 받은 요청 | 상위 준비 | 하위 평가 흐름 | 평가 노드 실행 수 |
| --- | --- | --- | --- | ---: |
| `basic-interpretation-none` | 이전 대화 없이 도곡1동 두 달 점수 비교 | 목적 파악 → 판단 → 실행(해석 호출) | 목적 파악 → 판단 → 실행(12월 조회) → 판단 → 실행(11월 조회) → 판단 → 실행(결합·차이 계산) → 판단 → 작성 → 상위로 반환 | 9 |
| `basic-interpretation-new_topic` | 이전 주제를 마치고 도곡1동 12월 행동 이상 점수만 질문 | 목적 파악 → 판단 → 실행(해석 호출) | 목적 파악 → 판단 → 실행(12월 조회) → 판단 → 작성 → 상위로 반환 | 5 |
| `basic-interpretation-revision` | 이전 정의·한계를 유지하며 실제 두 달 비교 근거를 추가 | 목적 파악 → 판단 → 실행(해석 호출) | 목적 파악 → 판단 → 실행(12월 조회) → 판단 → 실행(11월 조회) → 판단 → 실행(결합·차이 계산) → 판단 → 작성 → 상위로 반환 | 9 |
| `basic-interpretation-clarification_complete` | AI가 물은 지역·월을 모두 답함 | 목적 파악 → 판단 → 실행(해석 호출) | 목적 파악 → 판단 → 실행(12월 조회) → 판단 → 실행(11월 조회) → 판단 → 실행(결합·차이 계산) → 판단 → 작성 → 상위로 반환 | 9 |

위 네 사례의 시작 State는 호출 인자의 목표와 상위의 조건·대화·이벤트·버전·누적 예산을 받는다. 새 최상위 요청에서 위 준비를 실행했으므로 해석 진입 시 이미 노드 3회·하위 호출 1회를 사용했다. 하위 내부 이력은 비우지만 예산은 초기화하지 않는다. 종료 후 반환값과 누적 사용량이 실제 상위 호출 기록에 보존된 상태까지 대조한다.

## 3. 데이터 시각화

요청의 목적·지역 범위·산출물 수에 맞게 등록 뷰와 표시 조건을 선택·검사한다. 정상 반환은 유효한 설정과 확인 범위를 제공한다는 뜻이며 실제 화면 표시 성공을 확인하는 흐름은 아니다.

| 시나리오 ID | 상위가 받은 요청 | 상위 준비 | 하위 평가 흐름 | 평가 노드 실행 수 |
| --- | --- | --- | --- | ---: |
| `basic-visualization-none` | 이전 대화 없이 도곡1동 상세 지도 요청 | 목적 파악 → 판단 → 실행(시각화 호출) | 목적 파악 → 판단 → 실행(상세 지도 설정 검사) → 판단 → 작성 → 상위로 반환 | 5 |
| `basic-visualization-new_topic` | 이전 동별 설명을 마치고 강남구 전체의 12월 배경 취약성 지도 요청 | 목적 파악 → 판단 → 실행(시각화 호출) | 목적 파악 → 판단 → 실행(도시 배경 취약성 지도 설정 검사) → 판단 → 작성 → 상위로 반환 | 5 |
| `basic-visualization-revision` | 같은 동의 지도 기간을 11월에서 12월로 변경 | 목적 파악 → 판단 → 실행(시각화 호출) | 목적 파악 → 판단 → 실행(상세 지도 설정 검사) → 판단 → 작성 → 상위로 반환 | 5 |
| `basic-visualization-clarification_complete` | 상세 지도와 기여도 차트 요청 후 AI가 물은 지역·월을 모두 답함 | 목적 파악 → 판단 → 실행(시각화 호출) | 목적 파악 → 판단 → 실행(상세 지도 설정 검사) → 판단 → 실행(행동 지표 기여도 차트 설정 검사) → 판단 → 작성 → 상위로 반환 | 7 |

시각화 진입 State도 상위의 실제 호출에서 만들며 노드 3회·하위 호출 1회의 누적 사용량을 이어받는다. 도시 지도는 특정 동에 한정하지 않고, 기간 변경 요청은 같은 동을 유지한다. 두 산출물 요청은 지도만 준비한 시점에는 작업을 계속하고 기여도 차트까지 준비한 뒤 작성한다. 검사된 산출물은 하위 반환과 상위 호출 기록에서 동일하게 보존한다.

## 4. 보고서 시각화 선정

사용자 대화 없이 2025년 12월 보고서 요청으로 시작한다. 입력은 기간과 서로 다른 상세 뷰 3개를 요구한다. 점수 추세 조회 후 관측된 변화와 함께 설명할 지표 기여도를 확인하고, 세 번째 공간 관측을 위해 현재 월 격자 자료를 조회한다. 확인한 근거로 뷰 3개와 설명 범위를 선정·검토해 반환한다.

| 시나리오 ID | 대상 동 | 노드 흐름 | 노드 실행 수 |
| --- | --- | --- | ---: |
| `basic-report_selection-1168065500` | 도곡1동 | 판단 → 실행(월별 점수 조회) → 판단 → 실행(기여도 조회) → 판단 → 실행(격자 조회) → 판단 → 작성(선정·검토) → 반환 | 8 |
| `basic-report_selection-1168063000` | 대치4동 | 판단 → 실행(월별 점수 조회) → 판단 → 실행(기여도 조회) → 판단 → 실행(격자 조회) → 판단 → 작성(선정·검토) → 반환 | 8 |
| `basic-report_selection-5111062000` | 효자1동 | 판단 → 실행(월별 점수 조회) → 판단 → 실행(기여도 조회) → 판단 → 실행(격자 조회) → 판단 → 작성(선정·검토) → 반환 | 8 |

월별 점수는 7~12월 범위로 조회하며 실제 반환된 자료는 8~12월이다. 기여도는 설명에 사용하는 전월·현재 월인 11·12월, 격자는 현재 월만 조회한다. 세 동은 동일한 자료 종류가 제공되어 경로 길이는 같지만, 조회 후 판단과 선정 이유에는 각 동의 변화 방향·지표·격자 값을 사용한다. 상세 제약은 [자료 제약](README.md#4-실제-근거와-자료-제약)을 따른다.

## 6. 보고서 퀵 인사이트

같은 동의 설명 시나리오가 반환한 승인 설명 3개와 근거를 시작 State로 받는다. 승인 범위 안에서 중복 없는 네 문장을 작성·검토해 반환한다.

| 시나리오 ID | 대상 동 | 노드 흐름 | 노드 실행 수 |
| --- | --- | --- | ---: |
| `basic-report_insight-1168065500` | 도곡1동 | 판단 → 작성(인사이트 작성·검토) → 반환 | 2 |
| `basic-report_insight-1168063000` | 대치4동 | 판단 → 작성(인사이트 작성·검토) → 반환 | 2 |
| `basic-report_insight-5111062000` | 효자1동 | 판단 → 작성(인사이트 작성·검토) → 반환 | 2 |

보고서의 선정 → 설명 → 인사이트는 같은 동의 승인 결과·이력·누적 사용량을 이어받는 별도 시나리오다. 현재 묶음의 평가 노드 실행은 사용자 요청 계열 95회와 보고서 36회를 합쳐 131회다. 전문 역할 8개의 상위 준비 24회는 별도 집계한다. 각 평가 단계의 독립 입력·기대 결과·사례 ID는 시나리오 목록에서 연결한 개별 파일의 `steps`에서 확인한다.
