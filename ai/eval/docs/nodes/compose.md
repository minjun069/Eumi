# 응답 작성

상태: 검토용 명세. 수정일: 2026-11-13.

[노드 평가 개요·지표·합격 판정](README.md) · [공통 평가 기준](common.md)

## 평가 범위

응답 작성 노드(N04)가 주어진 자료로 작성한 응답·산출물, 공개할 결과의 선택과 보고서 검토 판정을 평가한다.

같은 검사를 에이전트 종류별로 적용하며, 해당 산출물에 정해진 기준만 사용한다.
[산출물별 기준](#산출물별-기준)은 다음 검사에 연결한다.

| 평가 내용 | 담당 검사 |
| --- | --- |
| 필수 내용 충족 | N04-O.1, 해당 공통 검사 |
| 내용 정확성 | N04-O.2, N04-O.4, N04-B.1, 해당 공통 검사 |
| 승인된 설명을 요약한 인사이트의 충실성 | N04-B.1의 퀵 인사이트 행 |
| 보고서 검토자가 반환한 판단 | N04-O.3 |

## 출력 형식

출력 형식은 [정형 평가 정의](compose.json)의 `output-format`과 호출 목적별 원칙을 따른다.

### 일반 응답

일반 응답은 [정형 평가 정의](compose.json)의 `output-general` 원칙을 따른다.

### 보고서 시각화 선정

보고서 시각화 선정은 [정형 평가 정의](compose.json)의 `output-selection`, `selection-boundaries` 원칙을 따른다.

### 보고서 설명·퀵 인사이트

보고서 설명은 [정형 평가 정의](compose.json)의 `output-description`, 퀵 인사이트는 `output-insight` 원칙을 따른다. 공통 작성 형식은 `output-report-writing`에서 관리한다.

| 찾아볼 내용 | 원칙 |
| --- | --- |
| 미완성 안내와 부분 작성의 분량 | `report-partial-format` |
| 부분 작성 내용의 대상·근거 | `report-partial-accuracy` |
| 설명·인사이트·보고서 전체의 완성 구분 | `report-completion-scope` |

### 보고서 검토

보고서 검토는 [정형 평가 정의](compose.json)의 `output-review` 원칙을 따른다.

## 산출물별 기준

에이전트·산출물별 필수 내용과 정확성 기준은 [정형 평가 정의](compose.json)의 관련 원칙을 따른다.
검사 행에는 대조 절차와 근거 유효성을, 역할별 원칙에는 해당 산출물의 내용 정확성 조건과 허용 예외를 둔다. 작성 책임과 검사 경계는 `requirements-common`에서 확인한다.

형식·분량 요구의 근거는 [기능 명세](../../../docs/agent/components.md#3-에이전트-명세)와 [보고서 산출물](../../../docs/agent/report.md#4-산출물과-실패-처리)이다.
역할별 내용 기준은 [분석 해석 지침](../../../src/instructions/analysis-interpretation.md), [시각화 결과 사용 지침](../../../src/instructions/visualization-tool.md), [보고서 지침](../../../src/instructions/analysis-report.md)을 따른다.

## 전용 검사

검사 정의의 단일 원본은 [정형 평가 정의](compose.json)다. 이관 내용은 [원본 Markdown 보관본](originals/compose.md)과 대조한다.

작성 결과와 검토 판단은 서로의 통과를 대신하지 않는다.
수정본은 [수정본의 판정 원칙](../methods.md#검사-범위와-판정-연결)에 따라 원래 결함을 담당한 검사와 나머지 적용 검사로 평가한다.
보고서의 별도 검토 호출·순서·모델·수정 횟수는 응답 작성 노드의 내부 처리 책임이며 일반 해석·응답에 같은 절차를 요구하지 않는다. 현재 모델 출력 검사와 내부 실행 검사의 정비 범위는 [노드 평가 대상](README.md#대상)을 따른다.

## 평가 준비

검사별 적용 조건·측정 방법·성공 기준은 실행 전에 정한다. LLM 기반 검사는 다음 내용을 저장된 실행 당시 입력에서 확인한다.

| 대상 | 확인할 실행 당시 입력 |
| --- | --- |
| 공통 | 제공된 자료·지표 정의·관측 범위·확인 상태·한계 |
| 보고서 선정 | 제공된 뷰 목록·자료와 역할별 선정 조건 |
| 보고서 설명 | 배정 뷰·확정 범위 |
| 퀵 인사이트 | 승인된 설명과 그 설명이 제공하는 근거·한계 |

같은 목적과 역할별 조건을 충족하는 선택을 인정하며 모든 후보를 출력하도록 요구하지 않는다. 수치 값을 직접 비교하는 규칙 기반 검사의 독립 계산값·허용 오차는 해당 규칙에 따라 준비한다.

V06 기여도·V01 도시 중앙 50% 범위는 [실제 자료 공급 상태](../../../docs/agent/report.md#6-구현-범위와-남은-연결)에 따라 공급된 근거만 평가한다. 미공급 값을 정상 사례의 필수 결과로 배정하지 않으며, 합성 근거를 제공한 시험은 실제 자료원 연결 검증과 구분한다.

사용자 요청의 단계 안내·최종 결과 전달과 보고서 내부의 후속 실행은 [실행 흐름](../../../docs/agent/workflow.md#21-사용자-요청의-진행-안내와-결과-전달)에 따른다. 응답 작성 노드의 상태 갱신은 노드 책임이며, 노드 간 결과 전달·다음 단계 실행과 전체 반환·종료는 [에이전트 실행 평가](../execution/README.md)에서 확인한다.
