# 응답 작성

상태: 검토용 명세. 수정일: 2026-11-11.

[노드 평가 개요·지표·합격 판정](README.md) · [공통 평가 기준](common.md)

## 평가 범위

응답 작성 노드(N04)가 주어진 자료로 작성한 응답·산출물, 공개할 결과의 선택과 보고서 검토 판정을 평가한다.

같은 검사를 에이전트 종류별로 적용하며, 해당 산출물에 정해진 기준만 사용한다.
[산출물별 기준](#산출물별-기준)은 다음 검사에 연결한다.

| 평가 내용           | 담당 검사                               |
| --------------- | ----------------------------------- |
| 필수 내용 충족        | N04-O.1, 해당 공통 검사                   |
| 내용 정확성          | N04-O.2, N04-O.4, N04-B.1, 해당 공통 검사 |
| 보고서 검토자가 반환한 판단 | N04-O.3                             |

## 출력 형식

N-F.1은 호출 목적에 맞는 아래 형식과 [공통 형식 기준](common.md#출력-형식의-공통-기준)을 적용한다.
표의 필드는 모두 필수다. 최초 작성본과 수정본에 같은 형식을 적용한다.

### 일반 응답

데이터 분석 결과 해석·데이터 시각화·사용자 요청 처리에 적용한다.

이 응답은 해당 역할의 실행을 마치는 최종 응답이다. 사용자 요청의 단계 시작 안내는 런타임이 작성하며, 보고서 작성·검토의 후속 판단용 응답과 구분한다.

| 필드 | 자료형 | 형식 기준 |
| --- | --- | --- |
| `content` | 문자열 | 사용자에게 제공할 본문이다.<br>별도 문장·단락 수를 요구하지 않는다. |
| `artifact_ids` | 문자열 배열 | 공개할 결과의 작업 ID 목록이다.<br>기존 공개 산출물은 `previous`로 지정한다.<br>선택할 산출물이 없으면 빈 배열이다. |
| `status` | 문자열 | 완료 `completed`, 부분 완료 `partial`, 제공 불가 `failed` 중 하나다. |
| `reason` | 문자열 | 제공 범위와 완료 상태의 이유를 담는다. |

### 보고서 시각화 선정

| 필드 | 자료형 | 형식 기준 |
| --- | --- | --- |
| `views` | 객체 배열 | 선정 뷰를 0~3개 담는다.<br>각 항목은 아래 세 필드로 구성한다. |
| `views[].view_key` | 문자열 | `EmbedDetailV01`~`EmbedDetailV08` 중 하나다. |
| `views[].reason` | 문자열 | 선정 이유와 설명 범위·제외한 비교를 담는다.<br>공백 외 문자가 있어야 한다. |
| `views[].evidence_ids` | 문자열 배열 | 근거로 선택한 작업 결과 ID를 1개 이상 담는다.<br>각 문자열에는 공백 외 문자가 있어야 한다. |

뷰 중복, 근거의 유효성, 자료 부족에 따른 3개 미만 선정의 적절성은 내용 검사에서 판정한다.
빈 선정은 입력 근거와 빈 목록을 대조하며, 이 형식에 없는 별도 사유 필드를 요구하지 않는다.

### 보고서 설명·퀵 인사이트

| 호출 | 필드 | 자료형 | 형식 기준 |
| --- | --- | --- | --- |
| 뷰별 설명 작성 | `content` | 문자열 | 한 뷰의 설명을 한 단락·최대 3문장으로 작성한다.<br>공백 외 문자가 있어야 한다. |
| 퀵 인사이트 작성 | `content` | 문자열 | 완성본은 줄바꿈으로 구분한 3~4개 항목이며 항목당 한 문장이다.<br>공백 외 문자가 있어야 한다. |

작성 본문만 반환한다. 대상 뷰·입력 근거 참조를 이력에 붙이는 처리는 런타임이 맡는다.
미완성 항목의 안내에 적용할 분량은 [산출물별 기준](#산출물별-기준)을 따른다.

### 보고서 검토

선정·뷰별 설명·퀵 인사이트의 검토 호출에 적용한다.

| 필드 | 자료형 | 형식 기준 |
| --- | --- | --- |
| `accepted` | 불리언 | 적합하면 `true`, 부적합하면 `false`다. |
| `reason` | 문자열 | 적합·부적합 판단 이유를 담는다. |

| 에이전트         | 산출물    | 형식 준수                   | 필수 내용 충족                                                                                                                | 내용 정확성                                                                                                                                                          |
| ------------ | ------ | ----------------------- | ----------------------------------------------------------------------------------------------------------------------- | --------------------------------------------------------------------------------------------------------------------------------------------------------------- |
| 데이터 분석 결과 해석 | 해석문    | [일반 응답](#일반-응답)         | 주요 신호·비교 설명·근거 지표·한계와 확인 사항을 담는다.<br>자료가 지지하는 작은 변화·유지·안정도 설명하며, 현장 맥락이 없으면 확인할 수 없는 부분만 한정한다.<br>해석할 수 없는 부분은 사유를 밝힌다. | 실제 근거의 수치·지표 의미와 일치하고 관측한 지역·집단·기간 안에서 해석한다.<br>점수와 실제 활동·관계 상태를 구분하고 서로 다른 집계를 같은 사람의 변화로 합치지 않는다.                                                             |

| 사용자 요청 처리    | 최종 응답  | [일반 응답](#일반-응답)         | 요청한 답변 항목·근거·미해결 사항을 담는다.<br>산출물을 수정·제외하면 변경 이유를 밝힌다.                                                                   | 하위 결과의 의미와 제공 범위를 보존하고 직접 추가한 설명은 근거와 일치한다.<br>완료 여부·미해결 사항·변경 이유가 실제 확보 결과에 맞는다.<br>새로 제공할 결과를 빠뜨린 채 이전 답변만 반복하지 않으며, 유효한 기존 산출물의 유지는 반복 오류로 보지 않는다.           |
| 보고서 시각화 선정   | 선정 목록  | [선정 목록](#보고서-시각화-선정)    | 선정 뷰·선정 이유·근거 참조·설명 가능한 범위·제외한 비교를 담는다.<br>1~2개만 선정할 때는 선정 이유에 자료 부족 사유와 제한한 설명 범위를 포함한다.                               | 충분한 근거가 있으면 서로 다른 허용 상세 뷰 3개를 선정한다.<br>자료가 부족하면 근거 있는 1~2개를 허용하며, 설명 가능한 자료가 없을 때 빈 목록을 허용한다.<br>설명에 기여하는 작은 변화·유지의 뷰와 적합한 대안 조합을 인정하고, 부족한 비교를 가능하다고 설명하지 않는다. |
| 보고서 시각화 설명   | 뷰별 설명문 | [설명문](#보고서-설명퀵-인사이트)    | 배정된 각 뷰의 설명·근거 참조를 담는다.<br>완성하지 못한 항목은 사유를 밝힌다.                                                                         | 확정된 뷰와 설명 범위를 지키며 해당 근거에 맞게 설명한다.<br>1~2개만 배정돼도 근거가 충분하면 그 설명을 모두 작성하며, 수를 채우려고 뷰를 추가하거나 추가 자료를 이유로 앞 단계의 선정을 바꾸지 않는다.                                          |
| 보고서 퀵 인사이트   | 핵심 요약  | [퀵 인사이트](#보고서-설명퀵-인사이트) | 검토를 통과한 설명의 핵심 내용과 근거 참조를 담는다.<br>일부 설명만으로도 완성 조건을 충족하면 그 범위에서 요약하고, 부족하면 미완성 사유를 밝힌다.                                  | 검토를 통과한 설명의 변화·유지 의미를 충실하게 요약하고 같은 내용을 중복하지 않는다.<br>추가 확인 자료에 있더라도 승인된 설명에 없는 계산·지역 맥락·해석을 새 주장으로 넣지 않는다.                                                       |

완성하지 못한 항목의 안내에는 완성본 분량을 요구하지 않는다. 일부만 작성한 경우에도 실제 작성한 설명의 문장 수·대상·근거 기준은 적용한다.
배정된 1~2개 뷰의 설명 완성, 일부 설명으로 작성한 인사이트 완성, 보고서 전체 완성은 구분한다.

근거 참조는 해당 호출에서 모델이 직접 작성·선택하는 부분을 검사한다. 입력 참조를 이력에 붙이거나 산출물을 조립하는 런타임 처리는 모델의 필수 출력으로 요구하지 않는다.
출처의 누락·오류는 N-O.8, 필수 한계는 N-O.5, 하위 결과의 누락·왜곡은 N-O.9가 담당한다.

형식·분량 요구의 근거는 [기능 명세](../../agent/components.md#3-에이전트-명세)와 [보고서 산출물](../../agent/report.md#4-산출물과-실패-처리)이다.
역할별 내용 기준은 [분석 해석 지침](../../../src/instructions/analysis-interpretation.md), [시각화 결과 사용 지침](../../../src/instructions/visualization-tool.md), [보고서 지침](../../../src/instructions/analysis-report.md)을 따른다.

보고서 V01·V07은 요청 월을 포함한 최근 6개월, 다른 뷰는 요청 월과 필요한 비교 자료의 기간을 적용한다. 단위·분모·기간이 다른 자료는 사례에 정한 허용 변환과 비교 가능 범위 안에서 설명한다.
