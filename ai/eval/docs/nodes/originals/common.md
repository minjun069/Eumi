# 공통 평가 기준

상태: 검토용 명세. 수정일: 2026-11-11.

[노드 평가 개요·지표·합격 판정](README.md)

여러 노드에 적용하는 출력 형식·내용 검사와 판정 기준을 정의한다.
각 노드의 전용 검사와 함께 적용한다.

## 노드 검사의 세 축

| 평가 축 | 검사 내용 | 기준 구분 |
| --- | --- | --- |
| 형식 준수 | 요구된 출력 구조·자료형·분량을 지켰는지 확인한다. | 필수 필드의 존재, 해석 가능한 인자 구조, 문장·항목 수 등 명시된 형식 |
| 필수 내용 충족 | 해당 입력 상황과 역할에서 요구되는 내용을 빠뜨리지 않았는지 확인한다. | 목표·조건, 판단 이유, 답변 항목, 질문 대상 등 의미상 필요한 내용 |
| 내용 정확성 | 출력된 내용·선택·판정이 요청·근거·허용 범위에 맞는지 확인한다. | 의미 왜곡, 잘못된 대상·값·진행 방향, 근거 없는 추가와 제한 위반 |

노드 검사는 **형식 준수 → 필수 내용 충족 → 내용 정확성** 순서로 수행한다.

| 단계의 검사 결과 | 후속 처리 |
| --- | --- |
| 적용 검사 모두 통과 | 다음 단계로 진행한다. |
| 실패 확인 | 사례를 실패로 판정 완료하고, 후속 검사는 `선행 단계 실패로 미실행`으로 기록한다. |
| 실패 없이 미판정이 남음 | 다음 단계로 진행하지 않고, 사례도 판정 미완료로 남긴다. |

필드가 있어도 필요한 내용을 담지 않으면 필수 내용 충족을 통과하지 못한다.

공통 검사에 노드별 기준을 적용하고, 산출물이 다르면 에이전트·산출물별 기준을 함께 적용한다.
특별한 형식 요구가 없는 산출물에는 임의의 분량·문체 기준을 만들지 않는다.
모델 연동 라이브러리가 형식을 강제하거나 검사하는 경우에도 검사할 원본과 판정을 확보한다.
원본을 확보하지 못한 부분은 미판정으로 남긴다.

검사 항목은 축의 수에 맞추지 않고, [평가 문서 작성 지침](../writing-guide.md#1-작성-원칙)의 판정 기준·증거·수정할 동작에 따라 구분한다.
출처 대조·하위 결과 전달처럼 같은 대상의 누락과 오류를 함께 확인하는 검사는 주된 검사 목적의 축에 두고, 세부 조건별 결과를 구분한다.
같은 조건을 다른 축에서 다시 채점하지 않으며, 축별 지표를 자동으로 추가하지 않는다.

## 출력 형식의 공통 기준

형식 검사 N-F.1의 기준은 다음 표에 연결한 출력 형식이다.
평가 전에 적용할 문서 버전과 역할을 정하며, 코드가 수용했다는 사실만으로 형식 통과를 판정하지 않는다.

| 평가 대상 | 출력 형식 정의 |
| --- | --- |
| 작업 목적 파악 | [목표·조건·정보 필요 여부](interpret.md#출력-형식) |
| 작업 선택 및 실행 | [선택 결과·호출 인자](act.md#출력-형식) |
| 작업 진행 판단 | [진행 방향·이유](decide.md#출력-형식) |
| 응답 작성 | [일반 응답·보고서 선정·설명·인사이트·검토](compose.md#출력-형식) |
| 사용자 정보 요청 | [질문·이유](ask.md#출력-형식) |

| 구분 | 형식 기준 |
| --- | --- |
| 반환 구조 | 모델 호출별 결과는 JSON 객체 하나다.<br>선택 필드로 명시한 경우를 제외하면 정의된 필드를 모두 포함한다.<br>이름 → 값의 매핑으로 정의한 객체를 제외하고, 정의하지 않은 필드를 추가하지 않는다. |
| 자료형 | 문자열·불리언·정수·수·객체·배열을 구분한다.<br>불리언은 `true` 또는 `false`이며 문자열이나 숫자로 대신하지 않는다.<br>배열은 모든 원소가 지정된 자료형이어야 한다. |
| 빈 값·생략 | `null`을 허용한다고 명시한 값만 `null`을 사용할 수 있다.<br>'공백 외 문자가 있는 문자열'은 빈 문자열·공백만 있는 문자열을 허용하지 않는다.<br>일반 문자열·배열에는 따로 명시한 경우에만 최소 길이·개수를 적용한다. |
| 고정값·분량 | 명시된 선택값과 최소·최대 개수, 문장·단락·항목 수를 지킨다.<br>허용한 값 중 무엇을 선택해야 하는지와 문장이 필요한 내용을 담았는지는 뒤의 내용 검사에서 판정한다. |

필수 필드의 존재와 자료형은 형식 기준이며, 필드에 담아야 할 설명·조건의 누락은 필수 내용 기준이다.
평가 문서와 실행 시 제공한 응답 명세가 다르면 그 차이를 기록하고 입력 구성 문제와 모델 출력 오류를 구분한다.

같은 문장이 선택 이유와 공개 설명에 반복되면 담당 판정과 증거를 연결한다.
자료·이력의 실제 전달 누락과 공개 상태에 다른 내용이 섞인 문제는 [에이전트 실행 평가](../execution/common.md#공통-실행-검사)에서 확인한다.

## 준비 자료

검사별 입력을 [검사 입력 구분과 목록](../methods.md#검사-입력)에 따라 준비한다.
[입력 선정 원칙](../methods.md#입력-선정-원칙)에 따라 필요한 원문·필드만 추출하고 원본 위치·범위·조건부 제공 여부를 기록한다.
출력 형식은 위 [공통 기준과 노드별 정의](#출력-형식의-공통-기준)를 사용한다.
작업 선택의 시각화 입력 프로필은 실행 전에 해당 뷰의 필수 이름·자료형을 고정한다.
의미상 기대 결과는 사전에 검토한 요구·자료·역할별 기준을 사용한다.
LLM 기반 검사의 기준 사례와 사람 검토는 [LLM 판정 절차](../methods.md#llm-판정-절차)를 따른다.

## 노드 검사 판정

노드 실행마다 검사 ID별 전체 판정과 세부 항목별 판정을 연결해 기록한다. 같은 노드를 반복 실행하면 각 실행에 별도 기록을 남긴다.

| 기록 수준 | 판정 단위 | 기록할 내용 |
| --- | --- | --- |
| 검사 전체 | 노드 실행 1회·검사 ID | 적용되는 세부 항목의 결과를 종합한 판정 1건 |
| 세부 항목 | 해당 검사에서 정한 대상·조건 1개 | 항목별 통과·실패·미판정·비적용과 판정 근거·증거 위치 |

세부 항목은 목표·조건·주장·수치 등 해당 검사에서 따로 확인할 대상이다. 판정 단위·분리 규칙·필수 항목은 사례 실행 전에 정하고, 같은 검사에는 같은 규칙을 적용한다. 필수 항목의 누락도 판정 대상에 포함하며, 항목별 판정은 [공통 판정 원칙](../methods.md#4-판정-원칙)을 따른다.

| 검사 전체 판정 | 판정 조건 |
| --- | --- |
| 통과 | 적용되는 세부 항목이 모두 통과함 |
| 실패 | 세부 항목 중 하나라도 실패함 |
| 미판정 | 확인된 실패 없이 미판정 항목이 남음 |
| 비적용 | 검사 자체가 적용 조건에 해당하지 않음 |

검사 전체 판정과 세부 항목 판정은 각각 집계하며 건수를 서로 합치지 않는다. 세부 항목의 실패·미판정 위치는 검사 전체 판정에 연결해 확인할 수 있게 한다.
