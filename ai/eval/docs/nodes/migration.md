# 노드 평가 정의 이관 방식

수정일: 2026-11-13.

평가 프롬프트와 판정 로직은 [노드별 평가 정의](README.md#1-노드별-평가)에 연결한 JSON을 함께 사용한다. 이 문서는 초기 이관의 원문 보존, 이후 현행 기준의 의미를 보존하는 조항 분리, 상황별 행·조항·입력 선택을 설명한다.

## 1. 파일별 역할

| 파일 | 보관·관리할 내용 | 사용 목적 |
| --- | --- | --- |
| 각 `originals/`의 기존 Markdown | 기준 자료에 고정한 보관본 전체 바이트 | 원문 표현과 누락 여부 대조 |
| 현재 Markdown | 평가 범위·지표·논리 설명과 JSON 경로 | 평가 문서의 읽기 안내 |
| 같은 이름의 JSON | 검사 정의와 판정에 사용하는 출력 형식·산출물별 기준·진행 판단 조건·공통 원칙 | 평가 프롬프트와 판정 로직이 읽는 단일 원본 |

[원본 보관본](originals/README.md)의 상대 링크는 보관 전 위치를 기준으로 유지한다. 현재 Markdown에서 옮긴 표·본문 자리는 JSON 링크로 교체하고, 기존 참조가 사용하는 제목과 앵커를 유지한다. 프롬프트 조립이나 판정에 값이 필요한 내용은 JSON에 두며, 논리 설명을 위한 표는 Markdown에 남긴다.

평가 폴더 이동 후에도 보관 원문과 JSON의 판정 본문·해시·조항 위치는 유지한다. JSON의 원칙 참조 경로는 `eval/docs/nodes/`를 사용한다. 본문에 보존한 상대 링크는 문서 검사기가 이전 `docs/eval/` 위치에서 해석한 뒤 현재 파일로 연결해 확인한다.

공통 원칙을 가져온 평가 방법의 본문은 [공통 방법 보관본](../originals/methods.md)에 보관한다. 현재 [평가 방법](../methods.md)은 공통 JSON의 주제별 원칙을 안내하며 같은 판정·운영 규칙의 본문을 다시 관리하지 않는다.

보관 바이트는 [보존 검사의 기준 자료](../../tests/fixtures/node_criteria_origins.json)로 확인한다. 기존 노드 보관본의 `archives_sha256`은 본문과 현행 명세를 대조해 고정한 복구 기준이며, 초기 이관 이후 계속 불변이었다는 증거로 사용하지 않는다. 일치하지 않았던 이전 해시는 `archive_baseline.historical_sha256`에 별도 보존한다. 새로 보관한 평가 방법의 바이트는 `supporting_sources_sha256`에 별도로 고정한다.

## 2. 원문을 옮기는 절차

초기 이관에서는 다음 절차로 원문 표현을 보존한다. 이후 현행 기준을 정비할 때는 아래의 [판정 조항 선택](#판정-조항-선택)을 따른다. `originals/`의 보관본은 어느 단계에서도 수정하지 않는다.

1. 보관 원문의 검사 표에서 열 이름과 순서를 그대로 가져와 `checks`의 평탄한 행으로 만든다. 공통 검사에만 있는 `적용 노드`도 원문 구성을 따른다.
2. 검사 ID·평가 축·검사 항목·검사 내용·평가 방식은 원문 셀을 그대로 옮긴다. 같은 검사를 상황별로 나눠도 검사 ID를 유지한다.
3. 상황에 따라 필요한 입력·대조 대상·성공 기준이 달라지는 부분을 별도 행으로 나눈다. 적용 여부만 다르고 평가 방법과 기준이 같으면 한 행의 적용 조건으로 표현한다.
4. 나눈 행에는 해당 상황의 적용 노드·검사 대상 결과·판정 기준을 배치한다. LLM 행은 실행 당시 입력을 `모델 호출 입력` 전체로 지정한다. 각 행을 읽으면 무엇을 대조하고 어떻게 판정하는지 알 수 있어야 한다.
5. 측정 방법과 성공 기준은 원문에서 `<br>`로 구분한 문장 전체를 배치한다. 여러 상황을 함께 설명하는 문장은 그대로 유지하며, 필요한 행에 반복해서 둘 수 있다. 분리된 행 전체에서 원문의 문장·예외·근거가 빠지지 않았는지 확인한다.
6. 원문의 적용 조건이 실제 호출과 논리적으로 맞지 않으면 실제 업무 구현을 기준으로 적용 범위를 조정한다. 현재 JSON은 `상황: 원문 적용 조건`으로 기록하여 추가한 상황과 원문 표현을 구분한다. 평가 방법과 성공 기준을 새로 쓰는 근거로 사용하지 않는다.

예를 들어 보고서 작성 호출과 검토 호출은 실제로 반환하는 결과가 다르므로, 작성 결과를 확인하는 검사와 검토 판정을 확인하는 검사의 적용 범위를 구분한다. 구체적인 행과 기준은 [응답 작성 정의](compose.json)에 둔다.

## 3. JSON 구성과 입력 선택

원문 평가 내용과 평가기가 행을 선택하는 데 필요한 연결 정보를 분리한다.

| 구성 | 내용 |
| --- | --- |
| `checks` | 원본 표의 한글 열 이름을 유지한 현행 검사 행 배열 |
| `bindings` | 각 행의 식별자·적용 상황·관련 원칙과 판정 조항 |
| `principles` | 현행 원칙·기준의 전체 본문, 용도 분류와 판정 조항의 본문 위치 |

`bindings`는 다음 정보로 원문 행을 연결한다.

| 필드 | 연결 방식 |
| --- | --- |
| `row` | 같은 파일의 `checks`에서 0부터 시작하는 행 위치 |
| `row_id` | 같은 검사 ID에서 나뉜 상황별 행을 구별하는 식별자 |
| `when` | 노드·역할·호출 종류·도구 등 현재 상황과 대조할 선택 조건 |
| `principles` | 관련 원칙이 있는 JSON의 경로와 원칙의 `key`. LLM 행은 `clause_ids`로 사용할 판정 조항을 지정 |
| `judge_fields` | LLM 행의 적용 조건·측정 방법·성공 기준에서 전송할 원문 구간과 각 필드 전체 원문의 해시 |

모든 노드 LLM 행의 실행 당시 입력은 `모델 호출 입력`이다. 보고서의 승인된 설명처럼 근거로 사용할 수 있는 자료의 조건은 측정 방법·성공 기준에서 판단하며, 실행 입력을 그 자료로 제한하는 `input_scopes`는 사용하지 않는다.

평가기는 현재 상황에 맞는 행을 먼저 선택하고, 선택한 행의 평가 입력과 관련 원칙을 가져와야 한다. 같은 검사에 속한다는 이유로 모든 상황의 입력을 합쳐 요구하지 않는다. `checks`의 적용 조건과 `bindings`의 선택 조건은 같은 상황을 가리켜야 한다. 역할·호출 종류로 행을 선택해도 내용의 적용 조건을 충족했는지 판단한 것은 아니므로, 선택한 적용 조건은 평가 모델에 제공한다.

초기 이관에서는 `principles`의 본문에 원문의 문장·목록·표를 그대로 옮긴다. 상대 링크는 원래 가리키던 문서와 절이 유지되도록 새 파일 위치에 맞춰 조정한다.

### 판정 조항 선택

LLM 평가 모델에는 선택한 검사 행의 판정 내용과 그 판정에 필요한 현행 본문 조항을 제공한다. 현행 본문을 분리·정리하는 작업과, 확정된 본문에서 모델에 제공할 조항을 선택하는 작업을 구분한다.

- 사용자가 원문 분리·중복 통합을 요청하면 `checks`와 `principles.text`의 현행 기준을 정비할 수 있다. 검사 ID·담당 책임·적용 범위·필수 조건·예외·근거는 유지하며, 기준의 의미가 달라지거나 해석이 불확실하면 먼저 사용자에게 확인한다.
- 서로 다른 책임의 본문은 독립 원칙으로 나누고, 같은 책임 안의 조건은 선택 가능한 조항으로 나눈다. 각 원칙과 조항은 단독으로 읽어도 적용 조건·예외·우선순위가 완결되어야 한다.
- 같은 규칙은 한 곳에서 관리하고 각 검사 행에서 참조한다. 여러 역할에 걸친 검사 문장은 해당 역할의 행에 필요한 부분을 배치하며, 분리한 행 전체에서 원래 조건이 빠지지 않아야 한다.
- 변경한 셀·본문은 보관 원문과 현행 위치의 명시적 대응표로 대조한다. 변경 대상 밖의 내용은 기존 원문 일치 검사를 유지하며, 표현을 바꿨다는 이유로 보존 검사를 생략하지 않는다.
- `bindings[].principles[].clause_ids`에는 해당 행의 담당 조건을 판정하는 데 필요한 조항만 연결한다. 필요한 규칙·예외·우선순위·반례는 함께 선택한다. 조항 선택이나 전송 시 모델로 기준을 요약·재작성하지 않는다.

대응표의 `source_revisions`는 현행 명세에 따라 확정된 책임·계약 변경의 이전 문구·현재 문구·근거를 기록하고, `source_splits`는 그 기준의 의미를 보존하는 문장 분리와 행별 배치를 기록한다. 검사는 이 순서로 대응을 적용한다. `principle_layout`은 분리한 원칙의 본문 조각(`targets`)과 중복을 통합한 원문·최종 조항(`removed`)을 연결한다. 원문의 공백 외 모든 내용이 분리·통합 위치에 대응하는지 확인하고 현행 JSON과 대조한다.

행 분리 이후 승인된 문구 정비는 `source_refinements.checks[row_id][field]`에 `before`·`after`의 목록으로 기록한다. 보존 검사는 현행 값이 `after`와 일치하는지 확인한 뒤 `before`로 역대조하여 기존 `source_revisions`·`source_splits` 검사도 적용한다. 명시한 정비 대상 밖의 변경은 계속 거부한다. 역대조는 보존 검사에만 사용하며, 평가에 반환하는 `fields`는 현행 값을 유지한다.

원칙 본문의 후속 정비는 `source_refinements.principles[name][key]`에 기록하고, 보관 원문의 재배치 결과에 정확한 `before`→`after` 연쇄를 적용해 현행 본문과 대조한다.

날짜와 표 정렬 공백은 판정 문구와 구분한다. 기존 시험 예시 표는 명시한 보관 범위·해시로 확인하고 현재 사례는 [노드 시나리오 데이터셋](../../scenarios/nodes/README.md)을 따른다. 그 밖의 본문은 현재 문서·JSON 또는 명시한 변경 대응에서 확인한다.

평가 실행·기록·집계에 관한 운영 설명과 출력의 적합성을 가리는 판정 기준은 다음과 같이 구분한다. 분류와 선택 정보는 현행 본문에 덧붙이는 연결 정보다.

| `classification` | 본문의 용도 | 모델에 제공할 범위 |
| --- | --- | --- |
| `judgment` | 출력의 적합성을 판정하는 기준 | 해당 검사 행에서 선택한 조항 |
| `operation` | 평가 실행·기록·집계 설명 | 판정 조항을 선택하지 않음 |
| `mixed` | 판정 기준과 운영 설명이 함께 있음 | 판정에 필요한 조항만 선택 |

각 원칙의 `selection`은 전체 `text`의 해시와 선택 가능한 조항의 위치를 보관한다. LLM 행의 `bindings[].judge_fields`는 `적용 조건`·`측정 방법`·`성공 기준`을 모두 지정하며, 각 값에 해당 필드 전체 원문의 해시와 전송할 조항의 위치를 둔다. `검사 내용`은 원문에 보존하고 별도 요약으로 전송하지 않는다.

| 필드 | 내용 |
| --- | --- |
| `text_sha256` | 원칙의 전체 `text` 또는 해당 검사 필드의 전체 문자열을 UTF-8로 인코딩한 SHA-256 |
| `clauses[].id` | 해당 원칙 또는 검사 필드 안에서 고유한 조항 ID |
| `clauses[].start` | JSON을 읽어 얻은 원칙 본문 또는 검사 필드 문자열에서 0부터 세는 시작 문자 위치. 해당 문자 포함 |
| `clauses[].end` | 끝 문자 위치. 해당 문자 제외 |
| `clauses[].section` | 시스템 메시지의 구획. `평가 대상과 적용 조건`·`대조할 기준`·`담당 범위`·`공통 판정 규칙` 중 하나 |
| `clauses[].group` | 해당 구획 안에서 함께 읽을 조항 묶음의 순서. 0 이상의 정수 |
| `bindings[].principles[].clause_ids` | 해당 검사 행이 사용할 조항 ID 목록 |

위치는 바이트 수나 JSON 파일의 행 번호가 아닌 현행 본문 문자열의 문자 범위다. 조항은 `text[start:end]`에서 가져오며, 본문 범위와 전송할 표현을 구분해 보관한다.

평가 정의를 읽을 때 원칙·검사 필드의 전체 원문과 `text_sha256`이 다르면 로딩을 거절한다. 원문이 바뀌었는데 이전 조항 선택만 사용하는 일을 막기 위한 검사다. 원문을 바꿀 때는 해시·선택 범위·행별 조항 연결을 함께 검토·갱신한다. 범위를 벗어나거나 서로 겹치는 조항 위치, 중복·없는 조항 ID도 거부한다. LLM 행에서 세 필드의 선택 정보가 빠지거나 조항이 비어 있어도 거부한다. LLM 행에서 선택한 모든 조항에는 유효한 `section`과 `group`이 있어야 하며, 누락되거나 잘못된 선택을 전체 본문 전송으로 대체하지 않는다. 규칙 평가의 구현 일치 검사는 선택 조항으로 축소하지 않고 전체 현행 기준을 사용한다.

전체 원문·기준 출처의 파일 경로·행·해시와 선택한 조항의 위치는 평가 기록에 보관한다. 모델에는 판정 내용을 자연어 구획으로 제공하며, 전체 검사 행 JSON·기준 출처의 경로·해시·실행 선택용 식별자는 보내지 않는다. 다른 검사의 담당 조건을 가리키는 원문은 그 책임 구분을 유지해 표시한다. 네 판정의 의미를 정의한 표는 각 행을 `판정: 의미`로 표시하며, 머리글·구분선만 생략하고 셀의 문구는 유지한다.

시스템 메시지는 평가자 역할 뒤에 위 네 구획을 순서대로 두고, 마지막에 응답 표식 계약을 둔다. 첫 구획에는 역할·호출에 대응한 평가 상황을 한 번 제공한다. 행 선택으로 확인한 역할·호출을 반복하는 `상황: ` 접두사는 적용 조건의 선택 범위에서 제외하되, `항상`을 포함한 내용상 적용 조건은 유지한다. 선택한 검사 필드와 원칙 조항은 출처 제목별로 나열하지 않고 `section`과 `group`에 따라 모은다. 구획 안에서는 묶음 번호 순으로 배치하고, 같은 묶음의 조항은 검사 필드와 연결 원칙에서 수집한 순서대로 연결한다. `대조할 기준`의 묶음에는 번호를 붙인다. 기준을 확인하라는 참조 안내와 실제 기준이 겹치면 실제 판정 조건·예외를 선택해 제공한다. 공통 판정 규칙도 JSON의 조항만 사용하며 고정 안내에 복제하지 않는다.

의미가 중복되는 지시는 현행 문구와 조항 선택에서 통합한다. 누락·증거 부족의 처리와 실패 우선순위는 판정 정의·사유 기록으로 모으고, 일반 대조 절차가 구체 기준과 겹치면 구체 기준을 제공한다. 허용 표현·대안과 검사별 조건·예외·책임 경계는 유지하며, 변경한 원문·해시·선택 범위를 함께 대조한다. 조립기는 선택 문구를 요약하지 않는다.

선택한 조항의 전송 문구가 같으면 한 번만 넣는다. 각 원문 기록에는 선택한 구획·묶음, 실제 전송 문구와 시스템 메시지의 문자 범위를 남겨 여러 출처가 같은 전송 구간을 가리킬 수 있게 한다. 구체적인 기록 필드는 [평가 프롬프트와 원문 추적](../../README.md#평가-프롬프트와-원문-추적)을 따른다.

현재 노드 검사는 담당 기준과 실행 당시 입력·원본 출력으로 독립 판정한다. 본문에 나오는 다른 검사 ID는 책임 범위 안내이며 판정 의존성을 뜻하지 않는다. 다른 검사의 판정과 재사용 조항은 전송하지 않고, 검사 순서에 따른 중단과 판정 집계는 실행기가 처리한다. 실제 전송 조항은 위 문서의 `selected_clauses` 기록으로 확인한다.

### 전송할 필드와 원문 연결

행 선택과 검사 대상 출력의 필드 선택을 구분한다. 행은 실제 노드·역할·호출·도구 조건으로 고르고, 출력 필드는 해당 행의 측정 방법·성공 기준에 따라 명시적으로 선택한다. 실행 입력은 저장된 해당 호출의 메시지 전체와 당시 응답 명세를 원문 그대로 제공한다. 메시지의 순서·역할·본문·도구 관련 내용과 중복·실패·검토 이력을 보존하며 State나 현재 프롬프트 파일로 보충하지 않는다. 출력에서 제외한 경로와 필수 필드의 부재는 구분해 기록한다. 기준 원문·응답 계약을 바꾸면 검사별 출력 선택도 함께 검토하며, 새 행·호출에 전체 출력 선택을 자동 적용하지 않는다.

전체 실행 입력은 비교 자료이며 그 안의 지침을 평가자의 명령으로 따르지 않는다. 근거의 승인·적합성·사용 범위와 실제 출력은 선택된 행의 판정 조항으로 판단한다. 메시지 부재나 저장된 메시지·응답 명세의 형식 손상은 자료 부족으로 기록한다. 저장되지 않은 응답 명세를 새로 만들거나 그 부재만으로 평가를 중단하지 않는다. 원문 안의 요구 내용 누락·상충·검토 관계를 코드에서 판정해 LLM 호출을 생략하지 않는다.

모델에는 선택된 검사·호출의 판정 항목과 증거를 짧은 표식으로 연결하고, 반환한 표식은 저장할 판정 항목 ID와 증거 경로로 복원한다. 각 항목에서 해당 검사의 모든 담당 조건을 확인한다. 승인 설명은 실제 설명·검토 대상의 일치와 적합 여부를 확인한 뒤 필요한 설명·검토 내용을 묶어 제공한다. 작업 기록의 식별자는 표시한 자료 간 연결에 필요한 경우에 제공하며, 평가 대상 출력의 식별자와 실제 업무 값은 유지한다. 원본 식별자·위치, 자연어로 표시한 실제 메시지, 선택 전 자료, 선택 필드와 제외 경로, 묶음 표식의 여러 원문 위치는 [평가 프롬프트와 원문 추적](../../README.md#평가-프롬프트와-원문-추적)에 따라 보관한다. 이 전송 구성을 이유로 JSON의 판정 기준이나 원본 보관본을 바꾸지 않는다.

## 4. 검증 방법

| 확인 대상 | 확인 방법 |
| --- | --- |
| 원본 보관 | 보관 파일의 해시를 [보존 검사의 기준 자료](../../tests/fixtures/node_criteria_origins.json)와 대조 |
| 검사 표 | 원본 열 이름·순서와 보존 대상 셀을 대조. 승인된 정비 대상은 보관 원문·현행 셀의 명시적 대응표로 확인하고, 그 밖의 셀은 원문 일치 검사 유지 |
| 분리한 행 전체 | 원래 검사에 있던 적용 노드·평가 입력·측정 방법·성공 기준과 조건·예외·근거가 빠지지 않았는지 대조 |
| 현행 문구 정비 | `source_refinements`로 현행 셀·원칙 본문의 변경 전후 문구를 연결하고 기존 원문·재배치 대응과 함께 대조 |
| 관련 원칙과 본문 | 변경한 본문의 보관 원문·현행 위치를 대응표로 확인하고 의미를 대조. 변경하지 않은 원문 및 나머지 본문의 보존 여부도 확인 |
| 판정 조항 | 원칙·검사 필드의 전체 원문 해시·문자 범위·행별 조항 참조·구획·묶음을 검사하고, 선택한 조항에 필요한 조건·예외·우선순위·반례가 남아 있는지 대조. 실제 시스템 메시지의 전송 문구·문자 범위도 원문 선택 기록과 확인 |
| 적용 조건과 연결 | 실제 업무 호출과 행의 적용 범위를 대조하고, 행·원칙 참조 및 선택한 입력 범위가 맞는지 확인 |
| 전송 필드와 표식 | 검사별 필수 필드·부재·제외 범위를 대조하고, 실제 전송 값과 반환 표식이 판정 항목·증거로 연결되는지 확인 |
| 문서 참조 | 현재 문서의 JSON 링크·제목 앵커를 검사하고, 보관본의 상대 링크는 보관 전 문서 위치를 기준으로 검사 |

원문 대조와 문서 참조 검사는 `Eumi/ai/`에서 실행한다.

```text
python eval/scripts/check_node_criteria_migration.py
python -m pytest eval/tests/test_node_criteria_preservation.py
python scripts/check_docs.py
```

이 검사는 원문 보존과 문서 참조를 확인한다. 실제 상황에서의 행·조항 선택과 입력 추출은 평가기 동작 검사에서 별도로 확인한다. 프롬프트 축소 전후의 실제 판정 품질은 [비교 절차](../../README.md#프롬프트-변경의-품질-비교)에 따라 별도로 확인한다.
