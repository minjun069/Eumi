## 평가 범위

한 동·월의 보고서 작성에 진입해 반환할 때까지 시각화 선정 → 시각화 설명 → 퀵 인사이트의 연결 순서와 입력 전달, 최종 보고서 구성·완성 상태를 평가한다.

| 항목 | 내용 |
| --- | --- |
| 입력 | 보고서 작성 진입 시 받은 요청 ID, 대상 행정동 1개, 기준 월, 조회 가능한 분석 자료와 실행 상태 |
| 출력 | 선정 뷰 최대 3개, 대응하는 설명, 퀵 인사이트로 구성한 보고서와 반환 상태.<br>미완성 항목은 `NULL` |
| 평가 단위 | 한 동·월의 보고서 작성 진입부터 반환까지 1회.<br>내부 역할 전환은 같은 평가 실행에 포함 |
| 재진입 | 외부에서 오류가 난 동의 작성을 다시 호출하면 그 진입부터 반환까지를 별도 평가 실행으로 기록.<br>주어진 기존 상태·이력·누적 예산은 이어서 사용 |

여러 동의 배정·대기·재호출 결정과 서비스 연동의 제외 범위는 [실행 단위와 경계](README.md#실행-단위와-경계)를 따른다. 노드·역할이 반환한 결과를 기준으로 전달·연결·보고서 구성을 확인하며, 노드 내부 동작·품질은 [책임과 평가 구분](README.md#책임과-평가-구분)에 따라 노드 평가에 연결한다.

각 보고서 역할은 작업 진행 판단으로 시작한다. 역할별 입력·순서·재개·산출물의 근거는 [보고서 생성](../../../docs/agent/report.md), [실행 흐름](../../../docs/agent/workflow.md), [실행 상태](../../../docs/agent/state.md)다.

EX-R5의 완성·부분·생성 결과 없음 구분은 보고서의 완성 범위다. 이 구분으로 실제 실행의 `failed`·`cancelled` 상태나 기술적 실패 판정을 바꾸지 않는다.

## 기준 자료와 실행 증거

진입 요청·대상 동·월, 기대하는 역할 연결·입력·반환 조건, 재진입에 제공할 완료·오류 이력과 누적 예산을 실행 전에 정한다.

역할이 실제 반환한 결과·승인 참조, 역할 진입·반환의 상태와 호출 순서, 최종 보고서·상태를 수집한다. 재진입 사례는 주어진 승인·초안·검토·수정 이력과 이번 실행에서 새로 반환한 결과를 구분한다. 노드의 작성·검토 결과는 원본 산출물 ID와 해당 노드 판정에 연결한다.

상태·호출·자원 원본 수집과 모의·실제 실행의 구분은 [전체 실행 시험과 기록](common.md#전체-실행-시험과-기록)을 따른다. 실제 실행·판정 기록을 확보하기 전에는 검증 완료로 표시하지 않는다.

[단위 평가 실행기](../runner.md)의 `unit=workflow`, `target=report`와 [보고서 업무 테스트](../../../tests/test_reports.py)·[역할 연결 테스트](../../../tests/test_report_agents.py)에서는 이 문서의 역할 연결·반환 경계에 해당하는 증거를 사용한다. 재진입은 해당 입력과 실행 증거를 확보한 범위에서 판정한다.

## 기능 지표

검사별 통과율과 필수 평가 실행의 검증 완료 여부는 [공통 기능 지표](common.md#기능-지표)를 따른다. 보고서 완성률은 최종 보고서를 모두 구성해 실제 반환한 실행의 비율이다.

| 지표 | 적용 검사 | 측정 단위 | 계산 방법 | 집계 시점 | 용도 | 목표 |
| --- | --- | --- | --- | --- | --- | --- |
| 보고서 완성률 | EX-R4·5, EX-5 | 작성 실행 | 검토 통과한 3개 뷰·모든 설명·인사이트를 실제 반환하고 EX-R4·5와 EX-5를 통과한 실행 수 ÷ 시작한 평가 대상 동별 작성 실행 수 | 평가 묶음 종료 시 | 진단용.<br>부분 처리 합격과 별도 보고 | 별도 목표 없음 |

대상 동·월, 최초 진입·재진입, 사례 유형을 구분해 집계한다. 재진입은 진입부터 반환까지를 별도 실행으로 분모에 포함한다.

보고서를 완성했더라도 반환 전 실패 등으로 호출자에게 전달하지 못한 결과는 분자에서 제외한다. 미판정 실행은 분모에 남기고 분자에 넣지 않으며, 작성에 진입하지 않은 요청은 완성률에서 제외한다. 분모가 0이면 산출 불가로 기록하고 분자·분모의 실제 건수를 함께 보고한다.

자료 부족으로 적절히 부분 반환한 실행은 적용 검사를 통과할 수 있지만 완성률 분자에는 넣지 않는다. 미실행·미판정과 검증 완료 여부는 [공통 합격 판정](common.md#합격-판정)에 따라 함께 보고한다.

## 운영 지표

[공통 운영 지표](common.md#운영-지표)로 이번 동·월의 작성 진입부터 반환까지 측정한다. 재진입 전 이력·사용량은 기존 상태와 누적 한도 확인에 사용하며, 이번 실행의 자원 집계에는 진입 이후 실제 소비량만 포함한다.

## 합격 판정

필수 평가 실행과 예정 반복에서 적용 EX-R 검사와 공통 검사를 모두 확인하고 통과해야 기능 합격이다. 노드 품질·보고서 완성률·실행 규칙 준수·운영 목표 충족은 구분해 보고한다.

실패·미판정·미실행과 검증 완료 여부, 운영 합격·보류 조건은 [공통 합격 판정](common.md#합격-판정)을 따른다. 자동 채점·집계의 현재 지원 범위는 [단위 평가 실행기의 제약](../runner.md#7-현재-제약과-후속-작업)에서 확인한다.

## 남은 확인 사항

운영 목표·시험 조건·반복 횟수·실행 증거와 노드 내부 검증의 남은 사항은 [공통으로 남은 확인 사항](common.md#남은-확인-사항)을 따른다.
