# 에이전트 실행 평가

상태: 검토용 명세. 수정일: 2026-11-13.

에이전트가 작업 하나를 수행하며 노드를 올바르게 연결하고 결과를 반환하는지 평가한다. 기능 평가는 연결·반환 규칙을, 운영 평가는 실행 전체의 성능·안정성을 다룬다. 절차·입력 명칭·판정은 [평가 방법](../methods.md)을 따른다.

## 평가 문서

| 평가 대상 | 문서 내용 |
| --- | --- |
| [사용자 요청 처리](user-request.md) | 한 질문에서 목적 파악·진행 판단·작업 실행·응답 또는 질문 반환을 연결하는 기준 |
| [대시보드 보고서 생성](dashboard-report.md) | 한 동·월의 선정 → 설명 → 인사이트 역할 순서·승인 결과 전달·오류 후 재개·보고서 구성 |
| [공통 평가 기준](common.md) | 노드 간 전이·상태 전달·공유 예산·중단·최종 반환 검사와 기능·운영 지표 |

## 실행 단위와 경계

| 항목 | 사용자 요청 처리 | 대시보드 보고서 생성 |
| --- | --- | --- |
| 실행 단위 | 질문 하나에 대한 에이전트 호출 1회 | 특정 동·월의 보고서 작성 호출 1회 |
| 시작 | 준비된 요청·대화·화면 문맥과 초기 상태로 에이전트에 진입한 시점 | 해당 동·월의 입력과 상태로 동별 작성 흐름에 진입한 시점 |
| 종료 | 최종·부분 응답 또는 질문을 반환하거나 오류·취소로 종료한 시점 | 해당 동의 보고서·부분 결과를 반환하거나 오류·취소로 종료한 시점 |
| 확인 결과 | 실제 반환 응답·산출물·종료 상태와 사유 | 보고서 구성·완성 여부·종료 상태와 사유 |

호출자에게 반환한 뒤 다시 진입하면 별도 평가 실행이다. 받은 이력·누적 한도는 실행 계약에 따라 보존하며, 운영 지표는 [이번 진입 이후의 소비량](common.md#운영-지표)만 집계한다. 미종료 실행은 관측 종료 시점과 마지막 확인 결과를 남긴다.

실행 중 도구를 통한 DB 조회와 하위 호출의 시간·자원은 전체 측정에 포함한다. 서비스의 접수·입력 준비·반환 후 DB 저장·알림·화면 표시, 여러 동의 배정·대기·재호출 결정·전체 완료 집계는 평가에서 제외한다.

## 책임과 평가 구분

[평가 단위와 책임](../methods.md#평가-단위와-책임)에 따라 개별 노드의 판단·작성·호출·상태 갱신·이력 기록은 노드 평가에 둔다. 에이전트 평가는 노드가 반환한 결과의 전달·전이·공유 한도·최종 반환을 확인한다. 노드 내부의 기록 생성과 단계 간 기록 보존을 구분한다.

| 구분 | 하위 항목 | 확인할 내용 |
| --- | --- | --- |
| 기능 평가 | 공통 실행 규칙 | 노드 간 순서·상태 전달, 공유 한도, 중단·최종 반환 경로 |
| 기능 평가 | 보고서 생성 흐름 | 역할 간 순서·승인 결과 전달·오류 후 재개, 최종 보고서 구성·완성 상태.<br>공유 예산은 공통 검사 판정 참조 |
| 운영 평가 | 전체 실행의 성능·안정성 | 종료 결과 분포·기술적 실패율·시간·호출량·토큰·비용·반복 결과 |

기능·운영 합격은 따로 판정한다. 올바른 부분 반환은 실행 규칙을 통과할 수 있지만 보고서 완성 건수에는 포함하지 않는다. 정상 종료만으로 내용 품질이나 사용자 업무의 해결을 판정하지 않는다.

## 검사 분류

기능 검사표에는 다음 네 열을 둔다. 관찰 범위·검사 대상·평가 관점은 대표값 하나를, 실행 상황은 해당 값을 쉼표로 구분해 적는다. 적용 여부는 각 행의 적용 조건으로 정하며, 상황별 입력·방법·성공 기준이 다르면 행을 나눈다.

| 열 | 가능한 분류 | 적용 기준 |
| --- | --- | --- |
| 관찰 범위 | 개별 내부 동작 / 단계 간 연결 / 실행 전체 | 노드 내부, 노드·역할 간 경계, 진입부터 반환까지의 전체 실행을 구분한다.<br>개별 내부 동작은 노드 책임이므로 이 평가에서 제외한다. |
| 검사 대상 | 입력 / 상태·이력 / 호출·전이 / 반환 결과 | 다음 단계에 건네는 입력, 경계에서 보존하는 상태·이력, 실행 순서·중단, 최종 보고서·호출자 반환 중 직접 비교하는 대상을 표시한다. |
| 평가 관점 | 규칙 준수 / 결과 완성 / 안정성 / 효율성 | 정해진 실행 계약, 반환 결과의 구성·완성 여부, 실행의 실패·반복 양상, 소비한 시간·자원을 구분한다. |
| 실행 상황 | 정상 / 자료 부족 / 오류·재시도 / 한도·취소 | 적용하는 입력·발생 조건을 표시한다.<br>여러 상황에 같은 방법·기준을 적용하면 한 행에 함께 적는다. |

오류·한도 상황에서도 기능 검사는 중단·재개 규칙을 확인하고, 운영 지표는 발생률·시간·사용량을 측정한다. 분류값을 점수나 별도 합격 조건으로 사용하지 않는다.

## 판정 연결

같은 대상·조건은 [담당 검사의 판정·증거](../methods.md#검사-범위와-판정-연결)를 참조한다. 도구의 처리·반환 정확성은 [도구 평가](../tools.md), 노드 내부 동작·내용 품질과 현재 검사 지원 범위는 [노드 평가](../nodes/README.md)에 연결한다. 에이전트 연결 검사 통과를 노드 내부 검증 완료로 확대하지 않는다.

실제 최종 반환에 채택된 작성 결과는 [최종 출력 품질 평가](../runner.md#9-최종-출력-품질)로 응답 작성 노드의 판정에 연결한다. 최종 품질·EX 기능·운영 판정은 각각 보고하며, 작성 내용의 같은 결함을 새 EX 검사로 중복 판정하지 않는다.

책임 근거는 [기능 명세](../../../docs/agent/components.md), [실행 흐름](../../../docs/agent/workflow.md), [실행 상태](../../../docs/agent/state.md), [보고서 생성](../../../docs/agent/report.md)이다. 실행 증거의 수집 범위와 자동 채점 지원은 [단위 평가 실행기](../runner.md)를 따른다.
