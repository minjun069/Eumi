# 공통 평가 기준

상태: 검토용 명세. 수정일: 2026-11-13.

[에이전트 실행 평가](README.md)

여러 노드의 연결·전달·공유 한도와 한 작업의 반환·종료를 검사하고, 실행 전체의 성능·안정성을 측정한다. [사용자 요청 처리](user-request.md)와 [대시보드 보고서 생성](dashboard-report.md)에 함께 적용한다.

## 평가 범위

[실행 단위와 경계](README.md#실행-단위와-경계), [책임과 평가 구분](README.md#책임과-평가-구분)을 따른다. 노드가 반환한 상태·결과를 다음 단계 또는 호출자에게 전달할 때의 원본으로 삼는다. 한 진입 안의 보완·재시도·역할 전환은 같은 평가 실행에 포함한다.

## 전체 실행 시험과 기록

실행 전에 사례별 실행 상황과 아래 조건을 정한다. 실제 연결과 모의 결과를 구분하며, 모의 결과로 확인한 연결을 실제 모델의 품질·운영 성능으로 확대하지 않는다.

| 준비·기록 | 확인할 내용 |
| --- | --- |
| 시험 조건 | 요청·자료·모델·지침·배포 버전, 입력 규모·연결 환경, 초기 상태·누적 예산, 필수 검사·예정 반복 횟수와 운영 목표를 고정한다. |
| 경계 증거 | 이번 실행의 진입·반환, 각 노드·역할의 진입·반환 상태와 호출 순서를 연결한다.<br>모델 반환값만으로 노드 간 전달을 확인한 것으로 처리하지 않는다. |
| 예외 조건 | 정상 시험과 결함 주입 시험을 구분하고 오류·취소·한도의 발생 위치와 기대 경로를 남긴다.<br>재진입은 이전 실행과의 관계·기존 이력·누적 사용량을 함께 기록한다. |
| 최종 결과 | 실제 반환 응답·산출물·상태·종료 사유를 남긴다.<br>반환 전에 종료되거나 관측이 끝나면 마지막 확인 상태와 결과 유무를 기록한다. |
| 운영 원본 | 실행·호출 시각, 실제 모델·도구·하위 호출, 노드 진입·재시도, 입력·출력 토큰과 적용 단가를 보존한다.<br>평가용 모델의 사용량은 업무 실행과 분리한다. |

노드 반환 상태와 다음 노드 진입 상태가 없으면 해당 전달 검사는 미판정이다. 개별 역할 단독 실행은 원인 확인용이며 전체 연결 검증을 대신하지 않는다. 증거 수집·자동 채점의 지원 범위는 [단위 평가 실행기](../runner.md)를 따른다.

## 평가 지표

### 기능 지표

공통·업무별 기능 검사는 아래 기준으로 집계한다. 검사 ID별로 계산하며 여러 검사를 합친 평균이나 분류별 점수로 대신하지 않는다.

| 지표 | 적용 검사 | 측정 단위 | 계산 방법 | 집계 시점 | 용도 | 목표 |
| --- | --- | --- | --- | --- | --- | --- |
| 검사별 통과율 | 해당 업무의 공통·전용 기능 검사 | 평가 실행 1회당 해당 검사 1건 | 해당 검사를 통과한 실행 수 ÷ 해당 검사에 통과·실패 판정이 있는 실행 수 | 평가 묶음 종료 시 | 연결·반환 오류 진단 | 별도 수치 목표 없음.<br>기능 합격은 필수 검사의 전부 통과로 판정 |
| 필수 사례 통과율 | 사례에 적용한 기능 검사 | 필수 사례 | 예정 반복의 적용 검사를 모두 통과한 사례 수 ÷ 통과·실패 판정이 있는 필수 사례 수 | 평가 묶음 종료 시 | 기능 합격 판정 | 전체 필수 사례의 검증 완료 및 적용 검사 전부 통과 |

검사별 통과율은 미실행·미판정·비적용을 분모에서 제외하고 건수와 비적용 사유를 남긴다. 필수 사례는 확인된 실패가 하나라도 있으면 실패로 판정한다. 통과는 예정 반복의 적용 검사를 모두 확인한 경우에만 인정하며, 실패 없이 필수 확인이 남은 사례는 사례 통과율 분모에서 제외한다. 실패 사례에도 미확인 조건이 있으면 검증 미완료로 함께 기록한다.

분자·분모의 실제 건수와 전체 필수 사례의 검증 완료·미완료 현황을 함께 보고한다. 분모가 0이면 산출 불가다. [보고서 완성률](dashboard-report.md#기능-지표)은 규칙 준수와 별도로 기록한다.

### 운영 지표

한 실행의 종료 결과와 반환 범위, 성능·안정성을 측정한다. 외부 서비스 콜백의 저장·알림 시간이 섞이면 그 구간을 분리한다. 분리할 증거가 없으면 내부 실행 시간은 측정 미완료로 남긴다.

누적 예산은 한도 적용에 유지하고, 이번 사용량은 진입·종료 누적값의 차이 또는 이번 진입 이후 호출 기록으로 구한다. 이전 실행의 소비량·외부 재호출 대기 시간·평가용 호출은 제외한다. 상위·하위·보고서 역할에 중복 기록된 호출의 시간·사용량·비용은 한 번만 센다.

업무·역할·최초 진입과 재진입·입력 규모·환경별로 집계한다. 실제 연결과 모의 구성, 정상 시험과 결함 주입 시험을 분리한다. 대상 지역·기간은 개별 실행 정보로 보존하며 집계를 나누거나 필터링하는 조건으로 쓰지 않는다. 평균·중앙값·p95는 집계 대상 개별 실행의 측정값으로 계산한다. p95는 측정값의 95%가 그 값 이하인 지점이다.

| 지표·기록 | 평가 관점 | 측정 단위 | 측정·계산 방법 | 집계 시점 | 용도 | 목표·판정 기준 |
| --- | --- | --- | --- | --- | --- | --- |

| 기술적 실행 실패율 | 안정성 | 종료한 실행 | 기술적 문제로 실패한 실행 수 ÷ 종료한 실행 수.<br>미종료는 제외하고 시작·종료·미종료 건수를 함께 보고한다. | 평가 묶음 종료 시 | 안정성 진단·운영 판정 | 필수 운영 목표로 지정한 경우 시험 전에 최대 비율 확정 |
| 실행 시간 | 효율성 | 종료한 실행 | 이번 진입부터 반환·종료까지 경과 시간의 종료 결과별 중앙값·p95를 계산한다.<br>하위·역할별 시간은 원인 확인용이며 전체 시간에 다시 더하지 않는다. | 평가 묶음 종료 시 | 성능 진단·운영 판정 | 필수 운영 목표로 지정한 경우 시험 전에 통계값·상한 확정 |

부분·질문·거부·자료 없음 자체는 기술적 실패가 아니다. 하위 장애를 처리하고 정상 반환한 경우에도 하위 오류와 전체 종료를 구분한다. 기술적 실패와 평가 과정의 실패는 [판정 원칙](../methods.md#기술적-실패와-기능-판정)을 따른다.

미종료 실행은 관측 종료 시점·경과 시간·마지막 상태·확인된 소비량을 별도로 남긴다. 측정 누락은 0으로 채우지 않으며 해당 통계에서 제외하고 누락 건수를 보고한다. 입력·출력 토큰은 각각 누락을 확인하고, 사용량이나 단가가 없으면 비용은 산출 불가다. 분모가 0이면 비율을 산출하지 않는다. 평가 과정의 실패는 업무 실행의 기술적 실패율에 넣지 않고 측정 미완료 사유로 남긴다.

노드·도구 오류는 담당 평가에 증거를 연결하고 전체 반환·운영 결과에 미친 영향을 기록한다. 관측한 종료·사용량은 보존하되 오류 없는 실행과 구분한다. 낮은 비용·시간으로 기능을 통과시키거나, 올바른 오류 처리로 기술적 장애를 없었던 것으로 바꾸지 않는다.

## 합격 판정

| 구분 | 합격 조건 | 보류 조건 |
| --- | --- | --- |
| 기능 평가 | 전체 필수 사례·예정 반복의 적용 공통·전용 검사를 확인하고 모두 통과 | 실패 없이 미실행·미판정·필수 조건 미확인 또는 경계 증거 부족 |
| 운영 평가 | 실제 연결 환경에서 예정한 측정을 완료하고 사전에 필수로 지정한 성능·안정성 목표 충족 | 필수 목표·시험 조건·반복 횟수 미확정, 해당 측정 누락·미종료 또는 오류 영향 미해결 |

확인된 실패는 해당 범위의 불합격으로 판정하고 남은 필수 조건은 검증 미완료로 기록한다. 기능·운영 합격은 별도로 보고한다. 실행 한도 준수는 EX-3·4의 기능 계약이고, 운영 목표는 지정한 환경의 시간·실패율 등 성능 기준이다.

업무별 적용 범위는 [사용자 요청 처리](user-request.md#합격-판정)와 [대시보드 보고서 생성](dashboard-report.md#합격-판정)을 따른다.
