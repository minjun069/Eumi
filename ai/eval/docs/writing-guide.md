# 평가 문서 작성 지침

수정일: 2026-11-13. 평가 문서의 작성·수정·검토에 적용한다. 공통 작성 원칙·서식·검수는 [문서 작성 지침](../../docs/writing-guide.md)을 따른다.

## 1. 작성 원칙

- 검사할 기능·제약·수행 의무는 현행 명세에 근거한다. 명세에 없는 기능이나 검토·기록 의무를 추가하지 않는다.
- 검사 범위는 [평가 단위와 책임](methods.md#평가-단위와-책임)을 따른다. 다른 단계가 맡은 작업의 성공·실패를 현재 대상의 결과로 판정하지 않는다.
- 같은 조건을 여러 검사에서 확인할 때는 [검사 범위와 판정 연결](methods.md#검사-범위와-판정-연결)에 따라 기존 판정과 증거를 참조한다.
- 판정 기준·필요한 증거·실패 시 수정할 동작이 다르면 검사 항목을 우선 나눈다.
- 같은 기준으로 확인하는 조건은 하나의 검사로 묶는다. 조건마다 따로 실패할 수 있다는 이유만으로 항목을 나누지 않는다.
- 검사 항목을 묶어도 조건별 적용 범위·충족 여부·근거는 남긴다.
- 판정이나 개선에 쓰이지 않는 검사·지표·구현 설명은 제외한다.
- 평가 방식은 [검사 방식의 선택 기준](methods.md#검사-방식)에 따라 정하며, 한 검사에는 한 방식을 적용하는 것을 원칙으로 한다.
- 여러 평가 방식을 함께 쓰기 전에 검사 범위와 기존 검사가 맡은 조건을 검토한다.
- 여러 방식을 함께 써야 한다면 그 이유, 방식별 담당 조건, 결과를 합쳐 판정하는 방법, 판정할 수 없는 경우의 처리를 쓴다.
- 적용 검사·판정 기준은 실행 전에 정한다. 규칙 기반 비교에 필요한 기대값·허용 오차는 해당 규칙에 따라 준비한다. 노드의 LLM 기반 검사는 실행 당시 입력·실제 출력과 명시한 기준으로 판정한다. 실제 출력에 맞춰 기준을 바꾸지 않는다.
- 별도 평가 자료는 평가 대상의 실행 입력에 섞지 않는다.
- 평가 입력은 [입력 선정 원칙](methods.md#입력-선정-원칙)을 따른다. 노드 LLM 검사에는 실행 당시 모델 호출 입력 전체를 제공하고, 측정 방법에 대조할 내용과 조건을 쓴다. 규칙 검사와 검사 대상 출력은 필요한 범위를 지정한다.
- 시험 사례는 기본 기능부터 확인하도록 구성한다. 필수 예외는 판정 기준과 함께 남기고, 기준이 불명확하면서 우선순위가 낮은 특수 상황은 제외한다.

## 2. 구조와 서식

### 문서 구성

- [평가 방법](methods.md)은 여러 평가 단위에 공통인 용어·절차·기록·판정·집계 원칙과 해당 정의의 위치를 안내한다.
- 특정 평가 단위의 분류·검사 순서·기준·예외는 해당 단위 문서에 둔다. 여러 노드에만 공통인 기준도 노드 문서에서 관리한다.
- 여러 대상을 다루는 문서는 대상별 평가 범위·전용 검사를 묶는다. 공통 검사·준비 자료는 별도 절로 모은다.
- 노드 검사는 전용·공통 검사로 묶고 [세 평가 축](nodes/common.md#노드-검사의-세-축)에 따라 분류한다. 공통 검사에는 노드별·산출물별 기준을 연결한다.
- 에이전트 실행 검사는 [평가 단위와 책임](methods.md#평가-단위와-책임)의 진입·반환 경계를 따른다. 공통 실행 기준과 업무별 기준을 구분한다.
- 에이전트 실행 검사의 네 분류와 표기 기준은 [검사 분류](execution/README.md#검사-분류)를 따른다.
- 평가 지표와 합격 판정은 대상별·공통 평가 뒤에 둔다.

### 검사 표

노드 평가의 프롬프트·판정 로직이 읽는 검사 정의·출력 형식·관련 원칙은 [노드 평가](nodes/README.md)에 연결한 JSON을 단일 원본으로 관리한다. Markdown에는 평가 범위·지표와 논리 설명을 두고 정형 정의를 참조한다. 아래 속성별 작성 기준은 정형 정의에도 적용한다.
노드 정의의 초기 이관과 이후 현행 기준 정비는 [원문을 옮기는 절차](nodes/migration.md#2-원문을-옮기는-절차)를 따른다. 보관 원문과 현행 기준을 구분하고, 조항 분리·중복 통합·선택 범위의 관리와 의미 보존 검증은 [판정 조항 선택](nodes/migration.md#판정-조항-선택)을 따른다.
적용 상황에 따라 필요한 입력·대조 대상·성공 기준이 달라지면 별도 행으로 나누고, 각 행에 판정에 필요한 내용을 완결해 쓴다. 적용 여부만 달라지고 평가 방법·기준이 같으면 한 행의 적용 조건으로 표현한다.

검사 항목을 행에, 속성을 열에 두고 같은 열 순서를 유지한다. 표 안에서는 문장마다 줄을 바꾼다.
각 열의 뜻은 [평가 방법의 용어 정의](methods.md)를 따른다.

| 열 | 작성 기준 |
| --- | --- |
| 검사 항목 | 검사 대상을 알아볼 수 있는 짧은 이름을 쓴다. |
| 검사 내용 | 무엇을 대상으로 어떤 성질·동작을 확인하는지 한 문장으로 쓴다. |
| 적용 조건 | 해당 검사 전체가 필요한 상황을 쓴다. 모든 실행에 적용하면 `항상`으로 표시한다. |
| 평가 방식 | 정의된 분류명만 쓴다. 여러 분류값이 필요하면 쉼표로 구분한다. |
| 평가 입력 | [검사 입력 목록](methods.md#검사-입력)의 명칭과 분류별 표기 형식을 따른다. |
| 측정 방법 | 비교할 출력·입력·기준, 자료의 제공 조건과 대조 절차를 쓴다. 통과 조건·예외를 반복하지 않는다. |
| 성공 기준 | 실제 결과에서 확인할 통과 조건·예외를 쓰고, 조건이 겹치면 적용 우선순위를 정한다. 별도 기준 조항에 정의한 조건은 해당 조항을 연결하고 다시 나열하지 않는다. |

- 판정 단위가 공통이면 한 번만 정의하고, 검사마다 다를 때만 표에 표시한다.
- 검사 전체 판정과 세부 조건별 결과를 구분한다. 노드는 [노드 검사 판정](nodes/common.md#노드-검사-판정)을 따른다.
- 적용 조건과 비적용 사유는 [공통 판정 원칙](methods.md#4-판정-원칙)을 따른다.
- 평가자가 만든 요약이나 모델이 받지 않은 정보를 실행 당시 입력으로 쓰지 않는다.
- 모델의 내부 사고 과정을 추측해 성공·실패를 판정하지 않는다.

### 기준과 시험 사례

- 형식 검사에 필요한 구조·필드·자료형·필수 여부·허용값·분량을 평가 문서에 정의한다. 코드나 실행 시 스키마를 참조하는 것만으로 대신하지 않는다.
- 공통 형식과 대상별 차이는 각각 한 곳에서 정의하고, 해당 검사에서 연결한다.
- 실행마다 달라지는 등록 조건은 사례에 적용한 기준과 버전을 지정한다.
- 내용 검사는 허용하는 표현 차이와 누락·왜곡·근거 없는 추가 등 실패 조건을 구체적으로 쓴다.
- 내용을 판정할 때는 입력의 어느 부분을 결과의 어떤 문장·값과 대조했는지 근거를 남기도록 한다.
- LLM 검사는 [LLM 판정 절차](methods.md#llm-판정-절차)에 따라 기준 사례와 사람 검토 방법을 정한다.
- 시험 사례에는 입력과 발생 상황을 문장으로 설명하고 적용 검사를 연결한다. 규칙 기반 비교에 필요한 기대 결과는 해당 검사에 연결한다.

### 지표와 합격 판정

- 지표의 종류와 수는 확인할 문제와 집계 목적에 맞게 정한다. 검사 분류나 다른 문서의 지표 수에 맞춰 늘리지 않는다.
- 반복 실행은 사례의 통과 조건으로 다룰 수 있으면 별도 지표를 만들지 않는다.
- 지표 표는 기능·운영으로 나누고, 같은 분류는 한 표에 모은다.
- 특정 대상에만 적용하는 지표는 적용 대상을 표시한다.
- 지표마다 측정 단위·계산 방법·집계 시점·목표값을 구분해 쓴다.
- 비율은 분자·분모가 드러나는 식과 제외 기준을 쓰고, 실제 집계 건수도 확인할 수 있게 한다.
- 중복 집계와 미실행·미판정 처리는 [판정 원칙](methods.md#4-판정-원칙)과 [결과 보고](methods.md#5-결과-보고)를 따른다.
- 문제 진단에 쓰는 지표와 합격 판정에 쓰는 지표를 명시한다.
- 합격·보류 조건에는 필수 검사·예정한 반복 실행·검증 완료 여부를 반영한다.
- 미확정 기준은 확정할 시점과 그전까지 판정을 보류할 범위를 쓴다.

## 3. 수정과 검수

검사 항목을 합치거나 나눌 때는 요구사항·시험 사례·지표·합격 기준의 연결을 함께 갱신한다.
상위 문서의 [수정과 검수](../../docs/writing-guide.md#3-수정과-검수)에 더해 다음 항목을 확인한다.

| 검수 | 확인할 내용 |
| --- | --- |
| 검사 범위 | 검사 대상과 의무가 명세의 담당 범위에 맞는지 확인 |
| 검사 변경 | 항목을 합치거나 나누면서 필수 조건이 빠지거나 같은 조건을 중복 평가하지 않는지 확인 |
| 판정 가능성 | 선택한 평가 방식과 기준으로 담당 조건 전체를 판정할 수 있는지 확인 |
| 평가 입력 | 입력을 줄여도 누락·왜곡·근거 없는 추가를 찾을 증거가 남아 있는지 확인 |
| 판정 구분 | 기능 오류·기술적 실패·평가 과정의 실패를 구분하고, 미실행·미판정을 정해진 기준으로 처리하는지 확인 |
| 지표 집계 | 계산 대상·집계 시점·제외 기준이 명확하고 같은 판정을 중복 집계하지 않는지 확인 |
| 합격 판정 | 필수 검사와 반복 실행의 결과·검증 완료 여부로 합격·보류를 결정할 수 있는지 확인 |
