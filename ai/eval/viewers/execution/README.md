# 에이전트 실행 평가 결과 뷰어

수정일: 2026-11-14.

기존 [평가 뷰어](../results/README.md)의 화면과 [노드 뷰어](../nodes/README.md)의 탐색 구조를 사용하는 실행 결과 뷰어다. `score-executions`이 저장한 실행 연결 검사·보고서 완성률·운영 통계와 `score-outputs`이 저장한 최종 출력 품질을 별도로 확인한다. 기능·품질 지표와 합격 판정은 저장값을 표시한다. 운영 통계는 선택한 조건에 해당하는 개별 실행 측정값으로 집계한다.

## 사용 방법

`Eumi/ai`에서 다음 명령으로 서버를 시작하고 [실행 평가 뷰어](http://127.0.0.1:8872/eval/viewers/execution/)에 접속한다.

```powershell
python -m http.server 8872 --bind 127.0.0.1
```

`eval/outputs/evaluation-viewer/catalog.json`에서 목록을 읽고, 실행·최종 출력 품질 채점 또는 에이전트·보고서 실행이 확인된 묶음만 **평가 묶음**에 표시한다. 도구·노드 전용 묶음과 유형을 확인할 수 없는 묶음은 제외한다. 첫 묶음 또는 새로 선택한 묶음의 실행·채점 자료를 자동으로 모두 읽는다. 채점 JSON을 읽을 때 형식을 확인한다.

자동 읽기에는 입력 묶음, 모든 사례·반복의 입력·결과·실행 조건·전체 추적, 모든 실행·품질 채점 기록의 집계·검사·기준·평가 모델 추적이 포함된다. 사례·반복·탭·채점 기록을 바꿀 때는 이미 읽은 자료를 사용하며 별도 **원문 읽기** 버튼은 없다. 실행 추적은 사례의 실제 실행 도식에 사용한다.

자동 조회의 파일당 한도는 **128 MiB**다. 큰 기존 로그를 동시에 읽는 부담을 줄이도록 실행·채점 작업 두 개씩 처리한다. 읽는 동안 본문 캐시는 최대 32 MiB·4,096개이며 같은 본문의 동시 요청을 공유한다. 완료 후 요청 캐시는 비우고 선택한 묶음의 복원 결과를 메모리에 유지한다. 다른 묶음을 선택하거나 화면 샘플로 바꾸면 이전 읽기를 취소하고 이전 결과를 해제한다. 큰 묶음은 처음 열 때 시간이 걸릴 수 있다.

읽기 오류는 저장된 실패·미판정과 구분한다. 누락·형식 오류가 있는 파일은 오류를 표시하고, 읽은 검사와 저장 집계는 유지한다. 원본 파일은 브라우저 메모리에서만 읽고 수정하지 않는다. 상단에는 **화면 샘플** 버튼을 제공하며 시작 화면에서 수동으로 결과 폴더를 열 수 있다. 수동 선택의 합계 64 MiB 한도와 경로·파일 연결 검사는 [공통 조회 안내](../results/README.md#1-사용-방법)를 따른다. `file://`에서는 자동 조회를 사용할 수 없다. 자동 읽기 진행 상태는 본문에 표시하고 완료 후 숨기며 오류는 남긴다.

실행·채점 저장 후 조회 목록이 갱신되며, 열린 화면은 새로고침한다. 수동으로 복사한 결과는 `python -m eval.viewers.catalog`로 갱신한다.

| 결과 폴더의 자료 | 표시 범위 |
| --- | --- |
| `batch.json`이 있는 결과 폴더 | 시나리오별 검사 결과·기능·운영 지표, 입출력 |
| `execution-evaluation-v1` JSON | 기능·운영 지표와 계획된 반복의 판정·측정. 실행 원본이 없으면 입출력은 미제공 |
| `output-evaluation-v1` JSON | 최종 반환 항목의 품질 판정, 작성 호출별 검사·평가 모델 근거. 기능·운영 지표는 별도 채점 기록이 있어야 표시 |
| 개별 `report.json` | 에이전트 또는 보고서 전체 실행의 입출력. 채점 파일이 없으면 지표는 미제공 |
| **화면 샘플** | 고정한 모의 모델 응답과 합성 자료를 실제 실행기·채점기로 처리한 가상 자료. 실제 평가 결과와 구분하여 표시 |

최신 기록을 먼저 표시하며 **실행 기능·운영 채점 기록**과 **최종 출력 품질 채점 기록**을 각각 선택한다. 한쪽 기록을 바꿔도 다른 쪽의 선택·판정은 유지한다. 선택 목록은 `채점 02`처럼 표시하고, 저장 이름과 번호는 [실행기 저장 규칙](../../docs/runner.md#4-저장-결과)을 따른다. 파일명·저장 위치·다운로드·이전 UUID 기록의 표시는 [공통 표시 안내](../results/README.md#1-사용-방법)와 같다. 폴더를 열면 상대 경로로 같은 이름의 파일을 구분한다. 지원하지 않는 자료만 선택하면 기존 화면을 유지하고, 일부 파일의 오류는 나머지 자료와 분리해 표시한다. 도구·노드 채점은 각각의 뷰어에서 연다.

## 결과 확인

| 대상 | 기능 평가 | 운영 측정 |
| --- | --- | --- |
| 사용자 요청 처리 | 공통 실행 검사 `EX-1`∼`EX-5` | 한 번의 에이전트 진입부터 반환까지 |
| 대시보드 보고서 생성 | 공통 검사와 보고서 검사 `EX-R1`∼`EX-R5` | 한 동·월의 선정 → 설명 → 인사이트 전체 실행 |
| 해석·시각화·보고서 선정·설명·인사이트 역할 단독 | 운영 진단 전용으로 표시 | 해당 역할의 한 번의 진입부터 반환까지 |

측정·판정 계약은 [실행 전체 채점](../../docs/runner.md#8-실행-전체-채점), 검사 기준은 [에이전트 실행 평가](../../docs/execution/README.md)를 따른다. 위 표의 기능 평가 범위와 별도로 여섯 역할의 에이전트와 보고서 전체 실행에 [최종 출력 품질 채점](../../docs/runner.md#9-최종-출력-품질)을 표시한다.

| 화면 | 표시 내용 |
| --- | --- |
| 사례 목록 | 사이드바에서 대상별 검색·필터·사례 선택. 전체 집계에서도 사례 상세로 이동 |
| 개별 사례 | 본문 전체 너비에 상단의 시나리오명·이상적인 시나리오와 실제 실행 도식, 기능지표 / 최종 출력 품질 / 운영지표 / 입출력 탭 |
| 전체 집계·통계 | 기능지표 / 최종 출력 품질 / 운영지표 탭 |
| 기능 지표 | 저장된 검사별 통과율·판정 건수, 필수 사례 통과율과 검증 완료 여부, 누락·미완료 반복 |
| 최종 출력 품질 | 저장된 품질 집계, 반환 항목·원문·경로, 작성 호출 연결, 원본 노드·모델 호출별 검사와 평가 모델 입력·원응답 |
| 보고서 완성률 | 완성 반환·구성·완성 검사를 충족한 실행 수와 시작한 보고서 실행 수 |
| 운영 지표 | 에이전트별 탭과 다중 선택 조건 칩, 선택 범위의 종료 결과 분포·기술적 실패율·시간·호출량·재시도·토큰·비용 통계, 운영 목표, 반복별 측정과 미종료 사용량 |

사례 목록은 사이드바의 평가 대상 아래에 표시하며, 상세 화면은 사이드바를 제외한 본문 전체 너비를 사용한다. 사이드바 오른쪽 경계를 드래그하거나 경계에 초점을 맞춰 좌우 방향키·Home·End로 너비를 조절할 수 있다. 넓은 화면에서는 두 채점 기록 선택을 나란히 표시한다. 평가 대상은 제목 없이 목록으로 표시한다. 모바일에서는 너비 조절 없이 사례 목록·채점 기록 선택을 접어서 시작하고, 필요한 영역을 펼쳐 선택한다. 사례 선택 시 상세로 이동하며 목록으로 돌아가도 검색·필터를 유지한다.

본문·검색·주요 탭·JSON 값은 16px, 보조 설명은 14px 이상으로 표시한다. 표·JSON·탭은 좁은 화면에서 영역 안의 가로 스크롤로 확인하며 글자를 축소하지 않는다. 검색은 입력창 위에 항상 보이는 라벨을 제공한다.

사례 목록에는 시나리오의 한글 제목을 표시하고, 상세에서는 제목 앞에 `Scenario `를 붙인다. 개별 사례는 상단에서 실행 건을 선택하고 네 탭으로 확인한다. **기능지표**에는 탭 바로 아래 기능 지표와 그 아래 검사 항목, **최종 출력 품질**에는 선택한 실행의 반환 항목과 품질 근거, **운영지표**에는 운영 지표, **입출력**에는 선택한 실행의 입력과 전체 출력을 표시한다. 처음에는 기능지표 탭을 열며, 탭을 바꿔도 선택한 실행과 시나리오 도식의 펼침 상태를 유지한다. 방향키와 Home·End로 탭을 이동할 수 있다.

품질 탭은 반환 항목의 원문·반환 경로·결과 ID와 연결된 작성 노드·호출 ID·호출 순번을 표시한다. 연결 확인과 품질 판정, 비적용·미판정·미완료 사유를 구분하며 화면에서 다시 채점하지 않는다. 검사와 평가 모델의 원본 기준은 묶음을 열 때 함께 복원한다. 전송 메시지·평가 원응답·판정 전체를 추가 요청 없이 확인하고 내려받을 수 있다. 기존 품질 파일이 없는 결과는 **최종 출력 품질 미제공**으로 표시하며 기능·운영 결과는 그대로 유지한다.

**입출력** 탭에는 입력과 전체 출력의 펼침 영역을 제공한다. 별도의 기대값 비교표와 안내 문구는 표시하지 않는다.

입력과 전체 출력 영역을 열면 내부 객체·배열은 모두 펼친 하나의 표로 표시한다. 변수명은 16px로 표시하고, 객체·배열의 항목 수는 변수명 옆에 붙인다. 하위 관계는 들여쓰기, 배열 순서는 `[0]`부터의 인덱스로 구분하며 전체 경로는 변수명에 제공한다. 중첩 상자와 별도의 객체 제목 줄을 만들지 않고 긴 문자열도 생략하지 않는다. 미제공·null·false·0·빈 문자열·빈 배열·빈 객체를 구분한다.

기능 지표에는 해당 실행의 저장된 판정·검증 완료 여부와 보고서 완성 범위를 표시한다. 실행별 통과율을 새로 계산하지 않는다. 개별 검사에는 굵은 검사 제목·판정과 세부 판정을 표시한다. 입력은 실행 당시 준비 자료, 출력은 실행 후 State이며 저장 원문을 바꾸지 않는다.

이상적인 시나리오는 [시나리오 데이터셋](../../scenarios/nodes/README.md)에서 가져오고, 그 아래 실제 실행 결과를 같은 노드 카드·화살표 양식으로 표시한다. 특정 노드의 선택 강조색은 사용하지 않는다. 이상적인 도식은 실행 출처·대상과 선택한 시나리오 본문 해시를 대조한다. 전체 색인이 바뀌어도 해당 본문이 일치하면 표시하며, 본문이 달라졌거나 연결이 불분명하면 미제공으로 표시한다. 보고서 전체의 이상적인 도식은 명시된 이전 역할 연결을 따라 선정 → 설명 → 인사이트를 표시한다.

실제 도식은 선택한 반복의 기록된 노드·호출 순서를 사용하며, 하위 에이전트의 노드와 도구 호출도 구분한다. 기록이 없으면 실제 실행 기록 미제공으로 표시하고 이상적인 경로로 채우지 않는다. 시나리오 연결이 없어도 실제 기록은 표시한다. 제목은 연결된 시나리오 제목, 실행 준비 자료에 보존된 제목(`purpose`), 사례 ID 순서로 사용한다. 사례 ID는 제목 표시와 별개로 검색할 수 있다.

전체 집계는 기능지표(검사별 통과율·필수 사례·보고서 완성률), 최종 출력 품질(품질 집계·반환 항목·작성 호출 근거), 운영지표(조건별 통계·목표·반복 측정)로 나눈다. 공통 평가 정보 머리글은 표시하지 않는다. 품질 탭에는 해당 품질 기록의 이름·일시·저장 위치를 표시한다. 탭 선택은 대상·채점 기록을 바꾸거나 사례 상세를 보고 돌아와도 유지한다. 새 자료·평가 묶음은 기능지표부터 표시하며 자동 조회에 품질 채점만 있으면 품질 탭부터 연다. 방향키와 Home·End로 탭을 이동할 수 있다.

**기능·운영 합격 여부, 검사별 통과율, 보고서 완성률과 품질 통과율은 각각 선택한 채점 기록 전체의 저장 집계**다. 검사별 건수는 숫자로 표시한다. 사례 검색·필터는 저장된 지표를 바꾸지 않는다. 품질 탭의 반환 항목은 선택한 대상·실행 범위로 표시한다.

운영지표는 에이전트 종류별 탭을 제공한다. **실행 상황 / 진입 방식 / 실행 환경 / 입력 규모 / 실제·모의 호출**을 묶음별 칩으로 표시하며, 선택한 칩에는 색상과 체크를 표시한다. 같은 묶음에서 여러 값을 선택하면 하나라도 일치하는 실행을 포함하고(OR), 서로 다른 묶음에서는 모두 일치하는 실행만 포함한다(AND). 아무 값도 선택하지 않은 묶음은 제한하지 않으며 모든 선택을 해제하면 해당 에이전트 전체 통계를 표시한다. 값이 없는 기록은 **미기록**으로 선택할 수 있다. 에이전트 탭은 사이드바 대상과 함께 바뀌며 에이전트·채점 기록·평가 묶음·자료를 바꾸면 조건 선택을 초기화한다. 다른 화면을 보고 돌아오면 선택을 유지한다.

조건 선택에는 `summary.operational.runs`의 개별 실행 측정값을 사용하므로 원본 추적·검사 파일을 추가로 요청하지 않는다. 종료한 실행 중 평가 증거 오류를 제외한 측정값으로 평균·중앙값·p95·최솟값·최댓값을 집계한다. 기존 조건 그룹의 통계값을 합치지 않으며, 사례별 반복 통계도 선택한 실행값으로 다시 계산한다. 표본·누락 개수와 미종료 사용량을 구분하고, 결과가 없으면 건수 0과 산출 불가·미기록을 표시한다. 계산 정의는 [실행 전체 채점](../../docs/runner.md#8-실행-전체-채점)을 따른다.

대상 지역·기간은 집계 분리와 조건 선택에 사용하지 않는다. 두 값은 개별 사례의 운영지표와 반복별 실행 정보에 남긴다. 사례 전체의 예정·누락 반복은 선택 범위의 실행 통계와 구분해 표시한다. **운영 목표 충족 여부**는 시험 당시 조건으로 저장한 판정이며, 선택한 에이전트의 목표를 표시하되 필터로 합격 판정을 새로 계산하지 않는다.

필수 사례 통과율의 분모는 통과·실패로 판정된 필수 사례다. 실패하면서 미완료 반복이 남은 사례도 포함할 수 있어 검증 완료 여부를 따로 표시한다. 미실행은 미판정 등과 겹치는 건수이며, 완료된 비적용 검사는 미실행 건수에서 제외한다. 비율 `null`은 **산출 불가**, 측정 누락은 **미기록**, 실제 0은 **0**으로 표시한다. 분모가 있어도 미분류 종료 결과 때문에 비율이 산출되지 않을 수 있다.

재진입 전 누적 사용량은 이번 진입의 통계에 포함하지 않는다. 미종료 관측 사용량은 종료 통계와 구분한다. 기능 통과, 보고서 완성, 운영 합격은 각각 별도 결과이며, 기준이 바뀌었다는 기록 자체를 실패로 바꾸지 않는다.

시나리오 데이터셋을 수정한 뒤에는 `python -m eval.viewers.execution.scenario_catalog`로 조회 자료를 갱신한다.

샘플을 갱신할 때는 통합 검증 명령에 `--write-samples`를 붙인다. 모의 모델·합성 자료를 사용하며 외부 모델·운영 DB는 호출하지 않는다. 평가 대상 5사례를 각 2회 실행해 request·interpretation 에이전트와 보고서 전체의 세 묶음으로 저장한다. 묶음별로 두 번 채점하며, 3회 계획의 누락 반복과 기준을 바꾼 재평가를 함께 확인한다.

설계 대조는 사례 입력 → 실제 실행기의 원본 결과 → 별도 채점 파일 → 브라우저 메모리 → 화면 표시 경로를 대상으로 한다. 채점기의 조건 그룹에서 지역·기간을 제외하고, 뷰어는 저장된 개별 측정값으로 선택 범위를 집계한다. 실행·기능 채점의 판단과 업무 State의 필드·보관·전달 경로는 유지한다.

시나리오 도식은 선택 본문 대조, 색인만 바뀐 기존 기록, 상하위 호출 순서, 반복 스냅샷 중복 제거, 누락·충돌 기록과 원본 불변성을 검증한다. 실제 저장된 첫 사례에서 이상적인 14단계와 기록된 18개 실행 노드를 확인했다. 1,440×900·390×844 브라우저 화면에서 두 도식과 내부 가로 스크롤, 기능 지표 순서, 간소화한 탭·채점 선택을 확인했으며 페이지 가로 넘침과 콘솔 오류는 없었다.

자동 검증은 기존 탐색·원본 보존과 함께 에이전트별 탭, 조건의 OR·AND, 원시 측정값의 통계, 지역·기간 합산, 측정 없는 대상, 조건 초기화·유지, 추가 HTTP 요청 없는 필터 전환을 확인한다. Python 집계·JS 파일 연결 검사에서는 새 조건 그룹과 기존 지역·기간 포함 그룹을 함께 확인했다. Edge의 1,638px·390px 화면에서 칩 선택과 배치를 확인했으며 페이지 가로 넘침과 콘솔 오류는 없었다. 문서 참조 검사도 통과했다. 실제 모델·운영 DB 호출과 브라우저 파일·폴더 선택 대화상자의 실제 조작은 이번 검증에 포함하지 않았다.

최종 출력 품질 연결은 실행·품질 기록의 동시 열기, 품질 기록만 있는 실행 연결, 각각의 재채점 선택, 묶음 전체를 읽은 뒤 추가 요청 없이 전환하는 HTTP 흐름으로 검증했다. 같은 노드에서 나온 서로 다른 작성 호출의 ID·순번과 평가 원응답을 복원하며, 채점 파일에서 식별자가 바뀌면 연결을 거부한다. 모의 모델로 실제 채점기가 저장한 보고서 5개 반환 항목도 원본 실행과 연결했다. 공통 파일 읽기를 사용하는 도구·노드·실행 뷰어의 JS 회귀와 조회 목록의 품질 형식 보존 검사를 통과했다. 새 품질 탭의 실제 브라우저 배치와 실제 평가 모델의 판단 품질은 이번 추가 검증에 포함하지 않았다.
