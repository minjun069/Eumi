# 노드 평가 결과 뷰어

수정일: 2026-11-15.

[도구 평가 뷰어](../results/README.md)의 화면·탐색 구조를 복제한 독립 뷰어다. `score-nodes`가 저장하는 `node-evaluation-v1` 파일에서 노드·역할별 지표, 반복별 판정, 모델 호출별 세부 근거를 확인한다. 저장된 검사 판정과 모델 호출 측정으로 개별 실행·같은 사례의 반복 집계를 표시한다. 실행·채점을 수행하지 않으며, 원본 파일과 업무 실행 상태(`State`)를 변경하지 않는다.

## 사용 방법

`Eumi/ai`에서 다음 명령을 실행하고 [노드 평가 뷰어](http://127.0.0.1:8872/eval/viewers/nodes/)에 접속한다.

```powershell
python -m http.server 8872 --bind 127.0.0.1
```

HTTP 주소로 열면 `eval/outputs/evaluation-viewer/catalog.json`에서 파일 경로·크기와 묶음 목록을 읽는다. 선택 목록에는 실행 단위 목록(`units`)에 `node`가 포함된 묶음만 표시한다. 선택한 묶음의 모든 사례·반복 실행, 선택한 채점의 모든 검사·기준, 관련 시나리오를 자동으로 읽는다. 개별 자료의 읽기 버튼 없이 사례를 선택해 판정·프롬프트·입출력을 확인한다. 원문을 하나의 조회 파일로 합치지 않는다. 기본 결과 폴더의 실행·채점 저장 후 목록이 갱신되며, 화면을 새로 고치면 다시 읽는다. 직접 갱신할 때는 `python -m eval.viewers.catalog`를 실행한다.

`index.html`을 파일로 직접 열면 로컬 HTTP 서버 실행 명령과 접속 주소를 안내한다. 화면에서는 HTTP로 저장된 결과를 조회하며, 로딩 중·자료 없음·오류 상태를 안내한다.

| 조회 자료 | 표시 범위 |
| --- | --- |
| `batch.json` | 노드 실행을 포함하는 묶음의 사례·반복 목록 |
| `node-evaluation-v1` JSON | 채점 파일에 저장한 지표·검사 근거·기준·반복별 계획 |
| 실행의 `report.json`·`case.json` | 모델 입력·응답과 연결 가능한 운영 실측값. 채점 파일이 없으면 기능 판정·통과율은 미제공 |

HTTP 조회는 다음 자료를 자동으로 준비한다.

| 선택 | 자동으로 읽는 자료 |
| --- | --- |
| 실행 묶음 | `batch.json`·`suite.json`, 모든 등록 실행의 `report.json`·`case.json`, 모델 입력·운영 측정을 담은 최종 추적 본문 |
| 채점 JSON | 선택한 채점의 집계·검사·기준·반복·노드·호출별 판정과 평가 프롬프트 |
| 소속 시나리오 | 데이터셋 색인과 선택한 묶음의 사례에 연결된 모든 시나리오 |
| 사례·반복·탭 | 이미 읽은 자료를 사용하며 추가 파일 요청 없음 |

다른 묶음이나 채점을 선택하면 그 자료도 자동으로 준비한다. 한 번에 두 작업을 진행하며, 실행 하나는 결과·사례 파일을 함께 읽는다. HTTP 파일당 크기 제한은 64 MiB다. 다른 묶음으로 전환하면 이전 요청을 취소하고 읽은 자료를 해제한다. 선택한 채점 외의 과거 채점은 선택할 때 읽는다. 시간순 전체 추적과 평가 모델 전체 추적은 결과 폴더에 보관한다.

읽는 동안에는 진행 상태를 표시하고 완료 안내 배너는 남기지 않는다. 파일 부재·통신 실패·JSON 오류·파일 연결 불일치는 파일 확인 사항에 표시한다. 일부 파일이 실패해도 정상 자료는 계속 표시한다. 실패한 검사의 개별·반복 결과를 0으로 계산하지 않으며, 모델 호출 범위가 불완전한 사례의 개별·반복 운영 지표는 미제공으로 표시한다. 저장된 판정·측정 원본은 유지하고, 전체 집계 화면의 사례 요약과 전체 운영 통계는 아래 기준으로 계산한다. 실패한 자료는 새로고침하거나 해당 묶음·채점을 다시 선택하면 다시 읽는다.

묶음 선택에는 `작업 목적 파악 (2026.11.13 - 01)`처럼 노드 이름·실행일·저장된 실행 번호를 표시한다. 노드는 조회 목록의 `node_targets` 또는 읽은 묶음의 실제 실행 대상에서 가져오며, 폴더 이름으로 추정하지 않는다. 여러 노드가 있으면 이름을 함께 표시하고, 이전 목록에 대상 정보가 없으면 해당 묶음을 읽을 때 이름을 갱신한다.

채점 선택에는 `채점 01`처럼 저장된 채점 번호를 표시한다. 채점 기록은 목록에 기록된 시각순으로 나열하고 처음에는 최신 기록을 읽는다. 채점 ID와 한국시간 채점 일시·상태는 채점 정보 탭에서 확인한다. 저장 이름과 번호는 [실행기 저장 규칙](../../docs/runner.md#4-저장-결과)을 따르며, 파일명·저장 위치·이전 UUID 기록의 대체 번호는 [공통 표시 안내](../results/README.md#1-사용-방법)와 같다. 기록을 바꾸면 지표와 개별 판정이 함께 바뀐다. 도구 및 실행 전체의 채점 형식은 이 뷰어에 연결하지 않는다. 파일 경로·실행 식별자·사례·역할·반복이 맞지 않는 연결은 오류로 표시한다.

## 결과 확인

왼쪽 탐색의 첫 버튼에는 `N02 작업 선택 및 실행`처럼 묶음에 포함된 노드 번호와 이름을 표시하며, 누르면 기존과 같이 모든 대상을 함께 보여 준다. 나머지 대상 버튼과 선택한 대상의 본문 제목에는 역할 이름만 표시한다. 역할 버튼 글자는 노드 이름보다 가늘게 표시한다. 탐색 버튼은 별도 접기 제목 없이 바로 표시한다. 역할을 선택하고 **사례별 결과** 또는 **전체 집계·통계**를 연다. 사례 목록은 탐색 아래 사이드바에 한 열로 표시하며, 시나리오 기반 이름과 전체 사례 설명으로 탐색한다. 검색은 표시 이름과 원래 사례 ID·설명·태그·검사 항목을 함께 사용한다. 검색·필터·페이지·반복 선택을 제공하며, 전체 집계 화면에서도 사례를 선택해 상세로 이동한다. 모바일에서는 처음에 사례 목록을 접고 개수와 선택된 사례를 표시한다. 사례를 고르면 상세로 이동하며, 목록으로 돌아오면 검색·필터·선택을 유지한다. 목록 필터는 저장된 지표의 분모를 바꾸지 않는다.

사례 목록과 시나리오 영역 제목은 `Scenario 사용자 요청 처리 · 이전 대화 없음 - 6th`처럼 같은 이름을 표시한다. 순번은 검증된 시나리오 단계 배열의 실제 위치다. 같은 사례를 여러 단계·시나리오에서 사용하면 해당 위치를 모두 표시하며, 연결 자료가 없거나 모호하면 `사례 <ID>`를 유지한다. 사례 상세 본문은 이 제목에서 시작하며, 바로 아래의 **시나리오 도식**을 펼쳐 소속 시나리오를 확인한다. 모바일의 목록 복귀 버튼은 제목 위에 표시한다.

로컬 Pretendard 글꼴을 사용하며 주요 목록·검색·탭·수치는 16px, 설명·라벨은 14px 이상으로 표시한다. 긴 출력은 줄바꿈과 1.65 행간으로 읽고, 비교표·도식은 필요한 영역 안에서 가로로 탐색한다. 데스크톱 사이드바의 기본 너비는 256px이며 화면 폭이 1200px 이하면 240px이다. 본문과의 경계를 드래그하거나, 경계에 초점을 두고 좌우 방향키로 16px씩 조절한다. 최소 너비는 220px, 최대는 480px와 화면 폭의 45% 중 작은 값이며 Home·End로 양 끝에 맞춘다. 화면 폭이 760px 이하면 너비 조절을 숨기고 사이드바를 본문 위에 배치하며, 대상 버튼은 한 줄 안에서 가로로 탐색한다. 일반 버튼·입력·펼침 영역은 최소 44px 높이를 사용하고, 분할 영역의 키보드 초점 테두리는 안쪽에 표시한다.

개별 사례는 **소속 시나리오 → 반복 실행 선택 → 평가 결과와 입출력** 순서로 표시한다. 시나리오를 펼치면 단계 순서와 역할을 보여 주고 현재 사례의 모든 위치를 강조한다. 반복 실행 선택 아래의 구분선으로 평가 결과와 입출력 영역을 나눈다.

반복 실행을 선택하면 왼쪽 평가 결과와 오른쪽 입출력이 함께 바뀐다. 왼쪽에는 기능 지표·운영 지표 탭을 두고 오른쪽 입출력은 항상 표시한다. 탭을 바꿔도 선택한 반복과 시나리오 도식의 펼침 상태는 유지한다. 분할은 탭 행에서 시작하며 처음에는 두 영역을 같은 너비로 표시한다. 가운데 구분선을 끌어 왼쪽 너비를 25~75%로 조절할 수 있다. 화면 너비가 760px 이하면 평가 결과와 입출력을 위아래로 배치한다.

두 영역에는 각각 세로 스크롤바가 있어 독립적으로 탐색한다. 좌우 분할 높이는 화면 높이의 80%(최대 960px)이며, 위아래로 배치되는 화면에서는 각 영역이 화면 높이의 75%(최대 720px)를 사용한다. 키보드로 각 영역에 초점을 옮겨 스크롤할 수도 있다.

| 영역 | 표시 내용 |
| --- | --- |
| 왼쪽 기능 지표 | 기능 판정·완료 현황과 **검사 항목마다** 개별 실행 결과·사례 반복 집계 결과·노드·역할 전체 결과를 세 칸에 나란히 표시. 형식 준수 검사만 세부 항목 비교를 제공 |
| 왼쪽 운영 지표 | 응답시간·실패·토큰·모델 호출·기술적 재시도의 개별 실측값, 사례 반복 집계, 노드·역할 전체 집계를 한 표에서 비교 |
| 오른쪽 입출력 | 각각 접고 펼치는 입력과 영역 전체 폭의 출력. 실제 모델 입력이 없으면 데이터셋의 준비 입력임을 구분 |

| 비교 범위 | 기능 결과 | 운영 결과 |
| --- | --- | --- |
| 개별 실행 결과 | 해당 검사의 판정·사유. 같은 실행에 해당 노드 기록이 여러 개면 각각 보존 | 해당 모델 호출의 응답시간·입출력 토큰·모델 호출·기술적 재시도 |
| 사례 반복 집계 결과 | 같은 사례의 모든 반복을 합친 검사 통과율과 판정별 건수 | 같은 사례의 실패율, 정상·오류 응답시간과 사용량의 평균·중앙값·p95 |
| 노드·역할 전체 결과 | 해당 노드·역할의 모든 사례를 포함하는 저장된 검사 통과율과 건수 | 해당 노드·역할 전체의 저장된 운영 집계 |

운영 비교표에서는 세 열을 **개별 결과 · 반복 결과 · 전체 결과**로 짧게 표시한다. 선택한 채점의 사례 계획과 기록이 모두 1회이고 실행 목록도 1건이면 반복 결과에는 **반복 해당 없음**을 표시한다. 여러 회가 예정됐지만 1회만 기록됐거나 계획을 확인할 수 없으면 반복 통계와 누락 상태를 유지한다. 정상·오류 응답시간, 토큰·호출·재시도 통계의 개별 표는 표본 수를 첫 행에 둔다.

세 범위는 별도 화면으로 전환하지 않고 함께 표시한다. 같은 검사 ID라도 평가 축·방식이 다르면 구분하고, 다른 노드·역할의 집계는 섞지 않는다. [형식 준수 검사 `N-F.1`](../../docs/nodes/common.json)는 세부 항목의 실행 결과와 두 집계의 통과율도 펼쳐 비교한다. 좁은 화면에서는 비교 영역 안에서 가로로 탐색한다. 기능 판정과 완료 현황은 검사 항목보다 먼저 표시한다. 각 범위 제목 오른쪽에 판정을 두고, 세 표는 같은 높이에서 시작한다. 통과·실패·미판정·비적용·미실행 건수, 기록·예정 반복 수, 누락·미완료·제외 반복 번호는 각각 이름과 값이 구분된 표로 표시한다. 요약 표의 항목명은 숫자에 필요한 너비를 제외한 공간을 사용한다.

검사 카드는 처음에 접혀 있으며 검사명 오른쪽에 선택한 실행의 저장된 판정과 평가 축·방식을, 그 아래에는 검사 내용을 표시한다. 같은 실행에 노드 기록이 여러 개면 각 저장 판정을 구분하고 새 종합 판정을 만들지 않는다. 펼치면 세 범위의 결과를 확인하며, 기능·운영 탭을 바꿔도 해당 검사의 펼침 상태를 유지한다. LLM 기반 검사는 세 범위 결과 아래의 **평가 프롬프트**를 펼쳐 선택한 실행의 시스템·사용자 메시지 원문을 확인한다. 규칙 기반 검사에는 평가 프롬프트 영역을 표시하지 않는다. 같은 노드가 여러 번 나오거나 호출이 여러 개면 각각 구분하며, 반복·채점 기록 선택에 따라 내용도 바뀐다. 준비된 프롬프트만 저장되고 평가 모델이 실행되지 않았으면 미실행 여부와 사유를 함께 표시한다. LLM 기반 검사에 프롬프트가 제공되지 않았으면 해당 상태를 안내한다.

사례 반복 집계는 목록 검색·필터와 관계없이 선택한 채점 기록의 반복 전체를 사용하며, 누락된 예정 실행도 포함한다. 개별 판정과 사례 판정은 파일의 저장값을 표시하고, 반복 통과율과 통계만 저장된 판정·측정으로 계산한다. 새로운 합격 판정을 만들지 않는다. 분모 0의 비율은 **산출 불가**, 집계 행이 없으면 **미제공**, 누락 측정은 **미기록**, 실제 측정 0은 **0**으로 표시한다.

지표·통계의 소수는 최대 세 자리까지 반올림해 표시하고 불필요한 끝자리 0은 붙이지 않는다. 시간·통과율·실패율·평균·중앙값·p95와 운영 목표의 측정값·기준에 같은 표시 규칙을 적용한다. 계산에는 원래 정밀도를 사용하며, 실제 입출력·평가 프롬프트·원본 JSON·내려받기에는 원래 숫자를 유지한다.

입출력 영역은 선택한 실행의 입력과 전체 모델 출력을 표시한다. 출력은 처음에 펼쳐 표시하며, 입력과 출력은 각각 접을 수 있다. 출력이 없으면 **미제공**으로 표시한다. 기대 결과와 검사 원본 경로는 개별 사례 화면에 표시하지 않으며, 기대 기준과 원본 파일은 결과 폴더에 보관한다.

실제 모델 입력 메시지는 평가 프롬프트와 같은 본문 형식으로 표시한다. 시스템·사용자 등 메시지 역할을 펼침 제목으로 두고, 들여쓰기와 간격으로 메시지를 구분한다. 각 메시지는 처음에 펼쳐 표시하며 개별적으로 접을 수 있다. 본문의 줄바꿈과 공백을 보존하고, 호출이 여러 개면 호출별로 구분한다. 기능·운영 탭을 바꿔도 출력과 각 메시지의 펼침 상태를 유지한다. 메시지 부가 정보는 화면에 표시하지 않는다. 실제 메시지가 없고 준비 입력만 있으면 이를 구분해 항목·값 표로 표시한다.

출력은 에이전트 평가 뷰어와 같은 항목·값 표를 사용한다. 객체·배열의 모든 하위 항목은 펼쳐서 표시하고, 들여쓰기·배열 인덱스와 항목 수로 구조를 구분한다. 변수명은 16px이며 긴 문자열을 생략하지 않는다. JSON으로 읽을 수 있는 모델 응답은 구조화해서 표시하고, 형식이 맞지 않는 응답은 문자열 그대로 표시한다. 값 안의 객체·배열 JSON 문자열에는 표시용 줄바꿈과 들여쓰기를 적용하며 숫자·키 순서·이스케이프 등 원본 토큰은 유지한다.

소속 시나리오는 [노드 데이터셋 색인](../../scenarios/nodes/scenarios.json)과 선택한 묶음의 사례에 연결된 시나리오 원문을 처음에 자동으로 읽는다. 조회 목록에는 색인 경로만 둔다. 결과 파일의 사례·노드·역할과 일치하는 위치만 연결하며, 자료가 없거나 연결이 모호하면 시나리오를 추정하지 않는다. 도식은 현재 불러온 데이터셋의 단계 순서다.

**전체 집계·통계**는 다음 세 탭으로 나눈다. 처음에는 기능 지표를 보여 주며, 대상·채점 기록이나 사례 화면을 전환해도 선택한 집계 탭을 유지한다. 기능·운영 지표 안에는 **전체**를 첫 탭으로 두고 역할별 탭을 나열한다. 전체는 현재 사이드바에서 선택한 대상의 모든 역할을 합친다. 처음에는 전체를 표시하고, 기능·운영 지표 사이에서 역할 선택을 공유한다. 선택한 역할이 새 조회 범위에 없으면 전체로 돌아간다. 역할 탭을 바꿔도 사이드바 선택이나 사례 목록 범위는 바뀌지 않는다. 두 단계의 탭은 방향키와 Home·End로 전환할 수 있으며, 역할이 하나여도 전체 탭을 제공한다.

| 탭 | 내용 |
| --- | --- |
| 기능 지표 | 전체 사례 기준 종합 판정·통과율·검증 진행, 항목별 검사결과·세부 항목 통과율·사례 상세 |
| 운영 지표 | 운영 종합 판정·기술적 실행 실패율·측정 확인 사항, 목표별 결과표와 응답시간·토큰·호출·재시도 통계 |
| 채점 정보 | 채점 ID·일시·상태 |

탭 안에는 같은 이름의 제목을 반복하지 않는다. 채점 정보에는 기준 펼침 영역·묶음 기록·원본 파일 링크를 표시하지 않는다. 기준·실행 추적·조건·평가 모델 기록은 결과 폴더의 원본을 유지한다.

기능 요약은 필수·선택·필수 여부 미지정 사례를 모두 포함한다. 저장된 사례별 판정과 완료 상태로 아래 값을 계산하며, 원본 채점의 필수 사례 집계는 수정하지 않는다.

| 요약 | 계산·표시 기준 |
| --- | --- |
| 종합 판정 | 실패 사례가 하나라도 있으면 실패. 모든 사례가 검증 완료·통과하면 통과. 그 외와 사례가 없으면 미판정 |
| 전체 사례 통과율 | 통과 사례 ÷ 미판정을 포함한 전체 사례. 통과·실패·미판정 건수를 함께 표시하고 분모가 0이면 산출 불가 |
| 검증 진행 | 검증 완료 N / 전체 N. 사례가 없어도 표시하며 누락 반복은 1회 이상일 때만 추가 |

판정과 검증 완료는 구분한다. 실패가 확인됐어도 필요한 검사나 예정 반복이 남아 있으면 검증 미완료다. 전체 탭은 노드·역할·사례 조합마다 한 번 집계하며, 서로 다른 역할에서 평가한 같은 사례는 각 평가 대상으로 센다. 검사 항목별·세부 항목별 통과율은 기존의 통과 ÷ (통과+실패)를 유지한다. 검사 표는 검사 ID·이름, 평가 축·방식, 검사 내용 순서로 표시한다. 집계의 검사 표와 사례의 검사 카드는 **형식 준수 → 필수 내용 충족 → 내용 정확성** 순서로 표시하고, 분류명에는 각각 빨강·초록·노랑 표시를 사용한다. 같은 분류 안에서는 저장된 표시 순서를 유지하며 원본 검사 순서·판정을 바꾸지 않는다. 사례별 판정·반복 충족·미완료 사유는 표 아래의 접힌 상세에서 확인한다.

운영 요약은 운영 종합 판정, 기술적 실행 실패율, 측정 확인 사항의 세 카드로 표시한다. 실패율은 비율과 **실패 N / 측정 N건**을 함께 표시한다. 실패 여부 미확인·미종료 건수는 있을 때만 표시하며 확인 사항이 없으면 해당 카드 본문은 비워 둔다. 목표별 측정값·기준·판정은 **운영 목표 충족 여부** 표에서 확인하며, 목표 이름을 펼치면 측정 완료·표본 수·대상 사례·사유를 보여 준다.

역할별 운영 통계와 목표 결과는 저장값을 사용한다. 전체 탭은 저장된 실패·측정 건수를 합치고, 응답시간·사용량의 평균·중앙값·p95는 개별 실행의 원시 측정값을 모아 계산한다. 역할별 평균이나 분위수를 다시 평균내지 않는다. 원본이 일부 없으면 확인한 측정만 집계하고 확인되지 않은 값은 누락 건수와 측정 확인 사항에 표시한다. 전체 운영 판정은 어느 역할이든 실패면 실패, 모든 역할이 완료·통과면 통과, 나머지는 미판정이다. 운영 목표는 역할별 기준과 판정을 유지하여 한 표에 나열한다.

작업 선택만 실행한 판정은 `counted: false`에 따라 **노드 지표 집계 제외**로 표시한다. 에이전트·보고서 실행에서 추출한 노드는 노드·역할별로 탐색하며, 실행 전체 판정과 선택한 노드 판정을 구분한다.

운영 통계의 측정 범위는 `selected_model_calls`다. 채점 대상으로 선택한 모델 호출을 부모 노드별로 집계한 값이며 부모 노드 전체의 후처리·도구 실행·상태 반영 오류, 평가용 모델 호출은 포함하지 않는다. 측정·판정 계약은 [평가 실행 안내](../../README.md#운영-지표와-목표), 검사·합격 기준은 [노드 평가](../../docs/nodes/README.md)를 따른다.

검증 자료를 만들 때 실제 업무 모델·평가 모델·운영 DB를 호출하지 않는다. 실행·채점의 판단과 State 계약을 유지하며, 실행기가 저장한 입력 → 실행 결과·별도 채점 → 선택한 원본 파일의 브라우저 조회 → 화면 표시 경로를 대조한다.

실제 실행기·채점기로 생성한 모의 실행 4사례·8회와 채점 2건을 테스트 환경에 직접 주입해 사례 반복 지표·저장 집계·프롬프트 원문·미실행 상태·반복·재채점·역할 구분·원본 보존을 검사한다. HTTP 조회 검사는 실제 공통 읽기 모듈을 사용해 선택한 묶음·채점·관련 시나리오를 처음에 모두 요청하고, 사례·반복·탭 전환에는 추가 요청이 없는지 확인한다. 모델 입력·출력·기준·프롬프트가 원문대로 표시되는지도 검사한다. 노드 실행을 포함한 묶음 선별, 오류 구분과 부분 실패 격리, 묶음·재채점 전환 및 늦은 응답 취소, 시나리오 자동 조회, 사례 한 열 목록, 메시지 본문형 입력, 입출력 분리, 너비 조절과 선택 유지도 회귀 검사에 포함한다.
