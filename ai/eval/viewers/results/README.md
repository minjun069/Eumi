# 평가 결과 뷰어

수정일: 2026-11-13. 상태: 로컬 결과 자동 불러오기와 실행 기록·도구 검사 판정·기능 지표·운영 지표·재평가 조회 지원.

도구·노드·작업 선택·에이전트·보고서 생성 흐름의 실행 기록을 대상별로 찾아보는 화면이다. 여러 사례를 목록에서 비교하고, 사례를 선택하면 입력·기대 결과·실제 결과와 호출 근거를 확인할 수 있다. 같은 사례를 반복 실행한 기록도 각각 조회한다.

[평가 실행기의 저장 결과](../../docs/runner.md#4-저장-결과)와 `tool-evaluation-v1` 채점 파일을 읽는다. 도구별 기능·운영 지표와 합격 판정은 실행기가 저장한 값을 표시하고, 검사별 건수는 저장된 비교 항목의 판정을 모아 표시한다. 뷰어는 실행·채점·시간 통계 계산을 수행하지 않으며 원본 실행 기록을 바꾸지 않는다.

## 1. 사용 방법

`Eumi/ai`에서 다음 명령으로 로컬 HTTP 서버를 시작한 뒤 [평가 결과 뷰어](http://127.0.0.1:8872/eval/viewers/results/)를 연다.

```powershell
python -m http.server 8872 --bind 127.0.0.1
```

화면은 `eval/outputs/evaluation-viewer/catalog.json`의 작은 목록을 읽고, 선택한 실행 묶음의 `batch.json`만 요청한다. 목록에는 `eval/outputs/evaluations/`와 `eval/outputs/database-evaluations/`의 원본 경로·크기·식별 정보가 들어 있으며 실행·채점 본문은 포함하지 않는다. [조회 자료 생성기](../catalog.py)는 실행·채점 저장 후 목록을 갱신한다. 수동으로 복사한 결과는 다음 명령으로 갱신한다. 모델·DB를 호출하지 않는다.

```powershell
python -m eval.viewers.catalog
```

1. **평가 묶음**과 **평가 대상**을 선택한다. 도구 실행이 있는 묶음을 먼저 표시한다.
2. 채점 형식이 확인된 최근 기록의 JSON을 읽어 **전체 집계·통계**와 기준·검사 본문을 표시한다.
3. 사례를 선택하면 해당 반복의 입력·실제 결과를 읽고 채점 파일에 기록된 검사 판정과 함께 확인한다.
4. **사례별 결과**에서 사례·반복을 선택하면 그 실행의 `case.json`·`report.json`만 읽는다. **실행 근거**의 추적 파일과 **실행 조건**의 원문은 각각 읽기 버튼으로 요청한다.
5. **채점 기록**에서 재평가 기록을 전환한다. 형식이 알려지지 않은 기존 단일 JSON은 파일명·크기를 표시하고 **이 채점 원문 읽기**를 눌러야 읽는다.

**미로딩**은 아직 원본을 요청하지 않은 화면 상태다. 저장된 미판정·실패 또는 파일 누락과 구분한다. 요청 오류가 나도 저장된 판정·집계는 바꾸지 않는다. 다른 채점 형식의 결과는 해당 뷰어에서 열고, 형식이 알려지지 않은 기존 단일 파일은 명시 선택 후 확인한다.

평가 이름은 `도구평가 · 2026-11-12 실행01 · 채점02`처럼 표시한다. 저장 이름·번호는 [실행기 저장 규칙](../../docs/runner.md#4-저장-결과)을 따른다. 결과 파일·저장 위치를 함께 표시하며 이전 UUID 기록의 표시 이름은 원본을 바꾸지 않고 구성한다. 같은 이름의 기록은 상위 경로와 실행 식별자로 구분한다.

기준 원문은 선택한 채점 JSON과 함께 읽는다. 실행 조건, 추적 원문과 전체 평가 모델 추적은 읽기 버튼을 누를 때 요청한다. `report.json`에 포함된 추적은 실행 파일의 일부로 읽는다. 시간순 추적은 읽기 버튼을 누르면 전체 `trace.jsonl`을 읽는다. 전체 평가 모델 추적도 자동 요청하지 않는다. 한 파일의 읽기 상한은 64 MB이며 초과하면 오류와 직접 다운로드 경로를 표시한다. 읽은 파일 캐시는 최대 24개·16 MB로 제한하고 이전에 선택한 실행·검사 원문을 계속 누적하지 않는다.

다른 위치의 결과는 **결과 폴더 열기** 또는 **파일 선택**으로 열 수 있다. 수동 선택은 선택한 파일 전체를 읽으며 합계 64 MB를 넘으면 읽기 전에 안내한다. 큰 누적 결과는 HTTP 목록에서 필요한 항목만 선택한다. `file://`에서는 자동 조회를 사용할 수 없으며 수동 열기·화면 샘플만 사용할 수 있다. 샘플 자료도 버튼을 누를 때 읽는다.

### 열 수 있는 자료

| 선택한 자료 | 확인할 수 있는 범위 |
| --- | --- |
| `batch.json`이 있는 결과 폴더 | 등록 실행과 각 실행의 사례·결과·실행 조건·호출 기록. `assessments/`에 있는 도구 채점 파일도 함께 연결 |
| 여러 결과 폴더를 포함한 상위 폴더 | 각 묶음을 상단 선택기로 전환하여 조회 |
| 개별 `tool-evaluation-v1` JSON | 도구 지표·검사 판정·기준·근거. 실행 파일을 함께 열지 않으면 실행 입출력으로 이동할 수 없음 |
| 개별 `report.json` | 해당 실행의 결과와 파일 안에 저장된 근거. 함께 열지 않은 자료는 미제공으로 표시 |
| 여러 JSON·JSONL 파일 | 선택한 파일 사이에서 연결할 수 있는 실행 기록 |
| **화면 샘플** 버튼 | 탐색을 확인하기 위한 가상 자료. 화면에 샘플임을 표시하며 실제 평가 결과와 구분 |

여러 실행을 함께 볼 때는 폴더 선택을 사용한다. 일반 파일 선택은 폴더 경로를 보존하지 않아 이름이 같은 파일을 구분하지 못할 수 있다.

새 자료를 열면 현재 자료를 교체한다. 지원하는 결과를 하나도 읽지 못하면 오류를 알리고 기존 화면을 유지한다. 일부 파일만 잘못된 경우에는 읽을 수 있는 나머지 기록을 표시한다.

읽은 결과는 브라우저 메모리에 보관하며 서버로 전송하거나 수정하지 않는다. 새로고침하면 자동 조회 자료를 다시 읽는다. 수동으로 선택한 외부 자료를 다시 보려면 파일을 재선택한다. 자동 조회 목록에는 원본 내용이 없으며 선택한 파일만 읽는다.

## 2. 결과 확인

대상 목록은 실행 단위·역할·하위 호출 방식을 구분한다. 도구 대상에는 [도구 평가 명세](../../docs/tools.md#1-평가-대상)의 T01·T02·T03과 정식 명칭을 함께 표시한다. 사례 목록은 25개씩 표시하며, 사례 ID·설명·태그와 검사 ID·분류·항목명으로 검색하고 실행 상태·태그·필수 여부로 필터링한다. HTTP 조회에서 아직 읽지 않은 설명·태그·기대값은 검색 자료에 포함하지 않으며 목록의 식별자·실행 상태로 먼저 선택한다.

사례 ID를 제목으로, `purpose` 원문을 **사례 설명**으로 표시한다. **검사·판정**에서는 적용 검사의 분류·ID·정식 항목명을 표로 구분한다. 채점 파일이 있으면 선택한 기록의 검사별 수행 여부·판정·사유와 기대값·실제값·비교 방식·허용 오차·근거 경로를 확인한다. 도구의 입력·출력 검사명은 [기능 평가 명세](../../docs/tools.md#2-기능-평가)를 따르며, 표시 이름이 등록되지 않은 검사도 ID를 보존하고 분류·항목명을 미등록으로 표시한다. 사례 태그는 검사 분류와 별도로 표시한다.

실행 당시 적용 검사 목록은 실행 결과의 `assessment.checks`를 사용한다. 채점 기록의 검사·기준은 이 목록과 별도로 표시한다. 결과 파일이 없으면 연결된 사례의 검사 목록을 표시한다. 표시 이름을 붙여도 원본 사례·실행 결과·State는 바꾸지 않으며 검사별 판정을 생성하지 않는다.

넓은 화면은 사례 목록과 상세를 나란히 표시한다. **목록 넓게**를 누르면 관측 시간과 평가 판정 열까지 펼쳐 비교할 수 있다. 폭 1,200px 이하에서는 사례를 선택하면 상세로 전환되며, **목록으로** 돌아와도 검색·필터·페이지와 반복 선택을 유지한다. 필터는 기본으로 접혀 있으며 적용 중인 필터 수는 접힌 상태에서도 확인할 수 있다. 폭 760px 이하에서는 평가 대상도 접어 표시한다.

본문은 16px, 보조 설명은 14px이며 로컬 Pretendard 글꼴을 사용한다. 대상 메뉴, 사례 목록, 상세 영역을 배경과 테두리로 구분한다. 관측 시간과 평가 판정은 목록의 표시 폭에 관계없이 사례 상세와 전체 집계에서 확인할 수 있다.

| 화면 | 확인하는 내용 |
| --- | --- |
| 사례 목록 | 사례 ID·설명, 적용 검사 ID, 사례 태그, 반복 순번, 실행 상태. 펼친 목록에는 저장된 소요 시간과 선택한 채점 기록의 반복별 판정도 표시 |
| 검사·판정 | 검사 분류·ID·항목명, 선택한 채점 기록의 개별 판정·사유·대조 근거. 실행 당시 검사 목록과 원본 미판정 상태는 별도 보존 |
| 입력·결과 | 직접 입력, 기대 결과, 독립 기준 자료, 허용 범위, 실제 반환값, 업무 상태와 오류 |
| 반복·재평가 | 같은 사례의 반복별 상태·시간과 동일 실행의 채점 기록별 판정·사유. 채점 기록을 바꾸면 지표와 개별 판정이 함께 전환 |
| 실행 근거 | 호출별 입력·출력·오류와 기록 수집 범위, 모의 응답 사용 내역, 시간순으로 누적된 호출 기록 |
| 실행 조건 | 실행 시각과 식별자, 사례 자료의 출처, 코드·설정·입력의 기록, 파일 연결 상태 |
| 전체 집계·통계 | 도구별 검사 건수와 근거, 필수 사례 통과율·기능 합격 여부, 정상·오류 호출 시간 통계·운영 목표 충족 여부. 기록 현황과 실행 관측값도 별도 표시 |

전체 집계의 **기록 현황**은 불러온 기록 수이며 평가 지표와 구분한다. 목록의 검색·필터는 전체 집계의 대상 범위를 바꾸지 않는다. 실행별 행을 선택하면 해당 사례와 반복 실행의 입출력으로 이동한다. 실행 묶음만 있을 때 아직 등록되지 않은 예정 실행은 개수만 표시한다. 채점 파일에 계획된 사례·반복의 미판정이 있으면 해당 판정과 사유를 표시하며 실행 기록을 만들어 채우지 않는다.

### 실행 범위

실행 상태 객체(`State`)는 요청·작업 이력·응답·실행 정보를 보관하는 자료다. 화면은 [실행 단위별 반환 형식](../../docs/runner.md#42-사례별-결과)에 따라 결과를 표시한다.

| 실행 단위 | 결과를 읽는 방법 |
| --- | --- |
| 도구 | 자체 입력과 직접 반환값을 확인한다. 실행 상태 객체가 저장된 경우에는 함께 표시한다. |
| 노드 | 지정한 노드 1개를 실행한 뒤의 상태 객체와 반환된 다음 경로를 확인한다. 다음 경로의 반환은 그 경로까지 실행했다는 뜻이 아니다. |
| 작업 선택 | 하위 작업 실행 전의 선택 결과다. 작업 이름·이유·인자 원문을 확인하며 인자 문자열은 해석하지 않고 그대로 표시한다. |
| 에이전트 | 실행 상태 객체에 저장된 공개 응답과 작업 이력을 확인한다. 직접 반환값은 `null`이다. |
| 보고서 생성 흐름 | 한 동의 선정 → 설명 → 인사이트 순차 실행과 공유 예산·단계별 이력·최종 보고서를 확인한다. 직접 반환값은 `null`이고 별도 에이전트 역할은 없다. |

실제 하위 호출은 준비된 자료로 실제 구현을 실행한 기록이며, 모의 하위 응답은 미리 준비한 응답을 제공한 기록이다. 모의 응답은 사용 내역·예상 밖 호출·남은 응답을 구분해 표시한다. 남은 응답이 있다는 이유로 평가 실패를 부여하지 않는다. 실제 하위 호출도 운영 데이터베이스 연결의 증거는 아니다.

보고서의 선정·설명·인사이트 에이전트는 역할별 대상으로, 전체 순차 실행은 `workflow/report` 대상으로 구분한다. HTTP 접수·데이터베이스 저장·요청 전체의 재처리·완료 알림은 [실행 범위](../../docs/runner.md#1-실행-범위)에 포함되지 않는다.

### 상태 구분

| 상태 | 의미 | 예시 |
| --- | --- | --- |
| 실행 상태 | 지정한 실행 범위의 진행·종료 여부 | 실행이 반환되어 종료됨 |
| 업무 상태 | 업무 처리의 진행·완료 여부 | 실패·부분 완료·질문 대기 |
| 평가 판정 | 선택한 채점 기록의 판정 | 통과·실패·미판정·비적용. 채점 파일이 없으면 미제공 |

실행이 반환되어 종료됐어도 업무는 실패하거나 질문 대기 상태일 수 있다. 화면은 세 상태를 따로 표시한다. 적용할 검사 ID도 준비 자료이므로 검사 수행이나 통과를 뜻하지 않는다.

### 근거와 내려받기

누적 호출 기록 파일이 저장되지 않았더라도 결과 파일 안의 호출 기록은 확인할 수 있다. **기존 실행 모니터 열기**는 [실행 모니터](../../../report_viewer/README.md)를 별도 화면으로 여는 링크이며, 현재 실행을 자동으로 전달하지 않는다.

긴 원문은 화면에서 일부만 표시한다. **원본 내려받기**는 읽어 둔 JSON 값 전체를 서식화하여 저장하므로 원래 파일의 공백·줄바꿈까지 복제하지는 않는다. JSONL 파일은 정상적으로 읽은 호출 기록만 내려받으며 손상된 줄을 복구하지 않는다. 실행 조건에 있는 해시도 기록된 값을 표시하며 현재 코드나 입력과 다시 대조하지 않는다.

## 3. 파일 연결과 오류

뷰어는 선택한 JSON·JSONL 파일을 [실행기의 저장 구조](../../docs/runner.md#4-저장-결과)에 따라 상대 경로로 연결한다. 연결에 필요한 형식과 식별자를 검사하며, 실행기의 입력 검사나 업무 결과 판정을 대신하지 않는다.

| 조건 | 화면 동작 |
| --- | --- |
| 묶음과 실행의 식별자·대상·반복 순번이 다름 | 해당 결과를 연결하지 않고 불일치를 표시 |
| 실행과 사례의 역할·하위 호출 방식이 다름 | 해당 사례 자료를 연결하지 않고 불일치를 표시 |
| `case.json`이 없음 | 같은 묶음의 `suite.json`에 식별자·대상·역할·호출 방식이 맞는 사례가 있으면 대신 표시하고 출처를 명시 |
| 등록된 실행의 결과 파일이 없음 | 등록 기록을 유지하고 파일 누락을 표시. 진행 중이거나 저장 전에 중단됐을 수 있으므로 평가 실패로 표시하지 않음 |
| 같은 상대 경로나 실행 식별자가 중복됨 | 중복을 알리고 임의의 파일을 선택하지 않음 |
| 누적 호출 기록에 잘못된 줄이 있음 | 정상 줄은 표시하고 오류가 난 줄 번호와 일부만 읽었음을 안내 |
| 묶음과 결과 파일의 실행 상태가 다름 | 저장 시점 차이일 수 있으므로 두 상태를 유지하고 차이를 안내 |
| 결과 참조가 절대 경로이거나 상위 폴더를 가리킴 | 해당 참조를 연결하지 않음 |

알 수 없는 추가 필드는 원본 값에 보존하며, 별도 계약 없이 평가 지표로 해석하지 않는다.

## 4. 도구 지표와 제공 범위

[도구 채점 계약](../../docs/runner.md#6-도구-채점)에 따라 같은 평가 기록의 판정과 지표를 표시한다. 대상 선택은 집계 범위를 바꾸지만 사례 검색·필터는 저장된 분모나 시간 통계를 바꾸지 않는다.

| 구분 | 표시 기준 |
| --- | --- |
| 검사별 통과·실패·미판정·비적용 | 저장된 비교 항목 단위. 같은 도구·사례·반복·실행 ID·검사 ID·비교 경로·판정은 한 건으로 세며 중복 원본도 근거에서 보존 |
| 기능 지표 | 저장된 필수 사례 통과 건수·분모·통과율·합격 판정·완료 여부. 사례별 필수 여부와 예정·기록 반복, 누락·미판정 순번과 사유도 표시 |
| 분모 0·측정값 없음 | 통과율은 미제공, 시간은 미기록으로 표시. 0%나 0초로 만들지 않음 |
| 시간 통계 | 저장된 정상·오류 호출의 표본 수·중앙값·p95. 미종료·충돌·무효 측정·한도 초과와 사유도 표시 |
| 운영 목표 | 목표별 정상·오류 구분, 대상 사례·환경·자료 크기·통계·목표 상한·측정값·판정·완료 여부·사유. 목표가 없으면 목표 미제공·충족 여부 미판정 |
| 재평가 | 평가 시각·ID로 기록 선택. 해당 기록의 기준·근거·평가기 해시와 전체 JSON 내려받기 제공. 해시는 기록값이며 재계산하지 않음 |

채점 파일은 묶음 ID·입력 묶음 ID로 연결하고, 같은 실행 ID의 사례·대상·반복 순번이 다르면 해당 채점 파일을 연결하지 않는다. 중복 평가 ID나 모호한 묶음 연결은 경고한다. 파일명이 달라도 `tool-evaluation-v1`이면 읽는다. 연결할 `batch.json`이 없으면 채점 전용 묶음으로 열며 실행 원본은 미제공으로 표시한다.

반복 실행은 같은 사례를 새로 실행하는 것이고, 재평가는 저장된 실행을 기준에 따라 다시 판정하는 것이다. 채점 파일이 없거나 선택한 기록에 실행이 포함되지 않으면 그 실행의 채점 결과를 미제공으로 표시한다.

노드의 `node-evaluation-v1` 지표·재평가, 다른 단위의 채점 지표, 비용 통계, 기존 실행 모니터의 특정 실행으로 자동 이동은 연결하지 않는다. 도구의 기능·운영 합격 기준과 통계 계산식은 뷰어에서 정하지 않는다.

## 5. 개발과 검증

파일을 읽고 연결하는 부분과 화면에 표시하는 부분을 분리한다. 출력 계약이 바뀌면 파일 연결 부분에서 변화를 수용하고, 화면에는 제공된 결과를 전달한다.

| 파일 | 역할 |
| --- | --- |
| [조회 자료 생성기](../catalog.py) | 기본 결과 폴더의 경로·크기·식별 정보 목록 생성. 실행·채점 저장 후 자동 갱신 |
| [lazy-results.js](../shared/lazy-results.js) | HTTP로 선택 원본만 읽기, 상대 경로·파일 연결·해시 검증, 캐시·파일 크기 제한 |
| [data.js](data.js) | JSON·JSONL 읽기, 형식·식별 검사, 관련 파일 연결과 원본 값 보존 |
| [app.js](app.js) | 대상·사례·반복·재평가 탐색, 검사 건수와 개별 근거, 저장된 기능·운영 지표 표시, 내려받기 |
| [record-names.js](../shared/record-names.js) | 세 평가 뷰어의 실행·채점 이름, 한국시간, 다운로드 파일명 구성 |
| [index.html](index.html), [styles.css](styles.css) | 대상 목록·사례 목록·상세 영역의 구성과 화면 크기에 따른 배치 |
| [assets/PretendardVariable.woff2](assets/PretendardVariable.woff2) | 로컬 가변 글꼴. [SIL Open Font License](assets/Pretendard.LICENSE.txt) 포함 |
| [samples.js](samples.js) | 실제 결과와 구분한 가상 파일. 사용자 파일과 같은 읽기 과정을 사용 |
| [data.test.cjs](data.test.cjs), [app.test.cjs](app.test.cjs) | 파일 연결과 화면 탐색 검증 |
| [runner_integration.py](runner_integration.py) | 실제 조회 도구의 실행·채점 산출물을 뷰어에 연결하고 원본 보존·지표를 대조하는 검증 |

다음 명령은 `Eumi/ai`에서 실행한다. 파일·화면 검증에는 Node.js가 필요하며, 실행기 연결 검증에는 [AI 실행 환경](../../../README.md)도 필요하다.

```powershell
node --test eval/viewers/results/data.test.cjs eval/viewers/results/app.test.cjs eval/viewers/shared/record-names.test.cjs eval/viewers/shared/lazy-results.test.cjs
uv run python -m pytest eval/tests/test_viewer_catalog.py eval/tests/test_evaluation_runner.py eval/tests/test_evaluation_scoring.py -q
uv run python -m eval.viewers.results.runner_integration
python scripts/check_docs.py
```

HTTP 조회 회귀에서는 초기 목록·선택 묶음·채점 JSON을 요청하는지, 사례 선택 시 해당 실행 파일만 추가 요청하는지, 형식 미확인 JSON을 명시 선택 전에 읽지 않는지 확인한다. 미로딩·파일 누락·읽기 오류의 구분, 원본 판정 보존, 수동 선택 크기 제한과 기존 파일 탐색도 검사한다. 파일·폴더 선택 대화상자의 실제 브라우저 조작과 모델·운영 DB 성능은 이 자동 검증에 포함하지 않는다.

설계 대조: 실행기가 만든 원본과 별도 채점 파일을 읽기 전용으로 연결한다. 기준·판정·시간 통계의 생성 책임은 실행기에 유지하며, 뷰어는 표시와 저장된 판정 건수 집계만 담당한다. State·도구 인자·모델 응답·실행 흐름은 변경하지 않았다.
