# AI Agent 기능 명세

수정일: 2026-11-06.

시스템 구성 요소와 기술안은 [아키텍처](ai-agent-architecture.md)에서 정의한다.

## 1. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 도구 | 정해진 입력과 처리 규칙에 따라 결과를 반환하는 기능 |
| 워크플로우 | 수행 단계와 진행 규칙이 정해진 처리 과정 |
| Agent | 목표와 중간 결과를 보고 다음 작업을 선택하는 실행 주체 |

## 2. 도구 명세

아래 표는 기능별 입출력의 개념 명세다. 실제 서비스 API 경로는 별도 연동 계약을 따른다. Tableau 시각화 검증의 입력·출력·오류·실행 연결은 §2.3에서 구현 문서로 연결한다. 이 표만으로 화면 연동이 구현됐다고 보지 않는다.

자료 검색·RAG는 작업 선택 및 실행의 데이터 검색·조회 도구로 수행한다. 호출 결과는 results의 해당 output에 저장하고 출처·실제 자료 버전도 그 출력에 포함한다. 별도 info나 results.sources 목록을 만들지 않는다.

### 2.1 데이터 검색·조회

저장된 데이터에서 지정된 조건에 맞는 정보를 검색하고 반환한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 대상, 조회 방식·조건 / 필드·정렬·최대 건수·시점·버전 |
| 출력 | 레코드, 참조 ID, 출처·버전·기준 시점 |
| 조회 요약 | 적용 조건, 결과 수, 다음 페이지 |
| 오류 | 잘못된 조건, 권한 부족, 참조 없음 |

등록된 데이터만 조회한다. 임의 테이블·SQL은 실행하지 않는다. 결과 없음과 조회 실패를 구분한다.

### 2.2 데이터 가공

조회하거나 전달받은 데이터에 지정된 연산을 적용한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 원본 참조·버전, 연산·순서, 결합 키·방식 |
| 출력 설정 | 결측 처리, 반환 필드·자료형, 반올림 |
| 출력 | 가공 결과·단위, 적용 연산, 입력·출력·제외 행 수 |
| 오류 | 단위 불일치, 분모 0, 결측, 결합 실패 |

결측을 임의로 0으로 바꾸지 않는다. 분모·공간·시간 단위가 다르면 비교를 중단하거나 한계를 표시한다.

### 2.3 시각화 검증

게시된 Tableau 뷰와 표시 조건을 등록 설정에 대조하고 프론트용 산출물을 반환한다. 요청마다 외부 API·헤드리스 브라우저를 실행하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 등록 뷰 식별자, 해당 뷰의 매개변수·필터 |
| 검사 | 자료형, 뷰별 등록 이름·허용값·필수값, 선언된 날짜 순서·매개변수별 필터 허용값, 중복 값 |
| 출력 | 적합 여부, 구체적인 부적합 사유, 유효한 경우 `tableau` 산출물 |
| 산출물 | 뷰 주소·대상 시트·매개변수·필터·출처·등록 설정 버전·한계 |

설정 검사 통과는 자료 존재·최신성·실제 표시 성공을 의미하지 않는다. 실제 렌더링과 적용값 확인은 프론트가 수행한다. 구현 계약은 [Tableau 시각화 실행](TABLEAU.md)을 따른다.

뷰별 등록 정보는 선택 목적·한계와 워크북·게시 뷰명·필터 대상 시트를 정의한다. 같은 입력 규격은 공통 입력 프로필을 참조한다. 등록 시 참조·기본값·허용값·검증 규칙의 일관성을 검사한다. 작업 목적 파악에는 선택 목록, 작업 선택 및 실행에는 입력 프로필과 이미 확인된 조건의 상세값을 제공하며, 진행 판단·응답 작성은 실제 호출 결과를 사용한다. 별도의 모델 호출 단계는 추가하지 않는다.

시각화에 사용할 수 있는 뷰는 `execution.event`와 등록 카탈로그의 `event_views`로 결정한다. `analysis_pipeline`과 `user_request`별로 등록 뷰 ID 목록을 관리하며, 모델에는 해당 이벤트의 뷰·입력 프로필만 제공한다. 검증 도구도 같은 State와 배포 명세를 읽어 허용 목록 밖의 뷰를 `view_not_allowed`로 거부한다. 빈 목록은 해당 이벤트의 시각화 사용 불가를 뜻한다. 이벤트별 목록 누락·미등록 이벤트·미등록 뷰 ID는 구성 오류다. 모델의 도구 인자로 이벤트나 허용 목록을 받지 않는다. 하위 실행과 질문 재개는 [State 계약](ieumi-agent-state.md)의 이벤트 상속·유지 규칙을 따른다. 분석 이벤트 `analysis_pipeline`에는 `EmbedDetailV01`~`EmbedDetailV08`을 배정하고, `user_request`는 `all`로 등록 뷰 전체를 허용한다. 새 등록 뷰도 `all`에 포함되며 임의 URL·미등록 뷰는 허용하지 않는다.

## 3. Agent 명세

실제 호출 순서와 예외는 [실행 흐름](ieumi-agent-workflow-design.md)을 따른다. 각 Agent의 목적·확인된 대상·범위는 goal에 서술하고 별도 공통 subject는 두지 않는다. 작업 선택 이유·호출·검증·재시도·판단은 results에 기록한다. 공개할 설명과 산출물은 response.content·artifacts에 함께 구성한다.

작업 선택 및 실행은 모델 1회로 작업을 선택하고 도구 입력·설정 검사와 호출 결과를 기록한다. 별도의 결과 검증용 모델은 호출하지 않는다. 작업 진행 판단은 전체 요청에 부족한 내용을 decision에 기록하고 구체적인 도구 선택은 작업 선택 및 실행 노드에 맡긴다. 노드별 쓰기 범위와 읽기 컨텍스트 정책은 구분한다.

### 3.1 데이터 분석 결과 해석 Agent

분석 결과와 해석 가이드라인을 바탕으로 주요 신호, 비교 결과, 지역·집단 특성과 해석 한계를 설명한다. 도구로 분석·비교 자료와 계산 결과를 확보하고, 응답 작성에서 해석문을 생성한다. 이벤트 실행은 시스템이 goal·constraints·messages를 구성하고 입력 검증 후 작업 선택 및 실행으로 진입한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 분석 결과, 지역·집단, 단위·기간, 비교 기준·품질 지침 |
| 출력 | 주요 신호, 비교 설명, 근거 지표, 한계·확인 사항 |
| 종료 | 주요 신호·비교 설명·근거·한계를 갖춘 해석 또는 해석 불가 사유 반환 |

해석은 관측한 지역·집단·기간과 비교 근거 안에서 작성한다. 관측 사실과 가능한 설명을 구분하고, 근거가 뒷받침하는 범위와 한계를 제시한다. 이 기준은 해석을 작성하는 책임에 적용한다.

활용 도구: 데이터 검색·조회, 데이터 가공

### 3.2 데이터 시각화 Agent

전달 목적에 맞는 게시된 Tableau 뷰와 표시 조건을 선택한다. 시각화 검증 도구로 등록 설정의 적합성을 검사하고, 작업 선택 및 실행에서 사용자 목적·대상에 맞는 조건을 선택한다. 검증 이력을 남기고 부적합 사유를 바탕으로 조건을 수정하거나 필요한 정보를 요청한다. 작업 진행 판단에서 요청 충족 범위를 확인하며, 응답 작성에서 유효한 산출물·적용 조건·한계를 제공한다. 게시되지 않은 지표·임의 계산 결과를 다른 뷰로 대체하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 목적, 확인된 도시·기간·읍면동, 기존 화면·산출물 조건 |
| 출력 | 프론트용 Tableau 산출물, 적용 조건·출처·한계 |
| 종료 | 요청에 부합하는 유효한 표시 설정 또는 지원 범위·표현 불가 사유 반환 |

활용 도구: 데이터 검색·조회, 데이터 가공, 시각화 검증

### 3.3 사용자 요청 처리 Agent

서비스 이용 중 입력한 자연어 요청을 파악해 필요한 전문 Agent·도구를 선택하고 호출한다. 작업 진행 판단에서 추가 작업·사용자 정보가 필요한지 결정한다. 응답 작성에서는 제공할 중간 결과를 정리하거나 최종 결과를 통합하며, 설명문과 연결할 산출물을 함께 구성한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 요청, 현재 화면·선택 대상, 확인된 자료·관련 이력 |
| 출력 | 중간 응답·공개 산출물, 최종 통합 응답·근거·미해결 사항, 추가 질문 |
| 종료 | 요청 충족 또는 가능한 결과와 미해결 사항 반환 |

중간 응답은 실행 중 제공 가능한 개별 결과와 남은 작업을 설명한다. 최종 응답은 요청한 결과와 미해결 사항을 통합한다. 하위 결과를 전달·통합할 때 수치·의미·출처·한계를 보존한다. 직접 새로운 해석을 작성하면 해당 내용에 §3.1의 해석 기준을 적용한다.

공개할 산출물 선택과 응답 작성은 이 Agent가 맡는다. AI 서버는 결과 행을 저장한 뒤 백엔드에 POST로 알리고, 백엔드·프론트는 결과 조회·표시를 맡는다. 호출 후 공개 시점과 작업 계속 경로는 [실행 흐름 §2.1](ieumi-agent-workflow-design.md#21-사용자-요청-처리-agent의-중간-응답)을 따른다.

활용 도구: 데이터 검색·조회, 데이터 가공, 시각화 검증
활용 Agent: 데이터 분석 결과 해석 Agent, 데이터 시각화 Agent

## 4. 출력 구분

| 출력 | 위치 | 내용 |
| --- | --- | --- |
| 내부 기록 | results | 선택·판단 근거, 도구·Agent 반환값, 검증·재시도 |
| 진행 안내 | response.kind=progress | 실제 수행 중인 작업 안내. 기존 공개 산출물 보존 |
| 중간·최종 결과 | response.content·artifacts | 설명·해석·차트·표·근거·한계·미해결 사항 |
| 질문 | response.kind=question | 답변할 정보·질문 ID. 저장·재개는 실행 계층에서 관리 |

내부 sources·issues·result_refs 같은 공통 목록을 공개 응답에 복제하지 않는다. 출처와 한계는 내용과 관련 산출물에서 설명한다. 세부 자료형은 [State](ieumi-agent-state.md), 백엔드 전달은 [연동 API 초안](ai-runtime-api-20261029.md)에서 관리한다.
