# AI 개발 문서

기준일: 2026-11-13.

지역 분석 결과의 해석·시각화·사용자 요청 처리를 위한 명세와 실행 안내다. [전체 아키텍처](architecture.md)에서 실행 환경인 런타임과 업무 판단을 맡는 에이전트의 연결을 확인한 뒤, 작업에 해당하는 영역을 읽는다. 각 문서는 확정된 요구사항·현재 구현·미확정 사항을 구분한다.

## 런타임

요청 접수·저장·알림, 모델 연결과 입력 구성, 실행 관측을 다룬다. 설치·실행 → API → API 검증 → 모델 입력 구성 → 모니터링 순서로 읽는다.

| 문서 | 다루는 내용 |
| --- | --- |
| [설치·실행](../README.md) | 환경 설정, 서버·컨테이너 실행, 로컬 데모, 현재 검증 상태 |
| [API](runtime/api.md) | 사용자 요청·보고서 생성의 API 목록·입출력·저장·실행 제한, 공통 인증·알림·운영 조건 |
| [API 검증](runtime/api-verification.md) | 사용자 요청·보고서 생성의 로컬 HTTP 왕복 검증, 실행 명령·결과 확인·검증 범위 |
| [모델 입력 구성](runtime/prompts.md) | 실행 상태에서 모델 입력을 구성하는 방식, 노드·역할별 정보 제공, 모델 연결 |
| [모니터링](runtime/monitoring.md) | 원격·로컬 실행 기록, 수집 범위, 기록 조회와 검증 상태 |

## 에이전트

업무 목적·역할·판단 흐름·실행 상태와 결과 품질을 다룬다. 실행 상태(`State`)는 요청·작업 이력·응답·실행 정보를 보관하는 자료다. 업무 범위 → 기능 명세 → 실행 흐름 → 실행 상태 순서로 읽고, 작업에 필요한 세부 문서를 확인한다.

| 문서 | 다루는 내용 |
| --- | --- |
| [업무 범위](agent/scope.md) | 사용자, 문제, 지원 범위, 담당자 역할 |
| [기능 명세](agent/components.md) | 도구 입출력, 에이전트별 역할·호출·종료 조건 |
| [실행 흐름](agent/workflow.md) | 시작 이벤트, 판단·호출 순서, 단계 안내·결과 전달, 질문·종료·오류 처리 |
| [실행 상태](agent/state.md) | 필드·자료형·노드별 쓰기 범위·실행 상태와 예산 |
| [컨텍스트](agent/context.md) | 모델의 판단에 제공할 정보, 정보의 보관 기준과 쓰기 책임의 구분 |
| [데이터](agent/data.md) | 활용 자료·접근 방식·출처·갱신 |
| [업무 지침](agent/instructions.md) | 서비스 에이전트에 제공하는 지침의 작성·적용·관리·검증 |
| [보고서 생성](agent/report.md) | 시각화 선정·시각화 설명·퀵 인사이트 에이전트의 순차 실행, 단계별 자료·산출물·검토와 동별 저장 |
| [Tableau 시각화](agent/tableau.md) | 등록 뷰·입력 검사, 에이전트 연결, 프론트 전달 계약 |
| [실행 시나리오](agent/scenarios.md) | 가상 자료를 사용하는 실행 예시·시연 문구·산출물·예외 |

## 평가

평가 파일의 위치와 실행·채점 시작점은 [평가 실행 안내](../eval/README.md)에서 확인한다. 코드·명세·시나리오·뷰어·테스트·실행 결과는 `ai/eval/`에 모아 둔다.

[평가 방법](../eval/docs/methods.md)에서 도구·노드·에이전트 실행의 내부 평가 분류와 공통 절차를 확인한다. 실제 사용자의 업무 지원·사용 경험은 서비스 검증으로 구분한다. 실제 검사·측정·지표·합격 기준은 해당 문서를 따르며, 미정인 기준과 미실행 검증은 별도로 표시한다.

| 문서 | 평가 대상 |
| --- | --- |
| [단위 평가 실행기](../eval/docs/runner.md) | 사례 입력 양식, 단위 실행·DB 조회 연동·증거 보존, 도구·노드·실행 전체·최종 출력 품질 채점과 지표 집계 |
| [평가 방법](../eval/docs/methods.md) | 평가 절차, 사례 기록, 결과 기록, 판정 원칙 |
| [도구](../eval/docs/tools.md) | 개별 호출의 처리·반환 결과 |
| [노드](../eval/docs/nodes/README.md) | 노드별 출력의 형식·필수 내용·정확성 |
| [에이전트 실행](../eval/docs/execution/README.md) | 노드·역할 간 순서·전달·공유 한도와 최종 반환의 기능 평가, 한 실행의 성능·안정성 운영 평가 |
| [서비스 검증](../eval/docs/service-validation.md) | 실제 사용자의 근거 탐색·이해와 사용 부담·만족. 세부 방법·기준 미정 |

평가에 사용할 사례의 구성·자료 출처·실행 방법·준비 상태는 각 데이터셋 안내에서 확인한다.

| 데이터셋 | 구성 |
| --- | --- |
| [합성자료 도구 사례](../eval/scenarios/tools/README.md) | 고정한 합성자료를 사용하는 도구 사례 |
| [서비스 DB 조회 사례](../eval/scenarios/database/README.md) | 별도 평가 DB에 합성자료를 적재해 서비스 조회 기능을 확인하는 사례 |
| [노드 시나리오 데이터셋](../eval/scenarios/nodes/README.md) | 여섯 역할의 정상 진입·반환 21개 경로, 색인에서 역할·보고서 전체 실행, 독립 노드 입력·기대 결과와 실제 DB 스냅샷 |
| [실행 연결 사례](../eval/scenarios/execution/README.md) | 사용자 요청·공유 한도·동별 보고서·기존 상태 재진입의 네 합성 사례, 공통·보고서 규칙 채점 |
