# AI Agent 모니터링

기준일: 2026-11-02. 구현 의도와 현재 코드·검증 범위를 구분한다.

## 1. 구현 의도

Langfuse로 Agent의 실행 경로·지연·실패·모델 사용량을 확인해 문제 구간과 배포별 차이를 찾는다. 업무 판단과 State 갱신은 기존 실행 흐름이 담당한다.

| 목적 | 구현 방향 |
| --- | --- |
| 실행 과정 확인 | 한 실행의 최초 호출·질문 재개와 하위 노드·모델·도구 호출을 연결 |
| 운영 문제 구분 | 완료·부분 완료·실패·대기를 구분하고 처리 시간·사용량 기록 |
| 수집 범위 제한 | 운영 정보만 전송하고 대화·State·오류 원문 제외 |
| 업무 실행 유지 | 추적 장애로 업무 호출을 반복하지 않고 실제 예외·취소는 호출자에게 전달 |

실행 완료는 답변 정확성이나 평가 합격을 의미하지 않는다. 품질 판정은 [평가 명세](ieumi-agent-evaluation.md)를 따른다.

## 2. 구현 상태

| 항목 | 상태 | 현재 범위 |
| --- | --- | --- |
| 추적 연결 | 구현 | [모니터링 모듈](../src/monitoring.py)의 Langfuse SDK 5 콜백을 [모의 데모](../demo/demo.py)와 [Gemini 시나리오](../demo/scenario_demo.py)에 연결. 호출마다 별도 콜백 사용 |
| 실행 식별 | 구현 | `execution.run_id`로 trace ID 생성, Session ID에는 `run_id` 사용. 최초 호출·재개를 같은 추적에 연결하고 `execution.version` 기록 |
| 데이터 제한 | 구현 | 입력·출력·임의 메타데이터를 전송 속성에서 제외. 오류 문자열은 예외 종류로 치환하고 미디어 업로드 비활성화. 이름·ID·버전의 원문 포함 여부는 검사하지 않음 |
| 장애·종료 처리 | 구현 | 추적 초기화·갱신·종료 실패는 경고 기록, 업무 재호출 없음. 종료 시 전송 대기열 처리. 잘못된 설정은 시작 시 거부 |
| 서비스 실행기 | 미연결 | HTTP 요청부터 서비스 결과 전달까지의 추적은 미연결 |
| 운영 수신·비용 | 미검증 | 실제 Langfuse 서버의 인증·수신·화면과 실제 모델 비용 산출은 확인하지 않음 |
| 운영 대시보드·알림 | 미구성 | 원격 대시보드 생성·자동 알림 미구성. 운영 임계값 미정 |

2026-11-01에 공통 그래프·데모·모니터링 테스트 **48개**가 통과했다. [모니터링 테스트](../tests/test_monitoring.py)는 실제 SDK의 전송 대상을 메모리로 대체해 실행 상태·재개 연결·동시 실행 분리·예외·취소 전파·원문 제외·모의 모델 사용량·도구 추적·추적 장애를 검사했다. 이는 실제 서버 수신 검증과 구분한다.

## 3. 관측 항목과 해석

추적 묶음을 trace, 개별 호출 기록을 observation이라 한다. 공통 그래프의 업무 단계는 [실행 흐름](ieumi-agent-workflow-design.md#2-agent-공통-실행-흐름)을 따른다.

| 항목 | 기록 | 해석 기준 |
| --- | --- | --- |
| 실행 경로·시간 | 최초 호출 `eumi.agent.start`, 재개 `eumi.agent.resume`, 그래프 `eumi.graph`와 하위 호출 | 처리 시간은 최초·재개 구간별로 확인. trace 전체 경과 시간에는 답변 대기가 포함될 수 있음 |
| 결과·오류 | `status`, `error_code`, `exception_type`, `response_kind` | 실패·실행 예외는 `ERROR`, 부분 완료·취소는 `WARNING`, 질문 대기는 정상 흐름 |
| 이력·실패·산출물 수 | `result_count`, `failure_count`, `artifact_count` | 호출 종료 시 State의 누적 수. 실패 수는 실패한 이력 항목 수이며, 최초·재개 값을 합산하지 않음 |
| 모델 사용량 | 모델명, 입력·출력 토큰, 비용 속성 | 모델이 사용량을 반환해야 수집 가능. 실제 비용 산출은 모델 가격 매칭 확인 필요 |
| 실행·배포 비교 | `run_id`, `version`, `phase`, 환경 | 실행 ID로 결과를 연결하고 배포 버전·환경별로 비교 |

최종 결과를 집계할 때는 실행 ID별 마지막 상태를 사용하고 대기·부분 완료·취소를 구분한다. 수집 비율을 낮춘 기록은 전체 실행 건수가 아니다. 이 값은 운영 진단용이며 자동 합격 판정이나 임계값은 적용하지 않는다.

실행 방법은 [실행 안내](../README.md), 설정 항목은 [환경변수 예시](../.env.example)를 따른다. 현재 한 프로세스에서 한 Langfuse 프로젝트를 사용하며, 콜백 설정을 전달한 LangChain 호출이 수집 대상이다.
