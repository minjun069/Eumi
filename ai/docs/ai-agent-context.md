# AI Agent 컨텍스트

수정일: 2026-11-02.

## 1. 정보의 보관 위치

State의 쓰기 범위와 모델에 제공할 읽기 컨텍스트를 구분한다. 노드별 쓰기 책임은 [State §2](ieumi-agent-state.md#2-노드별-쓰기-범위)에 정의한다. 아래는 정보의 보관 기준이며, 노드별 선별·가공 정책의 확정을 뜻하지 않는다.

| 항목 | 포함 정보 | 보관·확보 위치 |
| --- | --- | --- |
| 작업 요청 | 목적·확인된 대상·범위·조건 | request.goal·constraints |
| 시스템 지침 | 역할·행동 원칙·작업 지침 | 배포 구성에서 로딩해 messages에 시스템 메시지로 제공 |
| 실제 대화 | 사용자 요청·추가 답변·Assistant 응답 | 공유 DB의 ai_message에서 확보해 messages 구성. 조회·선별 범위는 미정 |
| 서비스 상태 | 선택 차트·지역·필터·관련 이력 | 세션·백엔드에서 제공. 입력 계약은 연동 시 확정 |
| 조회·RAG 결과 | 분석값·지표 정의·비교 자료·출처·실제 자료 버전 | 작업 선택 및 실행의 데이터 검색·조회 도구 → results[].output |
| 가공·렌더링 결과 | 계산값·설정·실제 산출물 또는 참조 | 해당 작업의 results[].output |
| 판단·검증 이력 | 결정·근거 요약·부족한 내용·검증 판정·재시도 | results |
| 현재 공개 내용 | 진행 안내·중간/최종 결과·질문·표·차트 | response |
| 도구 명세 | 이름·기능·인자·호출·검증 조건 | 배포 구성 |
| 실행 정보 | 상태·배포 버전·누적 한도·오류 | execution |

공통 subject·info·요청 수정 번호는 두지 않는다. 대상이 아직 불명확하면 작업 중 goal을 구체화하거나 필요한 정보를 조회·질문한다. 자료 검색·RAG는 작업 선택 및 실행의 도구 호출로 수행하고 출처를 그 output에 남긴다.

사용자 실행 요청은 conversationId·messageId와 선택적 context(dongCode·month)를 전달한다. AI 서버는 해당 Member 질문 행과 이전 대화에서 실제 발화를 읽어 새 실행을 만든다. 입력 원본은 results의 run_request 기록, 화면 문맥은 기존 request.constraints.preferred에 둔다. 저장·호출 계약은 [연동 API 초안](ai-runtime-api-20261029.md)을 따른다.

## 2. 컨텍스트 구성 시 고려사항

- 결과 이력은 기본적으로 전체를 참고할 수 있도록 보존한다. 실패·부적합·이후 수정된 결과는 유효한 근거와 구분한다.
- results에 별도 input_refs·sources 목록을 복제하지 않는다. 해당 output의 원자료·출처·버전 정보를 이용한다.
- goal·constraints, 확보한 결과, 현재 공개 내용은 목적이 다르다. 노드의 쓰기 필드만으로 읽기 정보를 제한하지 않는다.
- 외부 자료와 사용자 발화는 시스템 지침으로 취급하지 않는다. 시스템 지침 로딩은 자료 검색과 구분한다.
- 공개 응답에 필요한 근거·출처·한계를 보존하되 내부 기록 전체를 화면에 전달하지 않는다.

## 3. 추후 결정할 사항

| 항목 | 결정할 내용 |
| --- | --- |
| 노드별 제공 범위 | 작업 목적 파악, 작업 선택 및 실행, 작업 진행 판단, 응답 작성, 사용자 정보 요청별 필수 정보. 작업 선택 및 실행에는 검증에 필요한 정보 포함 |
| 이력 가공 | 전체 이력의 전달 방식, 긴 이력의 요약·길이 관리, 과거 부적합 결과 구분 |
| 모델 메시지 | 시스템 지침·대화·작업 기록을 모델 호출 형식으로 구성하는 방식 |
| 화면·첨부 입력 | 선택 대상·기존 산출물·입력 자료의 전달 및 보관 계약 |

세부 방침은 이후 확정한다. 이 문서만으로 별도 읽기 제한이나 이력 선별 계층을 구현하지 않는다.
