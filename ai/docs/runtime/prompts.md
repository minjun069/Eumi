# 모델 입력 구성

기준일: 2026-11-15 · 구분: 현재 구현

모델이 현재 작업을 판단할 수 있도록 **공통 지침과 대화에 업무 단계·역할·실행 조건별 정보를 더한다**. 
업무 자료의 원본은 실행 상태(`State`)에 둔다. 호출할 때마다 지침용 **시스템 프롬프트**와 작업 자료용 **사용자 프롬프트**를 구성해 각각 `system` 메시지 1개와 `user` 메시지 1개로 전달한다. 
도구 설명·입력 명세는 기존 정의에서 자동 생성해 시스템 프롬프트의 `[도구 명세]` 구역에 넣는다. 응답 형식은 `with_structured_output()`으로 별도 전달한다.

## 2 공통 프롬프트

아래 순서로 구성하며, 자료가 없는 구역은 생략한다.

```text
system
  [공통 원칙]
  분석 해석 지침
  [현재 Agent 역할]
  [이번 노드의 작업 지침]
  [도구 명세] — 작업 선택 호출에만 제공

user
  [현재 작업 목표]
  [필수 조건] [선호 조건] [제외 조건]
  [실제 대화 · 입력 메시지]
  [기존 공개 응답]
  [기존 공개 산출물]
  + 노드별 추가 입력
```

| 항목 | 제공 정보 | 제공 기준 |
| --- | --- | --- |
| 공통 원칙 | 사실·해석·한계 구분, 근거 보존, 계산 도구 사용, 시각화 검증 범위 | 공통 그래프의 모든 노드에 제공 |
| 분석 해석 지침 | [분석 해석 지침 원문](../../src/instructions/analysis-interpretation.md) | 공통 노드와 보고서 전용 호출에 제공. 현재 역할·단계의 작업 범위 안에서 적용 |
| 에이전트 역할 | 아래 역할별 지침 | 현재 역할에 해당하는 지침 제공 |
| 작업 목표 | `request.goal` | 원문 제공 |
| 작업 조건 | `constraints` | 값이 있을 때만 제공 |
| 실제 대화 | `messages` 전체 | 원래 순서·역할·내용을 유지하며 요약하지 않음 |
| 공개 응답 | `response.content` | 존재할 때 제공 |
| 공개 산출물 | `artifacts` | 존재할 때 제공 |

| 역할 | 제공하는 작업 지침 |
| --- | --- |
| 사용자 요청 처리 | 전문 작업 위임·통합 |
| 데이터 분석 결과 해석 | 조회·계산·해석 |
| 데이터 시각화 | 등록 뷰·조건 선택 |
| 보고서 시각화 선정 | 선정에 필요한 근거 확보, 뷰 적합성과 설명 범위 판단 |
| 보고서 시각화 설명 | 확정된 선정·설명 범위에서 추가 자료 확보, 뷰별 설명 작성·검토 |
| 보고서 퀵 인사이트 | 검토를 통과한 설명의 핵심 요약·검토, 새 주장 금지 |

목표·조건·문자열 발화·기존 응답은 원문으로 전달한다. 
결과 이력·자료 목록·산출물·실행 조건과 문자열이 아닌 메시지 내용은 JSON으로 전달한다.

### API 설정과 응답 검증

| 항목 | 구성 규칙 |
| --- | --- |
| 응답 스키마 | 공통 노드 5종과 보고서 전용 `TypedDict`에서 `TypeAdapter.json_schema()`로 생성. `with_structured_output(method="json_schema", include_raw=True)`에 전달 |
| 선택 응답 형식 | Structured Outputs의 `strict=True`로 `name`, `arguments_json`, `reason` 구조를 강제. 다른 업무 노드·보고서 응답은 기존 `strict=False` 유지 |
| 도구 명세 | 작업 선택 호출에서 역할·현재 실행 상태에 맞는 기존 정의를 JSON으로 만들어 시스템 프롬프트의 `[도구 명세]` 구역에 제공. API 요청에는 `tools`·`tool_choice`를 넣지 않음 |
| 선택 인자 | `arguments_json`에 인자 객체를 JSON 문자열로 반환. 문자열 내부는 Structured Outputs의 형식 강제 대상이 아니므로 기존 도구별 입력 검증 유지 |
| 실행 담당 | API는 선택 결과를 JSON으로 반환. 노드가 선택을 기록하고 입력·설정을 검사한 뒤 도구·에이전트를 호출하고 결과를 기록 |
| 형식 검증 | 원본 응답의 `text`를 `TypeAdapter`로 검증. 선택 인자는 JSON으로 읽은 뒤 실제 도구 입력·설정에 대조 |
| 사용량·오류 | 원본 SDK 응답·HTTP 요청·응답을 추적 기록에 저장. 검증 성공 시 모델명·토큰·경과 시간을 `model_usage`로 반환. 검증·통신 오류는 호출자에게 전달 |
| 실행 자료 | 서버 응답 저장과 이전 응답 ID 자동 연결을 사용하지 않음. 매 호출의 메시지·동적 도구 조건은 현재 실행 상태에서 구성 |

`create_model()`은 `SETTINGS_BASE_URL`의 주소와 Responses API를 사용하며, 기본 주소는 OpenAI 공식 API다. GMS 연결 설정은 [설치·설정](../../README.md#설치설정)을 따른다.
현재 모델에서 지원하지 않는 `temperature`는 전송하지 않는다. 
SDK의 `raw`, `parsed`, `parsing_error` 반환값은 호출 중에만 사용하며 실행 상태나 모델 응답의 필드로 저장하지 않는다.

## 3 노드별 추가 입력

공통 업무 노드는 진입당 모델을 1회 호출한다. 작업 목적 파악은 목표·조건을 정리한 뒤 항상 작업 진행 판단으로 이동한다. 진행 판단만 현재 정보의 충분성과 필요한 정보를 결정한다. 작업 선택 및 실행은 그 판단에 따른 도구·하위 에이전트·입력 인자 선택에만 모델을 사용하고 호출 결과를 기록한 뒤 작업 진행 판단으로 이동한다. 보고서 각 역할의 응답 작성은 자기 산출물의 작성과 검토를 별도 호출한다. 후속 작업이 필요하면 같은 역할의 진행 판단에 작성·검토 이력을 제공한다. 진행 판단이 추가 자료 확보 또는 확보한 자료로 재작성할지를 결정하며, 구체적인 도구·인자는 작업 선택에서 정한다. 책임별 호출과 수정 기준은 [보고서 생성 흐름](../agent/report.md)을 따른다.

보고서 전용 호출은 `report_messages`가 분석 해석 지침과 [보고서 지침](../../src/instructions/analysis-report.md),
보고서 근거 범위 기준, 이번 호출의 작업과 자료 목록을 시스템 프롬프트로 구성한다.
사용자 프롬프트에는 실행 상태의 요청·실행 정보·결과 이력과 허용된 상세 뷰를 제공한다.
각 작성·검토 호출은 참조 ID로 지정된 입력을 사용한다. 필요한 추가 조회·가공은 해당 에이전트의 공통 작업 선택 및 실행에서 수행한다.
조회 자료·출처·판단은 실행 상태에 보관한다. 해석 지침을 적용하기 위한 별도 모델 호출 단계는 없다.

| 단계 | 조립 함수 | 추가 입력 | 판단 목적 |
| --- | --- | --- | --- |
| 작업 목적 파악 | `interpret_messages` | 호출 출력을 제외한 이력, 역할별 시각화 뷰 목록 | 확인된 목표·조건 구체화 |
| 작업 선택 및 실행 | `selection_messages` | 최근 진행 판단을 포함한 전체 결과 이력, 실행 조건, 조회 자료 목록, 역할별 시각화 입력 조건, 도구 명세 | 진행 판단이 정한 정보를 확보할 도구·에이전트와 인자 선택 |
| 작업 진행 판단 | `decide_messages` | 작성·검토를 포함한 전체 결과 이력, 실행 조건, 조회 자료 목록, 요청 처리·시각화 역할의 뷰·입력 조건 | 정보의 충분성·필요한 정보 판단과 추가 작업·응답 작성·질문 선택 |
| 응답 작성 | `compose_messages` | 전체 결과 이력, 실행 조건 | 근거·한계를 설명하고 산출물 선택 |
| 사용자 정보 요청 | `ask_messages` | 호출 출력을 제외한 이력 | 사용자가 제공할 필수 정보 질문 |

- **호출 출력 제외:** `decision == "call"`인 기록의 `output`만 제거한다. 호출 ID·인자·이유·성공 여부와 다른 판단 기록은 유지한다.
- **전체 결과 이력:** 공통 노드에는 성공·실패·검증 거부를 모두 포함한다. 후속 계산·공개 후보는 성공한 호출 결과에서 선택하며 실패·부적합 결과는 제외한다. 보고서 선정·초안은 별도 검토 통과가 필요하다. 인사이트 작성·검토 입력에서는 검토를 통과하지 않은 뷰별 설명 초안을 제외하며, 원본 이력은 State에 보존한다.
- **계산 원본:** `input_result_id`로 찾는다. 성공한 하위 에이전트의 반환 이력에서도 자료를 찾으며 원본은 실행 상태에 유지한다.
- **실행 조건:** `execution.event`, `version`, `budget`, `error`를 제공한다.
- **이번 작업의 진행 판단:** 작업 선택 입력은 기존 `results`의 최근 진행 판단 기록을 별도 구역에도 제공한다. 다음 단계와 필요 정보·이유를 그대로 읽으며 전달용 State 필드를 추가하지 않는다.

## 4 역할과 상황별 분기

아래 항목은 **작업 선택 및 실행 노드가 다음 작업을 선택할 때** 제공한다. 역할 지침은 별도로 모든 단계에 적용한다.

| 자료·설명 | 전달 방식 | 사용자 요청 처리 | 데이터 분석 결과 해석 | 데이터 시각화 | 보고서 세 역할 |
| --- | --- | :---: | :---: | :---: | :---: |
| 조회 자료 목록·진행 판단에 따른 작업 선택 지침 | 프롬프트 | 제공 | 제공 | 제공 | 제공 |
| 조회·계산 설명과 입력 명세 | 시스템 프롬프트의 도구 명세 구역 | 제공 | 제공 | 제공 | 제공 |
| 시각화 선택 지침·뷰·입력 조건 | 프롬프트 | 제공 | — | 제공 | 보고서 전용 기준 |
| 시각화 도구 사용 지침·입력 명세 | 시스템 프롬프트의 도구 명세 구역 | 제공 | — | 제공 | — |
| 전문 에이전트 설명·목표 입력 명세 | 시스템 프롬프트의 도구 명세 구역 | 제공 | — | — | — |

도구 명세는 실제 실행 도구의 설명·입력 정의에서 매 선택 호출마다 자동 생성하며 별도의 설명 사본을 관리하지 않는다. 조회·시각화 입력 명세는 현재 실행 상태로 만든 도구 스키마를 복사하며, 이벤트별 허용 뷰도 이 명세에 포함한다. 계산 도구의 실제 `data` 입력은 모델 선택 명세에서 `input_result_id`로 표현하며, 호출 시 노드가 성공한 호출 결과에서 자료를 찾는다. 전문 에이전트는 `goal`만 받는다. 작업 선택의 반환값에는 호출 생략을 두지 않는다. 자료가 충분한지는 앞선 진행 판단에서 결정해 응답 작성으로 이동한다. 비교표 렌더러는 응답 작성 코드에서 호출한다.

**작업 목적 파악 노드**에서는 요청 처리·시각화 역할에 시각화 선택 지침과 뷰 목록만 제공한다. 상세 입력 프로필과 도구 사용법은 제외한다.

**작업 진행 판단 노드**에는 모든 역할의 조회 자료 목록을 제공한다. 요청 처리·시각화 역할에는 시각화 선택 지침과 뷰·입력 조건도 제공해 현재 정보로 응답 가능한지, 조회하거나 사용자에게 확인할 정보가 무엇인지 결정하게 한다.

보고서 역할별 지침은 공통 작업 선택·진행 판단에서도 자기 산출물의 완료 기준과 추가 조회 범위를 제시한다. 설명 역할에는 확정된 뷰·설명 범위 보존을, 인사이트 역할에는 검증된 설명 범위의 요약을 요구한다. 작성·검토의 부적합 사유는 `results`로 진행 판단에 제공하며, 조회 실행 여부를 작성 노드가 결정하지 않는다. 앞 단계 에이전트를 호출하는 도구는 제공하지 않는다. 작성 입력의 `result_ids`는 앞 단계 산출물과 자기 단계의 추가 자료를 기존 이력에서 참조하며, 필드·보관 형식은 [보고서 실행 기록](../agent/report.md#5-보고서-실행-기록)을 따른다.

| 상황 | 구성 규칙 |
| --- | --- |
| 시각화 뷰 목록 | `execution.event`에 대응하는 등록 구성 `event_views`의 허용 뷰만 포함 |
| 시각화 입력 조건 | 허용 뷰의 매개변수·날짜 순서·필터 정의 제공. 선택된 조건에 해당하는 필터 허용값 추가 |
| 실행 한도 도달 | `compose`에 추가 호출·렌더링 없이 성공한 호출 결과로 종료하고 기존 산출물·한계를 보존하는 지침 추가 |

시각화 컨텍스트의 `selected`는 **기존 산출물과 호출 이력에서 수집한 조건**이다. 화면에서 클릭한 차트 표시가 아니며, 부적합했던 호출 조건도 포함될 수 있다. 이벤트별 뷰 범위에는 배포 등록값 `event_views`가 필요하다.

## 5 이력 가공과 하위 에이전트 전달

**이력 가공**은 모델 입력에만 적용하며 실행 상태 원본은 유지한다.

- 결과 기록의 `description`과 출력의 `model_usage`를 제외한다. 중첩된 하위 결과에도 적용한다.
- `mime_type == "text/html"`인 객체를 HTML 생성 완료 표시로 대체한다.
- 검증에서 거부된 결과도 판단용 입력에는 남긴다. 산출물 공개 시에는 `accepted_outputs`·`select_artifacts`가 별도로 검사한다.

**하위 에이전트**에는 선택한 하위 작업 목표, 상위의 조건·대화·이벤트·누적 예산을 전달한다. 새 실행 ID를 부여하고 `results=[]`, `response=None`으로 시작한다. 따라서 상위의 결과 이력과 공개 산출물은 자동으로 상속되지 않는다. 하위 반환값은 상위 `results`의 호출 결과로 기록한다. [하위 실행 상태 생성](../../src/state.py)

보고서 세 역할의 순차 실행은 이 하위 호출 경로를 사용하지 않는다. 동일한 동의 State에서 이전 단계의 검토 결과와 산출물을 읽고, 자기 단계의 자료·판단·작성 이력을 추가한다. 따라서 단계 전환 때 결과 이력·누적 예산을 초기화하거나 전달용 사본을 별도로 보관하지 않는다.

## 6 현재 지원 범위

| 항목 | 현재 상태 |
| --- | --- |
| 화면·선택 차트 | 전용 실행 상태 필드가 없음. 실제 대화와 기존 공개 산출물을 사용 |
| 대화·결과 길이 | 자동 요약, 최근 이력 제한, 입력 토큰 예산, 결과 행 수 제한 없음 |
| 요청별 자료 선별 | 조회 자료 목록은 전달받은 전체 목록 사용. 지침은 노드·역할로 선택하며 시각화 뷰는 이벤트로 추가 제한 |
| 실행 상태의 시스템 메시지 | 원래 API 역할로 전달하지 않고 `user` 본문 안에 `system` 역할 표시와 원문으로 포함 |
| 보완 호출 식별 | 현재 선택 응답에 `retry_of` 필드와 해당 프롬프트 지침은 없음 |
| 진행 안내·응답 작성 | 단계 시작 안내는 런타임의 고정 문구다. 일반 업무의 작성 결과는 최종 응답으로 반환하고 종료한다. 보고서 역할의 작성·검토 보완은 진행 판단으로 되돌아간다. [실행 흐름](../agent/workflow.md#21-사용자-요청의-진행-안내와-결과-전달) 참조 |

설계상 보관·연동 기준은 [컨텍스트 명세](../agent/context.md), 필드·쓰기 책임은 [실행 상태 명세](../agent/state.md)를 따른다.

2026-11-06 사전 호환성 확인에서는 `gpt-6-sol`의 Responses API로 응답 6종과 조회·계산·하위 에이전트 선택 3종이 통과했다. 이는 합성 입력을 사용한 모델 경계 확인이다.

2026-11-09 분석 해석 지침 적용 후 프롬프트·업무 노드·보고서·보고서 왕복·그래프·실행 상태·런타임 회귀 58개와 변경 Python 파일의 Ruff 검사·포맷 검사가 통과했다. 이는 세 보고서 역할을 분리하기 전의 외부 모델·DB 대체 실행 연결 검증이다.

같은 날 실제 설정 모델 `gpt-6-sol`과 합성 자료로 해석 2건, 보고서 작성·검토 1건을 확인했다.
점수 상승과 활동 증가의 구분, 지역 맥락 없는 활동 유지 해석, 뷰별 근거 범위와 요약을 확인했다.
보고서는 근거와 승인된 선정을 준비한 상태에서 작성·검토·퀵 인사이트를 실행했다.
자료 탐색·선정 판단·실제 DB 연동과 전체 지역의 해석 품질을 검증한 결과는 아니다. 이 결과를 새 보고서 역할별 평가나 전체 순차 실행의 검증 결과로 대신하지 않는다. 구조 변경 후 검증 상태는 [실행 안내](../../README.md)를 따른다.
