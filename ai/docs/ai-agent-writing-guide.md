# AI Agent 문서 작성 지침

수정일: 2026-10-30. 문서 편집에 적용하며 Agent 업무 지침과 구분한다.

## 1. 작성 원칙

- [문서 목록](README.md)의 현행 명세와 최신 사용자 수정본을 기준으로 한다. 요청과 무관한 내용·명칭·양식은 유지한다.
- 현재 기능·입출력·실행 조건을 직접 쓴다. 확정 요구사항, 제안, 예시, 미확정 사항을 구분하고 근거 없는 용도·효과·수치를 넣지 않는다.
- 제목과 문장은 짧게, 문단은 하나의 주제로 쓴다. 중복·당연한 설명·편집 과정·불필요한 단서를 삭제한다. 축소할 때는 항목 자체의 필요성도 검토하되 필수 조건·예외·입출력 계약은 보존한다.
- 동작은 주체·조건·대상·결과가 드러나게 쓴다. 용어·약어는 처음에 정의하고, 비슷한 개념의 차이를 밝힌다. ‘처리·반영·정책’ 같은 포괄어만으로 설명하지 않는다.
- 노드명은 [실행 흐름의 명칭](ieumi-agent-workflow-design.md#2-agent-공통-실행-흐름)으로 통일한다. 본문·표·그림에는 한글명을 사용하고, 영어명은 코드 식별자가 필요한 곳에만 쓴다.
- 대상의 의미와 필요성을 먼저 설명한다. API는 호출 목적 → 입력의 출처 → 처리·응답 → 호출자의 후속 행동 순서로 쓴다. ID·버전은 확보·전달·보관·사용을 연결한다.
- 책임은 기능 명세·실행 흐름·State에 근거해 배정한다. 설계 역할과 구현 노드, Agent의 응답 작성과 서버 전달·화면 렌더링을 구분한다. 미정인 기술·연동 방식에 의존하는 책임과 필드·검증 규칙도 미정으로 둔다.

## 2. 구조와 서식

- 같은 위계에는 같은 분류 기준을, 반복 대상에는 같은 항목과 설명 순서를 적용한다. 공통 항목과 대상 전용 항목을 구분하고 해당 없는 항목은 생략한다.
- 명세는 Markdown 표로 쓴다. 한 열에는 하나의 속성을 두고, ID와 명칭, 검사 항목과 성공 기준은 별도 열로 둔다. 구분자·괄호로 독립 속성을 합치지 않는다.
- Agent는 역할 → 입력·출력·호출·종료 → 실행 예시 순서로 설명한다. 중간 응답과 최종 응답의 시점·내용·후속 처리를 구분한다.
- 명세는 한 곳에서 관리하고 다른 문서에서는 링크로 참조한다. 그림은 설명 바로 아래에 원본 위치와 함께 두고 비율을 유지한다.

## 3. 평가 문서

- 측정 관점 → 대상별 검사·지표 → 지표 정의·측정·합격 기준 순서로 구성한다. 도구·모든 개별 노드·Agent 전체를 각자의 책임에 맞게 평가하며, 전체 성공으로 개별 평가를 대신하지 않는다.
- 기능 검사는 입력·출력·State·행동으로 분류한다. 수행 여부와 결과의 정확성, 분기 판단과 실행 연결, 직접 생성한 내용과 하위 결과의 전달·보존을 구분한다. 계약 밖의 원본 확인·접근 통제·하위 오류 책임을 임의로 배정하지 않는다.
- 요구사항 → 검사 → 지표 → 집계·합격 기준을 ID로 연결한다. 조건표의 모든 행과 본문의 필수 행동을 검사에 연결한다. 독립적으로 실패할 수 있는 조건은 별도 검사로 나누며 같은 판정을 중복 정의·집계하지 않는다.
- 각 검사에 확인 사항, 성공 기준, 기준 자료·실행 증거·비교 절차를 명시한다. 상황별 행동은 조건 조합과 우선순위로, 정형화하기 어려운 품질은 별도 채점 기준으로 판정한다.
- 지표에는 측정 단위·분자·분모·집계 시점·예외 처리를 정의한다. 세부 검사 수가 늘어도 작업·주장 등 지표의 집계 단위는 유지한다.
- 조건의 참·거짓, 작업 완료 여부, 검사 통과 여부를 구분한다. 정보 부족에 따른 질문이나 올바른 거부도 기대 행동에 따라 판정한다.
- 진단용 지표와 필수 합격 지표를 구분한다. 필수 지표에는 목표값·시험 조건·합격식을 명시하고, 미정이면 확정 시점을 적는다. 현재 MVP의 완료·실패 판단에 불필요한 운영 고도화·현장 조사 항목은 제외한다.

## 4. 수정과 검수

지적된 사례와 같은 문제가 대상 문서 전체에 있는지 확인하고, 관련 표·예시·오류·흐름·ID 참조를 함께 수정한다. 수정 후 전체를 다시 읽어 명세 간 일치, 수치·단위·집계 기준, 링크·그림 경로를 확인한다.
