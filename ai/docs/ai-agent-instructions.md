# AI Agent 작업 지침

수정일: 2026-11-06.

## 1. 가공 과정

| 단계 | 내용 |
| --- | --- |
| 원천 자료 | 업무 매뉴얼·확정 요구사항·분석 가이드라인·산출물 명세 |
| 내용 분류 | 참조 사실 / 수행 절차 / 준수 원칙 / 출력 기준 |
| 초안 작성 | 적용 대상·조건·행동·예외·완료 기준 명시 |
| 검토 | 원자료 대조, 중복·충돌·모호한 표현 확인 |
| 등록 | 지침 ID·버전·시행일·원문 근거 관리 |
| 적용 | 공통 제공 / 업무별 필수 로딩 / 조건부 추가 로딩 |

## 2. 종류와 적용

| 지침 | 주요 내용 | 적용 대상 |
| --- | --- | --- |
| 공통 운영 지침 | 사실·추정·미확인 구분, 출처, 업무 범위·권한 | 모든 관련 모델 호출 |
| 분석 해석 지침 | 분석 근거, 단위·기간·비교 기준, 비전문가용 표현·한계 | 데이터 분석 결과 해석 Agent. 다른 Agent가 직접 해석을 작성하는 경우에도 적용 |
| 시각화 지침 | 목적에 맞는 표현, 단위·축·범례·출처, 오해 가능성 | 데이터 시각화 Agent |
| 요청 처리 지침 | 목표·완료 조건, 도구·Agent 호출, 질문·추가 조회, 응답 작성에서 중간 결과 제공·최종 결과 통합 | 사용자 요청 처리 Agent |

공통 지침은 매 호출 제공한다. 업무별 지침은 해당 배포 구성의 버전을 로딩하고 지도 표현 기준 등은 해당 작업 진입 시 추가한다. 지침은 유사도 검색·Top-k에 의존하지 않고 ID로 로딩한다. 관리 위치는 [컨텍스트](ai-agent-context.md) 명세를 따른다.

지침을 제공받는 범위와 각 단계가 수행할 책임을 구분한다.

| 단계 | 지침에 명시할 내용 |
| --- | --- |
| 작업 목적 파악 | goal·constraints에 목적·확인된 대상·조건을 구체화하는 방법. 시스템이 요청을 구성한 이벤트 실행은 이 노드를 생략 |
| 작업 선택 및 실행 | 필요한 기능·입력 인자·선택 이유, 호출 조건, 이번 작업의 결과 검증·재시도 기준 |
| 작업 진행 판단 | 전체 목표에 부족한 내용과 근거를 decision·reason에 기록. 진행 방향을 정하고 구체적 도구 선택은 작업 선택 및 실행 노드에 위임 |
| 응답 작성 | 직접 작성하는 설명·해석의 근거와 한계, 하위 결과 통합 시 수치·의미·출처 보존 |
| 사용자 정보 요청 | 미확보 필수 정보와 사용자가 답할 질문의 대응 |

사용자 요청 처리 Agent의 응답 작성 지침에는 공개할 중간 산출물 선택, 남은 작업 안내, 최종 응답에서 유효한 기존 결과 유지와 변경 이유 설명을 포함한다. 세부 흐름은 [실행 흐름](ieumi-agent-workflow-design.md)을 따른다.

## 3. 관리와 검증

시각화의 선택 설명·입력 명세와 검증 도구는 State의 `execution.event`에 배정된 뷰 목록을 사용한다. 이벤트와 목록은 모델이 지정하는 도구 인자가 아니다. 허용 범위와 오류 계약은 [기능 명세 §2.3](ieumi-agent-components.md#23-시각화-검증)을 따른다.

현재 시각화 지침 원문은 [작업 선택](../src/instructions/visualization-selection.md)과 [도구 사용](../src/instructions/visualization-tool.md)이다. 사용자 요청 처리·시각화 Agent의 작업 목적 파악에는 선택 지침·뷰 요약을, 작업 선택에는 두 지침·공유 입력 프로필·확인된 조건의 상세값을 제공한다. 검증·진행 판단·응답 작성·질문 작성에는 실제 요청·호출 결과를 사용하며 전체 지침·카탈로그를 반복 제공하지 않는다. 공통 운영 지침은 계속 매 호출에 적용한다. 선택 설명과 검증 규칙의 원본은 등록 카탈로그다. 실행 연결·검증 범위는 [Tableau 시각화 실행](TABLEAU.md)을 따른다.

- 지침 ID·적용 대상·버전·시행일·원천 자료와 위치·변경 사유·검토 상태를 기록한다.
- 검토한 지침·도구·API 구성을 함께 배포하고 실행에 execution.version을 기록한다. 배포 버전에서 실제 적용 지침을 확인할 수 있게 관리한다.
- 변경 시 정상·정보 누락·조건 충돌·근거 부족 사례의 기대 행동을 확인한다.

| 주체 | 검사 범위 |
| --- | --- |
| 코드 | 자료형·필수값·권한·배포 구성·중복 실행·노드별 쓰기 범위 |
| 작업 선택 및 실행 노드 | 이번 작업의 대상·조건·요구 정보 충족 여부 검증, 검증·재시도를 별도 results 기록으로 보존 |
| 작업 진행 판단 노드 | 요청 조건·자료·호출 결과를 바탕으로 추가 작업이나 사용자 정보가 필요한지 판단 |
| 응답 작성 노드 | 확보한 근거에 맞게 설명·해석을 작성하고 통합할 내용의 의미·한계를 보존 |
| 담당자 | 현장 사실 확인, 업무 판단 |

지침 제공만으로 접근 권한과 실행 조건을 충족한 것으로 처리하지 않는다. 필수 출력 항목과 조건은 시스템 규칙으로도 검사한다.

## 4. 기록·공개 지침

시스템 지침은 messages의 시스템 메시지로, 실제 사용자 요청·답변은 사용자 메시지로 구분한다. 자동 실행의 goal을 사용자 발화로 복제하지 않는다. 선택·판단 근거는 검토 가능한 짧은 요약으로 results에 기록한다.

응답의 출처·한계·미해결 사항은 content 또는 산출물 내용에 포함한다. 진행 안내 갱신 시 유효한 공개 산출물을 보존한다. 검증·재시도·공개 작성 책임과 쓰기 범위는 [State](ieumi-agent-state.md)를 따른다. 노드별 모델 컨텍스트 구성 방침은 이후 확정한다.
