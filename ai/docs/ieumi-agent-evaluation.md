# AI Agent MVP 평가

상태: 검토용 초안. 수정일: 2026-11-02.

## 0. 개요

본 문서는 **측정 관점 → 평가 대상 → 요구사항·검사·성공 기준 → 지표·집계 → 합격 판정**을 연결한다. §1~3에서 관점과 대상별 검사를 정하고, §4~5에서 판정·측정 방법을 정의한다. §6의 서비스 연동은 제출 단계별 합격 범위에 포함하고, §7의 업무 효과는 별도로 보고한다. 미확정 기준과 책임은 §8에서 관리한다.

- 요구사항: 충족할 내용
- 검사 항목: 요구사항의 충족 여부를 확인하기 위해 하나씩 판정하는 구체적인 확인 사항
- 지표: 판정 결과를 측정한 값

## 1. 측정 관점

| 관점 | 정의 |
| --- | --- |
| 기능 품질 | 요구한 처리 규칙과 산출물 기준을 충족하는 정도 |
| 운영 품질 | 정해진 시간·비용 한도 안에서 안정적으로 실행되고, 같은 조건에서 요구된 결과를 반복 제공하는 정도 |
| 업무 효과 | 서비스 사용으로 담당자의 실제 업무가 개선되는 정도 |

## 2. 평가 대상

평가 단위는 도구 → Agent 개별 노드 → Agent 전체의 세 단계로 구분한다.

현재 MVP(Agent 3가지)를 대상으로 한다.

### 2.1 도구

평가 대상: 도구(데이터 조회, 데이터 가공, 시각화 렌더링)의 개별 호출. 저장 도구는 채택하고 계약을 정의한 경우에만 T04로 평가한다. 저장 기능의 서비스 연동 결과는 도구 채택 여부와 관계없이 S04에서 평가한다.

| 관점 | 평가 의미 |
| --- | --- |
| 기능 품질 | 정해진 입력을 처리 규칙에 따라 정확히 처리하는가. 오류와 실제 반영 상태를 올바르게 반환하는가. |
| 운영 품질 | 개별 호출이 얼마나 빠르고 안정적으로 처리되는가. |

### 2.2 Agent 개별 노드

평가 대상: Agent 공통 실행 흐름을 구성하는 모든 구현 노드. 아래는 [실행 흐름](ieumi-agent-workflow-design.md)의 역할이며, 구현 노드와의 대응은 검사 전에 확정한다.

- 작업 목적 파악
- 작업 선택 및 실행
- 작업 진행 판단
- 응답 작성
- 사용자 정보 요청

| 관점 | 평가 의미 |
| --- | --- |
| 기능 품질 | 해당 노드의 역할을 정확히 수행하는가. 허용된 State 변경을 만드는가. 작업 진행 판단이 확보 자료·호출 상태·남은 작업에 맞는가. |
| 운영 품질 | 노드 실행이 얼마나 빠르고 안정적인가. 같은 입력·State에 대해 요구된 결과를 반복 제공하는가. |

### 2.3 Agent

평가 대상: 각 Agent가 수행하는 하나의 작업.

| 관점 | 평가 의미 |
| --- | --- |
| 기능 품질 | 작업의 완료 조건을 충족하는가. 중간·최종 응답과 산출물·근거·미해결 사항·실행 상태를 정확히 제공하는가. |
| 운영 품질 | 작업에 시간과 비용이 얼마나 드는가. 얼마나 안정적으로 실행되고 요구된 결과를 반복 제공하는가. |

## 3. 요구사항

각 요구사항에 대해 **검사 항목**과 **성공·실패 기준**을 작성한다.

#### 요구사항 ID

아래 코드는 요구사항을 찾기 위한 식별 접두사다. 평가 대상의 위계는 §2, 측정 관점은 §1을 따른다. 대상·측정 관점·요구사항 ID는 평가 기록의 별도 항목으로 관리한다. 기능 품질에서는 도구에 T, 노드에 N, Agent 전체에 A·F, 서비스 연동에 S를 배정한다. 운영 품질의 O는 §5.2에서 각 대상에 배정한다.

| 코드 | 의미 |
| --- | --- |
| T | 도구 요구사항 |
| N | 노드 요구사항 |
| A | Agent 요구사항 - 작업 결과 (필수 산출물·근거·완료 조건) |
| F | Agent 요구사항 - 실행 흐름 (노드 연결·대기·재개·장애·종료 처리) |
| S | 서비스 연동 요구사항 |
| O | 운영 요구사항 (시간·비용·안정성·재현성) |

#### 검사 ID

기능 검사 ID는 검사 대상의 속성(I·O·S·B)과 항목 번호를 붙인다. 여러 요구사항에 적용하는 공통 검사는 대상 코드(T·N·A)를, 전용 검사는 요구사항 ID를 접두사로 쓴다. 공통 검사의 실제 배정은 요구사항 표와 적용 대상 열을 따른다.

| 코드 | 의미 |
| --- | --- |
| I | 전달받은 입력값과 수용·거부 |
| O | 반환한 값·산출물·판정·안내 내용 |
| S | State에 기록·보존·복원한 값 |
| B | 실제 수행한 행동과 금지 행동의 부재 |

출처 연결·근거 일치·분기 판단·진행 장애 탐지는 출력의 검사 항목이다. 지표는 검사 결과의 집계 목적에 따라 구분하며, 작업 완료는 §4.3에서 종합 판정한다.

- 시나리오에는 이 검사 목록의 실제 입력·대상·기대값·증거를 채운다.
    - 시나리오에는 실제 도구·구현 노드·Agent 이름을 기록한다.
    - 적용 조건에 해당하지 않는 검사는 제외 사유를 남기며 통과로 세지 않는다.
- 각 행은 하나의 확인 사항을 판정한다.
- ‘필드별·항목별·주장별’ 검사는 같은 기준을 각 대상에 반복 적용하며, 검사 ID와 필드명·항목 ID를 함께 기록한다.
    - 예를 들어 N01에 적용한 N-S.1의 request.goal과 request.constraints는 각각 판정한다.
- 숫자를 표기하지 않는 경우 해당 구분의 모든 검사를 포함한다.
    - Ex: N-S = N-S.1~.3 전체
- 검사에는 명세상 담당 구성요소와 책임 근거를 연결한다. 담당이 미확정이면 개별 노드·도구에 임의 배정하지 않고 §8에서 확정한다.

### 3.1 도구

입출력 규칙은 [도구 명세](ieumi-agent-components.md#2-도구-명세)를 따른다. T-I는 각 도구 계약에 명시된 입력 검사에만 적용한다. T04는 저장 도구를 채택한 경우에 적용한다. 채택 여부·입출력 계약·검사 범위는 §8에서 확정하며, 도구가 내용 검증까지 수행한다고 가정하지 않는다.

| 요구사항 ID | 도구 | 충족할 내용 | 대조 대상 | 적용 검사 |
| --- | --- | --- | --- | --- |
| T01 | 조회 | 요청 조건에 맞는 자료와 조회 상태를 반환한다. | 반환 레코드·조회 요약·출처·상태 | T-I·T-O |
| T02 | 가공 | 지정한 연산·결합·결측·단위·반올림 규칙으로 처리한다. | 가공 결과값·단위·행 수 | T-I·T-O |
| T03 | 렌더링 | 입력 자료와 표현 설정에 맞는 실제 시각화를 반환한다. | 생성한 차트·표·지도와 적용 설정 | T-I·T-O, T03-O.1 |
| T04 | 저장 | 전달받은 내용을 지정 대상·버전으로 저장하고 실제 상태를 반환한다. | 실제 저장값·대상·버전·반환 상태 | T-I·T-O, T04-B.1 |

| 검사 ID | 검사 항목 | 판정 단위 | 성공 기준 | 대응 지표 | 판정 방법 |
| --- | --- | --- | --- | --- | --- |
| T-I.1 | 유효 입력 수용 | 입력 | 해당 도구 계약의 수용 조건을 충족한 요청을 수용한다. | 입력 처리 정확도 | 입력 대조 |
| T-I.2 | 잘못된 입력 거부 | 거부 조건 | 해당 도구가 검사하도록 명시된 조건을 위반한 요청을 거부한다. 임의 값으로 바꾸어 실행해도 X다. | 입력 처리 정확도 | 입력 대조 |
| T-O.1 | 처리 결과 정확성 | 처리 결과 항목 | 실제 조회·가공·렌더링·저장 결과가 명세·입력에서 도출한 기대값과 같다. 수치는 원자료·독립 계산값과 허용 오차 안에서 일치한다. | 출력 처리 정확도 | 값 대조 |
| T-O.6 | 반환 내용 정확성 | 반환 필드 | 반환값이 실제 처리 결과와 해당 필드의 계약에 맞는다. 실제 처리 오류는 T-O.1, 처리 상태는 T-O.2에서 판정한다. | 출력 처리 정확도 | 값 대조 |
| T-O.2 | 처리 상태 구분 | 호출 | 정상·자료 없음·실패·확인 불가를 실제 결과대로 반환한다. | 출력 처리 정확도 | 값 대조 |
| T-O.3 | 출처 제공 | 필수 출처 | 해당 자료의 주소 또는 내부 참조를 제공한다. | 출력 처리 정확도 | 출처 대조 |
| T-O.5 | 출처 정보 일치 | 출처의 대상·시점·버전 각각 | 반환한 출처 정보가 처리에 사용한 자료의 정보와 같다. | 출력 처리 정확도 | 출처 대조 |
| T03-O.1 | 실제 산출물 생성 | 산출물 | 명세뿐 아니라 실제로 열 수 있는 차트·표·지도를 생성한다. | 출력 처리 정확도 | 산출물 대조 |
| T04-B.1 | 중복 저장 방지 | 저장 요청 ID | 같은 저장 요청 ID를 반복해도 한 번만 반영한다. | 행동 준수율 | 저장 대조 |

실제 적용 조건·표시 설정·저장값은 T-O.1, 반환한 입력값·페이지 정보·설정·저장 메타데이터는 T-O.6으로 확인한다. 출처의 제공·정보 일치는 T-O.3·O.5로 판정한다. 참조를 통한 실제 조회는 T01의 조회 결과와 S04-O.1의 서비스 접근 검사로 확인한다.

### 3.2 Agent 개별 노드

| 요구사항 ID | 노드 역할 | 충족할 내용 | 관련 State |
| --- | --- | --- | --- |
| N01 | 작업 목적 파악 | goal에 목적·대상·범위를 서술하고 constraints 정리. 이벤트 실행은 생략 | request·results |
| N02 | 작업 선택 및 실행 | 작업·대상·인자를 선택·실행하고 이번 작업의 정보·조건 충족 여부 검증·재시도 | results·response |
| N03 | 작업 진행 판단 | 전체 목표에 대한 충분 여부·부족한 내용과 진행 방향을 decision·reason에 기록 | results·response |
| N04 | 응답 작성 | 근거·한계를 포함한 설명과 공개 산출물을 response로 구성하고 작성 이력 보존 | results·response |
| N05 | 사용자 정보 요청 | 부족한 필수 정보를 구체적인 question 응답과 작성 이력으로 구성 | results·response |

노드는 제공된 [작업 지침](ai-agent-instructions.md)과 권한 조건 아래에서 맡은 역할을 수행하는지 검사한다. 지침 준수는 아래 역할별 출력·행동 기준으로 판정하며, 지침 로드·주입은 F01에서 확인한다.

관련 State는 결과가 연결되는 영역이다. 논리적 쓰기 범위는 [State §2](ieumi-agent-state.md#2-노드별-쓰기-범위)를 따른다. 읽기·컨텍스트 선별 정책과 구분하며 직접 기록과 실행 계층 공통 기록의 실제 담당은 구현 시 확정한다. 실행 메타데이터는 F01-S.1·F02-S.1에서 확인한다. 역할이 여러 개인 구현 노드에는 해당 역할의 검사를 모두 적용한다.

N-O.1~.5는 N02·N04가 직접 생성·변경한 내용, N-O.6·O.8은 선택·작성한 참조, N-O.9는 하위 결과의 전달·통합에 적용한다. 하위 결과 생성 오류는 해당 도구·Agent에 귀속하고, N02가 맡은 요구 정보·조건 검증 누락은 별도로 검사한다. N03은 [실행 흐름 §2](ieumi-agent-workflow-design.md#2-agent-공통-실행-흐름)의 작업 진행 판단 책임만 검사한다. N04에서 새로 작성하는 내용의 정확성은 N-O로 평가한다. 생성 후 제공·저장·게시 전 내용 검사의 기준·수행 주체·시점은 §8에서 확정하고 A-B.2·S01-B.2·S04-B.1에 연결한다. N03의 작업 진행 판단을 생성 후 내용 검사로 대신하지 않는다.

| 검사 ID | 검사 항목 | 적용 대상 | 판정 단위 | 성공 기준 | 대응 지표 | 판정 방법 |
| --- | --- | --- | --- | --- | --- | --- |
| N-S.1 | State 변경 | 쓰기 책임이 확정된 노드 | 담당 변경 필드 | 담당 필드에 실제 입력·노드 결과와 일치하는 값을 작성한다. | State 변경 정확도 | State 대조 |
| N-S.2 | State 보존 | 모든 노드 | 노드가 변경하지 않아야 할 필드 | 담당 범위 밖의 값과 다른 노드의 기존 이력을 바꾸지 않는다. 진행 안내 갱신 시 유효한 공개 산출물을 보존한다. | State 변경 정확도 | State 대조 |
| N-S.3 | 노드 이력 기록 | 모든 노드 | 결정·호출·검증·재시도·응답 작성 기록 | 실제 수행·판단을 results에 남긴다. 부족한 내용은 decision, 출처·실제 자료 버전은 해당 output에 보존한다. | State 변경 정확도 | State 대조 |

조건 O는 충족 확인, X는 미충족 또는 확인 불가, —는 판단 불필요다. X에는 미충족·확인 불가를 구분해 적는다. 조건값과 검사 통과 여부는 별개다.

### 4.3 합격 판정

작업 완료는 최종 제공에서 요청한 필수 산출물을 모두 제공하고(A-O.1), 제공 결과가 필수 검사를 통과했으며(A-O.2), 필수 한계를 명시하고(A-O.3), 실제 검증을 수행한 경우(A-B.2)다. A-O.2의 필수 검사에는 적용되는 수치·근거·출처·표현 목적·산출물 간 일치 검사를 포함한다. 중간 응답의 실패 여부는 사례 합격에서 별도로 반영한다.

- 사례: 중간·최종 응답을 포함해 적용되는 기능 검사를 모두 통과하고 제공 범위·실행 상태가 기대값과 같아야 한다. 정상적인 중간 응답·질문·거부·부분 반환에서는 전체 제공을 요구하는 A-O.1의 적용 조건에 해당하지 않으므로 제외하고 상황별 검사를 적용한다. 제공 전 검사 수행이 없다고 확인되면 실패이며, 담당·절차가 미정이어서 판단할 수 없으면 미판정이다.
- 대상: 배정된 필수 사례를 모두 통과해야 한다. 필수 운영 목표가 있는 대상은 §5.2도 충족해야 한다.
- MVP: 채택한 모든 도구·구현 노드·Agent와 해당 제출 단계의 서비스 연동 검증을 통과해야 한다. 저장 도구 미채택은 T04 제외 사유이며 S04 제외 사유가 아니다.

확인된 실패가 있으면 불합격, 실패 없이 필수 미판정이 남으면 보류다. 권한 위반·허용하지 않은 저장·중복 저장·수치나 근거 조작·개인 판단·원인 단정·분석 모델 임의 변경은 한 건도 허용하지 않는다.

같은 대상·실행·응답·항목의 판정은 한 번 기록한다. 대상별로 따로 집계하며 다른 지표를 합산하지 않는다. 근거 일치율은 수치·설명·산출물 간 비교를 주장 ID에, 근거 연결률은 출처 검사를 출처 필요 항목 ID에 연결한 뒤 항목별 적용 검사를 종합한다. 제외는 이유와 함께 분모에서 빼고, 미판정은 통과로 세지 않으며 건수를 보고한다. ‘판정한’ 검사를 분모로 쓰는 지표는 미판정을 분모에서 제외하고, 전체 실행·작업·항목을 분모로 쓰는 지표는 미판정도 분모에 남긴다. 분모가 0이면 산출 불가로 표시한다. 모든 지표는 해당 평가 실행 묶음이 끝난 시점에 집계한다.

업무 완료율의 집계 시점은 실행 전에 정한다. 대기·진행·거부·취소·완료 확인 불가도 분모에 남기고 구분해 보고한다. 올바른 미완료 행동이 사례 합격이더라도 업무 완료로 세지 않는다.

| O02 | O02.1 | 실행 실패율 | 기술적 장애로 실패 종료한 실행 수 / 종료한 실행 수. 정상 거부·취소는 실패에서 제외 | 필수 대상의 실패율 ≤ 정한 최대 비율 |
| O04 | O04.1 | 반복 충족률 | 같은 조건의 핵심 사례를 지정 횟수 반복하고, 매회 필수 기능 검사를 모두 통과한 사례 수 / 반복 평가에 배정한 사례 수 | 반복 충족률 100%. 미실행·미판정이 있으면 보류, 확인된 실패가 있으면 불합격 |

Agent 전체를 O01~O03의 필수 운영 합격 대상으로 두고, 도구·노드는 기본적으로 원인 진단용으로 측정한다. 별도 목표가 필요한 도구·노드만 필수 대상으로 지정한다. O04는 노드·Agent의 필수 핵심 사례에 적용한다. 장애를 주입한 시험은 일반 실패율과 분리한다. 집계 시점까지 첫 유효 응답·종료가 없는 실행은 해당 지연 통계에서 제외하되 건수·경과 시간을 보고하며, 한도를 넘겼으면 시간 기준 실패, 아직 판단할 수 없으면 보류다. 입력 대기는 시간 한도에서 제외한다. 기술적 실패 없이 정상 거부·취소한 실행은 O02 분모에 포함하고 분자에서 제외하며 종료 상태별 건수도 보고한다.

반복 시 입력·State·자료·지침·권한·모델 설정·도구 응답 조건을 고정한다. 일관성은 사전에 허용한 분기·호출, 수치 허용 오차, 근거·필수 내용·종료 상태의 충족 여부로 판단한다. 같은 기준을 충족하는 문장 표현과 작업 순서의 차이는 허용한다. 모든 반복이 같은 오답이면 실패다. 반복 횟수·시간과 비용 목표값·자료량·동시 실행 수·모델·환경·실행 수는 §8에서 확정하고 평가 실행 묶음 종료 시 집계한다.

연동 준수율은 적용 검사를 모두 통과한 실행 수 / 연동 평가 실행 수다. 실행 묶음 종료 시 집계하며 미판정 실행도 분모에 남기고 별도 보고한다. 필수 사례는 모두 통과해야 한다. 개별 기능 평가와 별도로 집계한다. 최신 공개 상태 유지에 필요한 중복·역순 알림은 S06-B.2의 필수 사례다. 분석 완료 이벤트의 대량 중복·지연과 동시 수정의 확장 시험은 MVP 핵심 흐름 검증 후 수행한다.

## 7. 업무 효과

지역 탐색 담당자 또는 같은 업무 경험자에게 동일한 자료·목표로 수작업과 Agent 사용을 비교하게 한다. 참여자별 수행 순서를 바꾸고, 검토·수정 후 같은 품질 기준을 충족한 업무끼리 비교한다.

| 지표 | 측정 방법 |
| --- | --- |
| 업무 시간 | 자료 확인부터 검토·수정 완료까지의 시간. 업무별 시간 차이의 중앙값 보고 |
| 수정 부담 | 업무당 고친 항목 수와 수정 시간. 같은 항목은 한 번 계산 |

미완료·기준 미달 업무는 별도로 보고한다. 사용자 평가를 수행하지 못하면 미측정으로 남긴다. 업무 효과는 기능 합격 조건에 합산하지 않는다.

사용자 요청 결과를 기본 해석으로 게시하지 않는 규칙은 [연동 API 초안 §3.4](ai-runtime-api-20261029.md#34-해석-결과)의 현행 설계 기준에 따라 S01-B.3으로 검사한다. 담당·절차가 미정인 검사는 미판정으로 남기고, 확정한 명세에 따라 책임과 증거를 연결한다. 저장 도구 미채택처럼 적용 대상이 없는 경우의 제외와, 필수 책임이 미확정인 경우의 미판정을 구분한다. 코드로 구현한 기능도 구현 노드의 역할로 확정되면 그 노드의 검사에 배정하며, 동일 책임을 중복 집계하지 않는다. 최종 평가 결과를 본 뒤 기준을 바꾸지 않는다.

### 8.2 결과 보고

명세·실제 자료 버전·execution.version이 가리키는 배포 구성·모델·환경, 대상별 실행 수·지표, 중간·최종 응답별 결과, 반복 사례별 통과 횟수, 실패·미판정 검사와 증거, 원인 구성요소, 미검사 노드·연결을 보고한다. 원인을 확인하지 못한 실패는 원인 미확정으로 남긴다. 서비스 연동과 업무 효과는 별도로 보고한다.
