# AI 에이전트 작업 지침

수정일: 2026-11-12.

서비스 에이전트의 업무 지침은 모델이 따라야 할 행동·판단·출력 기준이다. 업무 매뉴얼과 확정 요구사항에서 지침을 작성하고, 적용할 모델 호출과 검증 책임을 구분한다. 개발자의 문서 작성 규칙과는 다르다.

## 1. 작성 과정

| 단계 | 내용 |
| --- | --- |
| 원자료 확인 | 업무 매뉴얼·확정 요구사항·분석 지침·산출물 명세 확인 |
| 내용 분류 | 참조 사실, 수행 절차, 준수 원칙, 출력 기준으로 구분 |
| 초안 작성 | 적용 대상·조건·행동·예외·완료 기준 명시 |
| 검토 | 원자료 대조, 중복·충돌·모호한 표현 확인 |
| 등록 | 지침 ID·버전·시행일·원문 근거 관리 |
| 적용 | 공통 제공, 업무별 필수 로딩, 조건부 추가 로딩으로 구분 |

## 2. 종류와 적용

| 지침 | 주요 내용 | 적용 대상 |
| --- | --- | --- |
| 공통 운영 지침 | 사실·추정·미확인 구분, 출처, 업무 범위·권한 | 모든 관련 모델 호출 |
| 분석 해석 지침 | 분석 근거, 단위·기간·비교 기준, 비전문가용 표현·한계 | 데이터 분석 결과 해석 에이전트. 다른 에이전트가 직접 해석을 작성하는 경우에도 적용 |
| 시각화 지침 | 목적에 맞는 표현, 단위·축·범례·출처, 오해 가능성 | 데이터 시각화 에이전트 |
| 요청 처리 지침 | 목표·완료 조건, 도구·에이전트 호출, 질문·추가 조회, 최종 답변과 산출물 통합 | 사용자 요청 처리 에이전트 |
| 보고서 지침 | 역할별 산출물·근거 범위, 자기 단계의 추가 조회·작성·검토, 앞 단계 보존 | 시각화 선정·시각화 설명·퀵 인사이트 에이전트 |

공통 지침은 매 호출 제공한다. 업무별 지침은 해당 배포 구성의 버전을 로딩하고 지도 표현 기준 등은 해당 작업 진입 시 추가한다. 지침은 유사한 문서를 일부 검색하는 방식이 아니라 식별자로 지정해 로딩한다. 관리 위치는 [컨텍스트](context.md) 명세를 따른다.

지침을 제공받는 범위와 각 단계가 수행할 책임을 구분한다.

| 단계 | 지침에 명시할 내용 |
| --- | --- |
| 작업 목적 파악 | goal·constraints에 목적·확인된 대상·조건을 구체화하는 방법. 시스템이 요청을 구성한 이벤트 실행은 이 노드를 생략 |
| 작업 진행 판단 | 현재 정보의 충분성·필요한 정보와 진행 방향을 결정. next·reason을 반환하며 구체적인 도구·인자 선택은 작업 선택 및 실행에 위임 |
| 작업 선택 및 실행 | 최근 진행 판단이 정한 정보를 확보할 기능·입력 인자·선택 이유와 호출 조건. 충분성 판단이나 호출 생략을 선택하지 않음 |
| 응답 작성 | 직접 작성하는 설명·해석의 근거와 한계, 하위 결과 통합 시 수치·의미·출처 보존 |
| 사용자 정보 요청 | 미확보 필수 정보와 사용자가 답할 질문의 대응 |

사용자 요청 처리 에이전트의 응답 작성 지침에는 최종 답변에 공개할 산출물 선택, 근거·한계·미해결 사항과 유효한 기존 결과 유지·변경 이유를 포함한다. 단계 시작 안내는 모델이 작성하지 않고 런타임이 정해진 문구를 사용한다. 세부 흐름은 [실행 흐름](workflow.md)을 따른다.

## 3. 관리와 검증

현재 [분석 해석 지침](../../src/instructions/analysis-interpretation.md)은 수치 관계의 의미, 점수·활동·관계 상태의 구분, 지역 맥락의 적용 범위를 정의한다. 공통 노드와 보고서 선정·작성·검토에 같은 원문을 제공하며 각 호출은 자신의 역할·입력·출력 범위에서 적용한다. 보고서의 세 역할은 공통 수치·근거·해석 기준을 재사용하되 산출물과 판단을 각각 평가한다. 역할별 계약은 [보고서 생성](report.md), 모델에 제공하는 원문은 [보고서 지침](../../src/instructions/analysis-report.md), 실제 로딩 경로는 [모델 입력 구성](../runtime/prompts.md)에서 관리한다.

현재 시각화 지침 원문은 [작업 선택](../../src/instructions/visualization-selection.md)과 [도구 사용](../../src/instructions/visualization-tool.md)이다. 선택 설명과 검증 규칙의 원본은 등록 카탈로그이며 실행 이벤트에 허용된 뷰만 사용한다. 호출별 지침 제공 범위와 검증 도구 연결은 [Tableau 시각화의 지침과 실행 연결](tableau.md#지침과-실행-연결), 허용 목록과 오류 계약은 [이벤트별 허용 뷰](tableau.md#이벤트별-허용-뷰)를 따른다.

- 지침 ID·적용 대상·버전·시행일·원천 자료와 위치·변경 사유·검토 상태를 기록한다.
- 검토한 지침·도구·API 구성을 함께 배포하고 실행에 execution.version을 기록한다. 배포 버전에서 실제 적용 지침을 확인할 수 있게 관리한다.
- 변경 시 정상·정보 누락·조건 충돌·근거 부족 사례의 기대 행동을 확인한다.

| 주체 | 검사 범위 |
| --- | --- |
| 코드 | 자료형·필수값·권한·배포 구성·중복 실행·노드별 쓰기 범위 |
| 작업 선택 및 실행 노드 | 진행 판단에 따른 도구·하위 에이전트·인자 선택, 도구 입력·설정 검사와 호출·재시도를 results에 기록 |
| 작업 진행 판단 노드 | 요청 조건·자료·호출 결과로 현재 정보의 충분성과 필요한 정보를 판단하고 추가 작업·응답 작성·사용자 정보 요청을 결정 |
| 응답 작성 노드 | 확보한 근거에 맞게 설명·해석을 작성하고 통합할 내용의 의미·한계를 보존 |
| 담당자 | 현장 사실 확인, 업무 판단 |

지침 제공만으로 접근 권한과 실행 조건을 충족한 것으로 처리하지 않는다. 필수 출력 항목과 조건은 시스템 규칙으로도 검사한다.

## 4. 기록·공개 지침

시스템 지침은 messages의 시스템 메시지로, 실제 사용자 요청·답변은 사용자 메시지로 구분한다. 자동 실행의 goal을 사용자 발화로 복제하지 않는다. 선택·판단 근거는 검토 가능한 짧은 요약으로 results에 기록한다.

응답의 출처·한계·미해결 사항은 content 또는 산출물 내용에 포함한다. 진행 안내 갱신 시 유효한 공개 산출물을 보존한다. 검증·재시도·공개 작성 책임과 쓰기 범위는 [State](state.md), 현재 모델 입력은 [컨텍스트 구성](../runtime/prompts.md)을 따른다.
