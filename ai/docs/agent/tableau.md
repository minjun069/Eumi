# Tableau 시각화 실행

수정일: 2026-11-12.

Tableau 뷰는 서비스에 게시해 둔 차트·표·지도 화면이다. 에이전트는 자연어 요청에 맞는 뷰와 표시 조건을 선택하고, 코드가 등록 설정에 맞는지 검사한 뒤 프론트용 산출물을 반환한다. 같은 입력에는 같은 검사 결과를 반환하며 요청마다 Tableau API나 화면 자동화 브라우저를 호출하지 않는다. 실제 화면 로딩·필터 적용 확인은 프론트가 수행한다.

## 지침과 실행 연결

- [시각화 작업 선택](../../src/instructions/visualization-selection.md): 목적별 뷰, 기간 의미, 조건 결정, 지원하지 않는 요청 처리.
- [시각화 작업 선택 시 도구 사용](../../src/instructions/visualization-tool.md): 입력·오류 처리·재작업·산출물 선택·프론트 전달 조건.

사용자 요청 처리·시각화 역할의 노드 구성 함수 `build_nodes`가 두 지침을 읽고 아래와 같이 제공한다.

| 단계 | 제공 정보 | 수행 내용 |
| --- | --- | --- |
| 작업 목적 파악 | 선택 지침, 뷰 요약 | 요청 목적과 표시할 대상·범위 파악 |
| 작업 진행 판단 | 실제 요청·호출 결과, 선택 지침, 뷰 요약과 입력 조건 | 현재 정보의 충분성과 필요한 정보를 판단하고 다음 진행 방향 결정 |
| 작업 선택 및 실행 | 최근 진행 판단, 두 지침, 뷰 요약, 공유 입력 프로필, 확인된 매개변수의 상세값 | 진행 판단에 따른 표시 조건 선택과 `validate_visualization` 호출 |
| 응답 작성 | 실제 요청·호출 결과 | 성공한 호출 ID로 원본 산출물 선택 |
| 사용자 정보 요청 | 실제 요청·호출 결과 | 사용자가 제공해야 할 조건을 질문 |

뷰 요약(`visualization_catalog.views`)의 목적·한계는 등록 명세에서 가져온다. 입력 프로필(`input_profiles`)은 여러 뷰가 함께 쓰는 입력 규격이며 같은 규격은 한 번만 전달한다. 매개변수별 전체 필터 목록은 생략하고 기존 산출물·호출 이력으로 확인한 상세값을 `selected`에 제공한다. 처음 요청한 필터값은 사용자가 명시한 값으로 검증하며 부적합 사유에 해당 조건의 허용값을 반환한다. 상세 조회를 위한 모델 호출은 추가하지 않는다.

작업 선택 및 실행 노드는 `create_tools()`의 시각화 검증 도구를 호출하고 결과를 작업 진행 판단에 전달한다. 호출 후 별도 모델 검증은 수행하지 않는다. 진행 판단에는 필요한 정보와 보완 가능 여부를 판단할 뷰·입력 조건을 제공하며, 응답·질문 작성에는 전체 지침·등록 목록을 반복 첨부하지 않는다.

`valid=false`는 검사를 마쳤지만 설정이 부적합하다는 뜻이다. 부적합 사유는 별도 검증 이력에 남기고 해당 산출물을 공개 후보에서 제외한다. 진행 판단이 보완할 정보나 사용자에게 확인할 조건을 결정하고, 작업 선택 또는 사용자 정보 요청으로 연결한다. 보완 호출의 재시도 집계 기준과 현재 구현의 제한은 [실행 예산](state.md#실행-예산)을 따른다.

HTML 렌더러는 직접 도구 사용 예제와 조회·가공 근거 비교표 생성에 사용한다. 에이전트의 시각화 작업 선택에서는 게시된 Tableau 검증 도구를 사용한다. 합성 가구 비율로 막대 차트를 생성하는 [S2 시나리오](scenarios.md#3-s2-동별-비율-시각화)는 가상 실행 예시이며 현재 Tableau 지원 범위의 검증 사례가 아니다.

## 등록 설정

### 이벤트별 허용 뷰

실행을 시작하는 코드가 State의 `execution.event`에 시작 원인을 설정한다. 노드 구성 함수는 이벤트나 허용 목록을 별도 인자로 받지 않는다. 하위 실행의 이벤트 상속과 공통 실행기 내부의 질문 재개는 [State 초기화](state.md#3-초기화와-남은-계약)를 따른다. 서비스 API에서 다음 질문은 새 실행으로 시작한다.

등록 명세의 `event_views`에서 이벤트별 허용 범위를 관리한다.

| 시작 원인 | State 값 | 허용 뷰 |
| --- | --- | --- |
| 분석 파이프라인 완료 | `analysis_pipeline` | `EmbedDetailV01`~`EmbedDetailV08` |
| 사용자 요청 | `user_request` | `all`: 등록된 임베드 뷰 전체. 새로 등록한 뷰도 자동 포함 |

`all`은 임의 URL이나 미등록 뷰를 허용하지 않는다. 명시 목록은 해당 ID만, 빈 목록은 시각화 사용 불가를 뜻한다. 이벤트 목록 누락·중복 ID·미등록 이벤트·미등록 뷰는 구성 오류다.

`visualization_context(state, ...)`가 해당 뷰와 사용되는 입력 프로필만 안내한다. 작업 선택 및 실행 노드는 현재 State로 `create_tools(providers, state=state)`를 구성하며, `validate_visualization(request, state=state)`도 같은 이벤트별 목록을 검사한다. 목록 밖의 뷰는 `valid=false`, `view_not_allowed`, `artifact=null`이며 오류의 `allowed`에도 이 이벤트의 허용 ID만 반환한다. `event`, `state`, `allowed_view_keys`는 모델의 JSON 도구 인자에 포함되지 않는다.

배포 명세는 프로세스에서 검사·캐시한다. 같은 배포의 내부 재개에는 별도 허용 목록 재주입이 필요하지 않다. 배포 설정 변경 후 프로세스를 다시 시작하며 배포 버전이 달라진 대기 실행의 내부 재개 방식은 미정이다. 서비스 API는 저장된 실행을 재개하지 않는다.

### 뷰와 입력 프로필

[등록 설정 파일](../../src/tools/tableau_catalog.json)이 선택 설명과 실행 명세의 원본이다. 현재 워크북 `eumi_tableau_main_dashboard_v2_0_6_connection_map_fixed`의 임베드 뷰 15개, 강남구·춘천시, 2025년 7~12월이 등록돼 있다. 등록 목록에서 벗어난 요청을 다른 값으로 자동 보정하지 않는다.

| 등록 항목 | 내용 |
| --- | --- |
| `event_views` | 시작 이벤트별 허용 뷰 ID 목록 또는 전체 등록 뷰를 뜻하는 `all` |
| `views` | 서비스 내부 뷰 ID별 제목·목적·한계, 워크북·게시 뷰명, 입력 프로필 참조, 필터별 대상 시트 목록, 시간 의미·부분 선택 주의사항 |
| `input_profiles.parameters` | 이름별 `data_type`, `allowed`, 선택적 표시 이름 `labels`. 등록된 매개변수는 모두 필수 |
| `input_profiles.filters` | 고정 허용값 `allowed` 또는 참조 매개변수 `depends_on`과 값별 허용 목록 `allowed_by` |
| `input_profiles.date_orders` | 실제 선후 검사가 필요한 날짜 매개변수 쌍 `start/end` |

기존 6개 뷰는 `monthly_city` 프로필로 도시·기간·읍면동 필터를 사용한다. 상세 지도와 `EmbedDetailV01`~`V08`은 `monthly_detail` 프로필로 기간과 `p_detail_adm`을 사용한다. `p_detail_adm`에는 `춘천시 후평3동`처럼 Tableau 표시값을 전달한다. 코드 `5111061100`을 API에 직접 적용하면 실패하는 것을 확인했다. 상세 뷰의 내부 계산 필터는 게시 설정을 유지하며 도구 입력에 노출하지 않는다.

현재 입력 값은 문자열이며 매개변수 자료형은 `string/date`, 필터는 문자열 범주 목록을 지원한다. 새로운 숫자 범위·자료형이 필요하면 등록 스키마·공통 검증·프론트의 적용 지원을 함께 추가해야 한다.

새 뷰는 `views`에 추가하고 같은 조건이면 기존 프로필을 참조한다. 조건이 다르면 프로필을 추가하며, 도시·기간이 없는 뷰는 해당 항목을 등록하지 않는다. 각 필터에 여러 대상 시트를 지정할 수 있고 모든 대상에 같은 조건을 적용한다. 다른 워크북도 뷰별로 지정한다. 뷰 종류마다 별도 도구·Python 분기를 추가하지 않는다.

[tableau_catalog.py](../../src/tools/tableau_catalog.py)의 `validate_catalog()`가 자료형·필수 필드, 프로필·필터 참조, 허용값·표시 이름, 날짜 규칙, 의존 필터의 허용 목록 누락·중복을 검사한다. 구성 오류는 사용자 입력의 `valid=false`로 숨기지 않고 등록 오류로 거부한다. 파일은 프로세스에서 처음 읽을 때 검사·캐시하므로 갱신한 설정 배포 후 프로세스를 다시 시작한다.

2026-11-06 새 게시본의 15개 임베드 뷰 로딩·시트·매개변수·필터 명세를 확인했다. 기존 6개 뷰의 후평3동 필터와 상세 9개 뷰의 표시값 매개변수 적용·재조회를 확인하고 공개 워크북 계산식으로 기간 의미를 대조했다. 모든 지역·월 조합의 데이터 존재를 검사한 결과는 아니다. `catalog_revision`은 원자료 버전이 아니다.

검사 항목은 자료형·필수값·추가 필드, 선택한 뷰의 매개변수·필터 이름과 허용값, 선언한 날짜 순서·필터 의존 조건, 빈 목록·중복 값이다. 부적합 시 `issues`에 `code/path/message/requested/allowed/retryable`을 반환하며 `artifact`는 `null`이다. 필수 매개변수 누락은 `missing_parameter`, 고정·의존 필터 허용값 불일치는 `invalid_filter_value`다. `retryable=false`는 같은 입력의 자동 재시도가 무의미하다는 뜻이며 수정 후 호출은 가능하다.

```python
from src.state import create_state
from src.settings import Settings
from src.tools.tableau import validate_visualization

state = create_state(
    {"goal": "춘천시 배경 취약성 지도"}, Settings(),
    messages=[], version="배포 버전", event="user_request",
)
# 해당 뷰를 event_views.user_request에 배정한 경우
result = validate_visualization({
    "view_key": "Embed01VulnerabilityMap",
    "parameters": {
        "p_city": "51110", "p_start": "2025-07-01", "p_end": "2025-12-01"
    },
    "filters": {"읍면동": ["후평3동"]},
}, state=state)
```

성공한 산출물의 `artifact.data`에는 프론트가 뷰를 표시하고 적용 조건을 확인할 정보가 담긴다.

| 필드 | 내용 |
| --- | --- |
| `schema_version` | 산출물 구조 버전 |
| `artifact_id` | 같은 조건에서 같은 값을 만드는 산출물 식별자 |
| `catalog_revision` | 등록 설정 버전. 원자료 버전과 구분 |
| `view_key` | 등록 뷰 식별자 |
| `src` | 게시된 뷰 주소 |
| `title` | 표시 제목 |
| `period_mode` | 뷰의 기간 해석 방식 |
| `parameters` | 확정한 매개변수 값 |
| `filters` | 적용 조건과 대상 시트 |
| `source` | 출처 |
| `validation_scope` | 검증한 범위 |
| `warnings` | 표시·해석 시 주의사항 |

같은 조건의 지역 순서를 바꿔도 같은 식별자를 생성한다. 생략된 읍면동 필터도 `operation=all`로 명시하여 이전 카드의 선택이 남지 않도록 한다.

프론트는 [패널 계약](../../../docs/api/ai-agent-panel.md#2-1-artifacts-형식)에 따라 완료 행의 시각화만 표시한다. 진행 행에 산출물이 있어도 그리지 않는다. 표시할 카드는 다음 순서로 처리한다.

| 단계 | 수행 내용 |
| --- | --- |
| 카드 준비 | `type=tableau` 카드의 새 인스턴스를 생성하고 `FirstInteractive` 이벤트까지 대기 |
| 조건 적용 | 자료형에 맞게 매개변수, 대상 시트 필터 순서로 적용. `date`는 `YYYY-MM-DD`의 UTC 날짜로 변환하고 각 `worksheet` 필터에 `replace/all` 적용 |
| 적용값 확인 | 실제값을 재조회. `p_detail_adm`은 표시값으로 적용하고 `formattedValue`로 비교. 행정동 코드인 원값 `value`와 표시값을 직접 비교하지 않음 |
| 상태 표시 | 적용 중에는 로딩 상태를 표시하고 적용값이 다르면 해당 카드의 오류로 표시 |
| 중복 표시 | 이전 완료 답변에 표시한 동일 산출물은 다시 그리지 않고 반복 개수를 표시. 다른 카드의 인스턴스·필터 상태는 공유하지 않음 |

시각화 검증 도구는 작업 결과로 산출물을 반환하고, 응답 작성이 선택한 결과를 `response.artifacts`에 넣는다. Python 도구의 검증 통과는 DB 저장·알림·프론트의 주기 조회와 실제 화면 표시 성공을 뜻하지 않는다.

## 실행과 검증

### 실행 방법

`ai/`에서 실행한다. `.env`의 OpenAI 키 `SETTINGS_API_KEY`를 사용한다. `--model`을 생략하면 Settings의 모델을 사용하며 현재 기본값은 `gpt-6-sol`이다. 이 명령은 지침·카탈로그·요청과 도구 명세·응답 스키마를 OpenAI Responses API로 전송한다.

```powershell
.\.venv\Scripts\python.exe -m demo.tableau_demo --model gpt-6-sol --goal "2025년 12월 춘천시 후평3동의 배경 취약성 지도를 보여줘." --output outputs/tableau/state.json
.\.venv\Scripts\python.exe -m pytest tests/tools/test_tableau.py tests/tools/test_tableau_catalog.py tests/test_visualization_events.py tests/test_agent_nodes.py -q
```

`tableau_demo.py`는 실제 `build_nodes`·공통 그래프·검증 도구를 호출한다. 합성 자료나 모의 모델 분기를 공통 실행 코드에 넣지 않는다. 일반 실행 시간의 기본 한도는 180초이며 `--timeout` 값을 최초 State에 반영한다. 모델·도구·하위 에이전트가 같은 잔여 시간과 누적 사용량을 공유한다. 한도 도달 후 별도 종료 예산은 [State의 실행 예산](state.md#실행-예산)을 따른다. 데모 외부에서 별도 timeout이나 호출 한도를 다시 설정하지 않는다.

### 검증 기록과 확인 범위
