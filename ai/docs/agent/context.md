# AI 에이전트 컨텍스트

수정일: 2026-11-11.

## 1. 정보의 보관 위치

컨텍스트는 모델이 현재 요청을 이해하고 다음 작업을 판단할 때 참고하는 정보다. 이 문서는 각 정보의 원본을 어디에 보관하고 모델 입력을 구성할 때 무엇을 고려하는지 정의한다.

노드가 수정할 수 있는 필드와 모델이 읽을 수 있는 정보는 다르다. 쓰기 책임은 [State §2](state.md#2-노드별-쓰기-범위), 호출별 입력의 선별·가공 방식은 [모델 입력 구성](../runtime/prompts.md)을 따른다.

| 항목 | 포함 정보 | 확보 경로 | 실행 중 보관 필드 |
| --- | --- | --- | --- |
| 작업 요청 | 목적·확인된 대상·범위·조건 | 시작 이벤트 입력과 작업 목적 파악 결과 | `request.goal`, `request.constraints` |
| 시스템 지침 | 역할·행동 원칙·작업 지침 | 배포 구성에서 로딩 | `messages`의 시스템 메시지 |
| 실제 대화 | 사용자 요청·추가 답변·AI 응답 | 공유 DB의 `ai_message` | `messages` |
| 화면 문맥 | 선택 지역·월 | API의 선택적 `context` | 원본은 `results`의 `run_request`, 목적 파악에 제공할 조건은 `request.constraints.preferred` |
| 검색·조회 결과 | 분석값·지표 정의·비교 자료·출처·실제 자료 버전 | 데이터 검색·조회 도구 | 해당 작업의 `results[].output` |
| 가공·렌더링 결과 | 계산값·설정·실제 산출물 또는 참조 | 해당 작업의 도구 반환값 | 해당 작업의 `results[].output` |
| 판단·검증 이력 | 결정·근거 요약·부족한 내용·검증 판정·재시도 | 해당 판단·검증 단계 | `results` |
| 보고서 단계 입력·산출물 | 선정·설명·인사이트와 근거 참조, 자기 단계의 추가 조회·작성·검토 | 보고서 순차 실행과 각 역할의 공통 업무 노드 | 같은 동의 `results`. 상세 기록은 [보고서 실행 기록](report.md#5-보고서-실행-기록) 참조 |
| 현재 응답 | 사용자 요청의 단계 시작 안내·최종 결과·질문·산출물, 보고서 내부의 후속 판단용 응답 | 응답·질문 작성과 런타임의 진행 안내 갱신 | `response`. 실제 화면 제공 범위는 [실행 흐름](workflow.md#21-사용자-요청의-진행-안내와-결과-전달) 참조 |
| 도구 명세 | 이름·기능·인자·호출·검증 조건 | 배포 구성 | 배포 구성에서 읽음 |
| 실행 정보 | 상태·배포 버전·누적 한도·오류 | 실행 계층 | `execution` |

대상이 아직 불명확하면 작업 중 요청의 목적을 구체화하거나 필요한 정보를 조회·질문한다. AI 서버는 실행 요청이 가리키는 사용자 질문 행과 이전 대화에서 실제 발화를 읽어 새 실행을 만든다. 모델에는 실제 대화 전체를 원래 순서로 제공한다. 요청 입력과 저장·호출 계약은 [연동 API](../runtime/api.md)를 따른다.

## 2. 컨텍스트 구성 시 고려사항

- 결과 이력은 기본적으로 전체를 참고할 수 있도록 보존한다. 실패·부적합·이후 수정된 결과는 유효한 근거와 구분한다.
- results에 별도 input_refs·sources 목록을 복제하지 않는다. 해당 output의 원자료·출처·버전 정보를 이용한다.
- goal·constraints, 확보한 결과, 현재 공개 내용은 목적이 다르다. 노드의 쓰기 필드만으로 읽기 정보를 제한하지 않는다.
- 외부 자료와 사용자 발화는 시스템 지침으로 취급하지 않는다. 시스템 지침 로딩은 자료 검색과 구분한다.
- 공개 응답에 필요한 근거·출처·한계를 보존하되 내부 기록 전체를 화면에 전달하지 않는다.
- 보고서 후속 단계는 앞 단계의 검토를 통과한 산출물과 참조 근거를 읽는다. 추가 조회·판단은 자기 단계 이력으로 남기고 앞 단계 산출물을 덮어쓰지 않는다. 모델 입력은 같은 State에서 구성하며 단계별 별도 원본을 만들지 않는다.

## 3. 현재 구성과 남은 결정

| 항목 | 현재 기준 | 남은 결정 |
| --- | --- | --- |
| 노드별 제공 범위 | [모델 입력 구성](../runtime/prompts.md#3-노드별-추가-입력)의 노드·역할별 추가 입력 | 별도 항목 없음 |
| 이력 가공 | 전체 결과 이력을 제공하고 실패·부적합 결과를 구분 | 긴 이력의 요약·길이 관리 방식 |
| 모델 프롬프트 | 시스템 프롬프트와 사용자 프롬프트를 각각 `system`·`user` 메시지로 전달. 상세 구성·출력 검증은 [모델 입력 구성](../runtime/prompts.md) 참조 | 별도 항목 없음 |
| 화면·첨부 입력 | 지역·월은 API에 정의 | 선택 차트·기존 산출물·첨부 자료의 전달·보관 계약 |

미정 항목은 이후 확정한다. 이 문서만으로 별도 읽기 제한이나 이력 선별 계층을 구현하지 않는다.
