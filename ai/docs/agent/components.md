# AI 에이전트 기능 명세

수정일: 2026-11-12.

에이전트가 어떤 요청을 맡고, 어떤 도구로 필요한 자료와 산출물을 확보하는지 정의한다. 시스템 구성 요소와 기술안은 [아키텍처](../architecture.md)에서 정의한다.

## 1. 용어 정의

| 용어 | 정의 |
| --- | --- |
| 도구 | 정해진 입력과 처리 규칙에 따라 결과를 반환하는 기능 |
| 워크플로우 | 수행 단계와 진행 규칙이 정해진 처리 과정 |
| 노드 | 워크플로우 안에서 목적 파악·작업 선택·응답 작성 등의 역할을 맡는 단계 |
| 에이전트 | 목표와 중간 결과를 보고 다음 작업을 선택하는 실행 주체 |

## 2. 도구 명세

아래 표는 기능별 입출력의 개념 명세다. 실제 서비스 API 경로는 [연동 API](../runtime/api.md), Tableau 검증의 구현 범위와 화면 연결은 [Tableau 시각화](tableau.md)를 따른다.

작업 선택 및 실행 노드는 데이터 검색·조회 도구로 필요한 자료를 찾는다. 호출 결과와 출처·실제 자료 버전은 해당 작업의 출력(`results[].output`)에 함께 보관한다. 보관 구조는 [State](state.md#13-results)를 따른다.

### 2.1 데이터 검색·조회

저장된 데이터에서 지정된 조건에 맞는 정보를 검색하고 반환한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 대상, 조회 방식·조건, 반환 필드, 정렬, 최대 건수, 시점·버전 |
| 출력 | 레코드, 참조 ID, 출처·버전·기준 시점 |
| 출력 요약 | 적용 조건, 결과 수, 다음 페이지 |
| 오류 | 잘못된 조건, 권한 부족, 참조 없음 |

등록된 데이터만 조회한다. 임의 테이블·SQL은 실행하지 않는다. 결과 없음과 조회 실패를 구분한다.

### 2.2 데이터 가공

조회하거나 전달받은 데이터에 지정된 연산을 적용한다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 원본 참조·버전, 연산·순서, 결합 키·방식 |
| 출력 설정 | 결측 처리, 반환 필드·자료형, 반올림 |
| 출력 | 가공 결과·단위, 적용 연산, 입력·출력·제외 행 수 |
| 오류 | 단위 불일치, 분모 0, 결측, 결합 실패 |

결측을 임의로 0으로 바꾸지 않는다. 분모·공간·시간 단위가 다르면 비교를 중단하거나 한계를 표시한다.

### 2.3 시각화 검증

게시된 Tableau 뷰와 표시 조건을 등록 설정에 대조하고 프론트용 산출물을 반환한다. 요청마다 외부 API·헤드리스 브라우저를 실행하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 등록 뷰 식별자, 해당 뷰의 매개변수·필터 |
| 검사 | 자료형, 뷰별 등록 이름·허용값·필수값, 선언된 날짜 순서·매개변수별 필터 허용값, 중복 값 |
| 출력 | 적합 여부, 구체적인 부적합 사유, 유효한 경우 `tableau` 산출물 |
| 산출물 | 뷰 주소·대상 시트·매개변수·필터·출처·등록 설정 버전·한계 |

설정 검사 통과는 자료 존재·최신성·실제 표시 성공을 의미하지 않는다. 실제 렌더링과 적용값 확인은 프론트가 수행한다. 구현 계약은 [Tableau 시각화 실행](tableau.md)을 따른다.

등록 정보는 각 뷰의 목적·표현 한계·입력 조건을 정의한다. 에이전트와 검증 도구는 실행을 시작한 이벤트에 허용된 뷰만 사용한다. 이벤트별 허용 목록과 구성 오류는 [등록 설정](tableau.md#등록-설정), 모델에 제공할 목록과 상세 조건은 [지침과 실행 연결](tableau.md#지침과-실행-연결)을 따른다.

## 3. 에이전트 명세

각 에이전트는 요청의 목적과 확인된 범위를 바탕으로 도구를 선택하고, 확보한 결과를 설명과 산출물로 구성한다. 실제 호출 순서와 예외는 [실행 흐름](workflow.md), 요청·내부 이력·공개 응답의 보관 구조는 [State](state.md)를 따른다.

작업 진행 판단 노드는 현재 정보의 충분성과 전체 요청에 부족한 정보를 판단한다. 작업 선택 및 실행 노드는 그 판단에 따라 모델을 1회 호출해 도구·하위 에이전트·입력 인자를 선택하고 도구 입력·설정 검사와 호출 결과를 기록한다. 두 단계의 책임과 검증 범위는 [공통 실행 흐름](workflow.md#2-에이전트-공통-실행-흐름)을 따른다.

### 3.1 데이터 분석 결과 해석 에이전트

분석 결과와 해석 지침을 바탕으로 주요 신호, 비교 결과, 지역·집단 특성과 해석 한계를 설명한다. 도구로 분석·비교 자료와 계산 결과를 확보하고, 응답 작성에서 해석문을 생성한다. 분석 완료 이벤트의 입력 구성과 진입 단계는 [시작 이벤트](workflow.md#1-시작-이벤트)를 따른다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 분석 결과, 지역·집단, 단위·기간, 비교 기준·품질 지침 |
| 출력 | 주요 신호, 비교 설명, 근거 지표, 한계·확인 사항 |
| 종료 | 주요 신호·비교 설명·근거·한계를 갖춘 해석 또는 해석 불가 사유 반환 |

해석은 관측한 지역·집단·기간과 비교 근거 안에서 작성한다. 관측 사실과 가능한 설명을 구분하고, 근거가 뒷받침하는 범위와 한계를 제시한다. 이 기준은 해석을 작성하는 책임에 적용한다.

활용 도구: 데이터 검색·조회, 데이터 가공

### 3.2 데이터 시각화 에이전트

작업 진행 판단에서 요청에 필요한 정보와 시각화 작업을 확인하고, 작업 선택 및 실행에서 전달 목적에 맞는 게시된 Tableau 뷰와 표시 조건을 선택한다. 시각화 검증 도구로 등록 설정의 적합성을 검사하고 결과를 기록한다. 진행 판단은 부적합 사유와 현재 자료를 대조해 보완할 정보와 다음 단계를 결정하며, 응답 작성에서 유효한 산출물·적용 조건·한계를 제공한다. 게시되지 않은 지표·임의 계산 결과를 다른 뷰로 대체하지 않는다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 목적, 확인된 도시·기간·읍면동, 기존 화면·산출물 조건 |
| 출력 | 프론트용 Tableau 산출물, 적용 조건·출처·한계 |
| 종료 | 요청에 부합하는 유효한 표시 설정 또는 지원 범위·표현 불가 사유 반환 |

활용 도구: 데이터 검색·조회, 데이터 가공, 시각화 검증

### 3.3 사용자 요청 처리 에이전트

서비스 이용 중 입력한 자연어 요청을 파악한 뒤 작업 진행 판단에서 현재 정보가 충분한지, 어떤 정보가 필요한지 결정한다. 추가 작업이 필요하면 작업 선택 및 실행에서 그 판단에 맞는 전문 에이전트·도구를 선택하고 호출한다. 응답 작성에서는 최종 답변과 연결할 산출물·근거·미해결 사항을 통합하고 실행을 끝낸다.

| 구분 | 내용 |
| --- | --- |
| 입력 | 요청, 현재 화면·선택 대상, 확인된 자료·관련 이력 |
| 출력 | 최종 통합 응답·공개 산출물·근거·미해결 사항 또는 추가 질문 |
| 종료 | 요청 충족 또는 가능한 결과와 미해결 사항 반환 |

실행 중 단계 시작 안내는 런타임이 정해진 문구로 작성·전달한다. 도구·하위 에이전트의 새 결과는 내부 작업 이력에 보관하며 최종 응답에서 공개할 내용을 선택한다. 하위 결과를 전달·통합할 때 수치·의미·출처·한계를 보존한다. 직접 새로운 해석을 작성하면 해당 내용에 §3.1의 해석 기준을 적용한다.

공개할 산출물 선택과 응답 작성은 이 에이전트가 맡는다. AI 서버는 진행·종료 행을 저장한 뒤 백엔드에 POST로 알리고, 프론트는 주기적으로 새 행을 조회해 표시한다. 단계 안내·최종 답변·산출물의 제공 시점은 [실행 흐름 §2.1](workflow.md#21-사용자-요청의-진행-안내와-결과-전달)을 따른다.

활용 도구: 데이터 검색·조회, 데이터 가공, 시각화 검증
활용 에이전트: 데이터 분석 결과 해석 에이전트, 데이터 시각화 에이전트

### 3.4 보고서 에이전트와 생성 흐름

분석 완료 후의 보고서는 시각화 선정 → 시각화 설명 → 퀵 인사이트 에이전트가 순차 작성한다. 각 에이전트는 동일한 공통 노드 전이를 사용하며 자기 산출물의 충분 여부를 판단한다. 작성·검토 후 추가 작업이 필요하면 이력을 진행 판단에 전달하고, 진행 판단이 추가 조회·가공 또는 재작성 여부를 결정한다.

| 에이전트 | 입력 | 출력·종료 기준 |
| --- | --- | --- |
| 시각화 선정 | 대상 동·월, 조회·가공한 자료 | 검토를 통과한 뷰·선정 이유·근거 참조·설명 범위 또는 선정 불가 사유 |
| 시각화 설명 | 검토를 통과한 선정·근거·설명 범위 | 검토를 통과한 뷰별 설명·추가 근거 또는 미완성 항목 |
| 퀵 인사이트 | 검토를 통과한 설명과 근거 | 검증된 설명 범위의 요약 또는 미완성 사유 |

활용 도구는 각 산출물 책임 안의 데이터 검색·조회, 데이터 가공이다. 앞 단계 에이전트를 호출하거나 완료된 산출물을 변경하는 기능은 제공하지 않는다. 여러 동의 병렬 실행·저장·완료 알림은 개별 에이전트가 아닌 보고서 생성 흐름의 책임이다. 허용 뷰·분량·검토·수정 상한·부분 완료·오류 재처리와 단계 간 전달의 상세 계약은 [보고서 생성](report.md)을 따른다.

## 4. 출력 구분

| 출력 | 보관 필드 | 내용 |
| --- | --- | --- |
| 내부 기록 | `results` | 선택·판단 근거, 도구·에이전트 반환값, 검증·재시도 |
| 응답 | `response` | 사용자 요청의 진행 안내·최종 결과·추가 질문, 보고서 내부의 후속 판단용 응답 |

공개 응답의 종류별 내용과 산출물 보존 기준은 [공개 응답](state.md#14-response), 백엔드 전달은 [연동 API](../runtime/api.md)에서 관리한다.
