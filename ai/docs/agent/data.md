# AI 에이전트 데이터

수정일: 2026-11-09.

## 1. 활용 데이터

에이전트는 분석 결과와 지표 정의·비교 자료를 함께 조회해 결과의 의미와 한계를 설명한다. 이 문서는 필요한 자료의 종류, 출처·갱신 기준, 실행 중 보관 방식을 정의한다.

자료의 활용 목적은 해석·비교·변환할 작업 대상, 요청 범위와 제약을 정하는 맥락 및 조건, 해석의 타당성을 확인할 판단 근거, 행동·출력·검증에 적용할 수행 기준으로 구분한다.

| 자료 | 형태 | 활용 방식 | 분류 | 활용 목적 |
| --- | --- | --- | --- | --- |
| 지역 통계 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 지역 구분·비교 |
| 인구 통계 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 인구 구성 분석·비교 |
| 가구 통계 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 가구 구성 분석·비교 |
| 경제 통계 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 경제 여건 분석·비교 |
| 거주환경 통계 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 거주환경 분석·비교 |
| 유동인구 데이터 | 정형 테이블 | 조건 기반 조회 | 작업 대상 | 활동 변화와 이상 신호 분석 입력 |
| 분석 결과 | 정형 테이블 | 식별자 조회 | 작업 대상 | 지역·집단 분석 결과의 해석·시각화 |
| 지표 정의 | 정형 테이블 | 식별자 조회 | 판단 근거 | 지표 의미·단위·산출 방식 |
| 분석 방법 설명 | 정형 테이블 | 식별자 조회 | 판단 근거 | 분석 방법·비교 범위 |
| 공통 운영 원칙 | 문서 | 지침 로딩 | 수행 기준 | 수행 범위·절차·권한 경계 |
| 업무 매뉴얼 | 문서 | 지침 로딩 | 수행 기준 | 해석·표현 방법·결과 검토 |
| 산출물 명세·작성 기준 | 문서 | 지침 로딩 | 수행 기준 | 필수 항목·출력 형식·누락 처리·검증 |

사용자 요청·선택 지역·필터는 [컨텍스트](context.md)에서 맥락 및 조건으로 관리한다. 에이전트는 분석 파이프라인에서 생성한 결과와 지표 정의를 조회해 해석한다.

## 2. 조회와 출처

식별자 조회는 ID·기준 시점·버전으로 특정 자료를 찾고, 조건 기반 조회는 명시적 조건으로 조회·필터링·계산·집계한다. 지침 로딩은 실행 업무에 연결된 수행 기준을 제공한다.

| 자료 | 출처 | 갱신 시점 |
| --- | --- | --- |
| 지역 통계 | 서울시 행정구역(동별) 통계 | 매년 공표·정정 자료 확인 시 갱신 |
| 인구 통계 | 서울시 등록인구(연령별/동별) 통계 | 분기별 공표·정정 자료 확인 시 갱신 |
| 가구 통계 | 서울시 가구원수별 가구 통계 | 매년 공표·정정 자료 확인 시 갱신 |
| 경제 통계 | 서울시 고용지표 통계 | 매월 공표·정정 자료 확인 시 갱신 |
| 거주환경 통계 | 서울시 노후기간별 주택현황 통계 | 매년 공표·정정 자료 확인 시 갱신 |
| 유동인구 데이터 | [데이터셋 1] 이동전화 가입자·이동 정보 | 실시간 수집 가능한 것으로 가정함 |
| 분석 결과 | 내부 분석 파이프라인 | 분석 완료 시 입력·분석 버전과 연결해 갱신 |
| 지표 정의 | AI 에이전트 지표 정의서 | 지표 정의 변경 확정 시 갱신 |
| 분석 방법 설명 | AI 에이전트 분석 방법 명세서 | 분석 방법 변경 확정 시 갱신 |
| 공통 운영 원칙 | 프로젝트 확정 요구사항, 기관 매뉴얼 | 변경 검토·확정 후 배포 구성에 포함해 갱신 |
| 업무 매뉴얼 | 내부 분석 방법론, 작성 가이드라인 | 방법론 변경 검토 후 갱신 |
| 산출물 명세·작성 기준 | 에이전트 구성 문서, 확정 산출물 명세 | 구성 문서·양식·명세 변경 검토 후 갱신 |

출처와 갱신 시점은 설계값이며 실제 확보 상태와 연동 방식은 자료원별로 확인한다. 현재 지도 시각화는 게시된 뷰와 표시 조건을 입력으로 받으며 상세 계약은 [Tableau 시각화](tableau.md)를 따른다.

| 관리 항목 | 기준 |
| --- | --- |
| 자료원 식별 | 실제 원문 URL·내부 경로·데이터셋·통계표 ID 기록 |
| 확보 상태 | 확보 전 자료는 후보 또는 미확정 상태로 관리 |
| 기준 시점 | 데이터 기준일, 원문 작성·수정일, 수집·확인일 등 필요한 시점 기록 |
| 접근 범위 | 권한이 허용된 자료만 조회·사용 |
| 해석 근거 | 지표 의미·단위·분모·기준값·비교 기간·출처 연결 |

수행 기준의 작성·적용·검증 절차는 [작업 지침](instructions.md)에서 정의한다.

## 3. 실행 중 자료 기록

| 항목 | 보관 기준 |
| --- | --- |
| 검색·조회 | 작업 선택 및 실행의 검색·조회 도구로 수행 |
| 조회 결과 | 데이터·출처·실제 자료 버전을 해당 results[].output에 저장 |
| 계산·가공 | 원자료·적용 조건·계산값을 작업 인자와 output에 보존 |
| 화면 제공 | 공개 출처·기준 시점·한계를 response.content 또는 산출물 내용에 포함 |
| 배포 구성 | 지침·도구·API를 execution.version으로 식별. 자료 버전과 구분 |

실행 기록의 공통 구조는 [State](state.md)를 따른다. 보고서의 대상 동·월과 분석 자료 수정 시각은 [API의 보고서 생성 계약](../runtime/api.md#2-보고서-생성), 자료 조회 도구의 입출력은 [기능 명세](components.md#21-데이터-검색조회)를 따른다. 분석 갱신과 보고서 저장이 겹칠 때의 화면 조회 제약은 [보고서 생성의 연동 대조](../runtime/api.md#26-연동-대조)에서 확인한다.
