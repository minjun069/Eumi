# AI Agent 컨텍스트 구성 규칙

기준일: 2026-11-06 · 구분: 현재 구현

모델 입력은 **공통 입력에 노드·역할·실행 조건별 정보를 더해 구성**한다. 업무 자료의 원본은 State에 두고, 호출할 때마다 system 메시지 1개와 user 메시지 1개를 만든다. 도구 설명·입력 명세는 `bind_tools()`, 응답 형식은 `with_structured_output()`으로 별도 전달한다.

## 2 공통 메시지

```text
system
  [공통 원칙]
  [현재 Agent 역할]
  [이번 노드의 작업 지침]

user
  [현재 작업 목표]
  [필수 조건] [선호 조건] [제외 조건]
  [실제 대화 · 입력 메시지]
  [기존 공개 응답]
  [기존 공개 산출물]
  + 노드별 추가 입력
```

| 항목 | 원본과 구성 규칙 |
| --- | --- |
| 공통 원칙 | 사실·해석·한계 구분, 근거 보존, 계산 도구 사용, 시각화 검증 범위 등. 모든 호출에 전체 제공 |
| Agent 역할 | 요청 처리: 전문 작업 위임·통합 / 해석: 조회·계산·해석 / 시각화: 등록 뷰·조건 선택 |
| 목표·조건 | `request.goal`과 `constraints`. 조건은 값이 있을 때만 제공 |
| 실제 대화 | `messages` 전체. 원래 순서·역할·내용을 유지하며 요약하지 않음 |
| 기존 공개 내용 | `response.content`와 `artifacts`. 존재하는 항목만 제공 |

목표·조건·문자열 발화·기존 응답은 원문으로 전달한다. 결과 이력·자료 목록·산출물·실행 조건과 문자열이 아닌 메시지 내용은 JSON으로 전달한다.

### API 설정과 응답 검증

| 항목 | 구성 규칙 |
| --- | --- |
| 응답 스키마 | 기존 6종 TypedDict에서 `TypeAdapter.json_schema()`로 생성. `with_structured_output(method="json_schema", strict=False, include_raw=True)`에 전달 |
| 도구 명세 | 작업 선택 호출에서만 `bind_tools(..., tool_choice="none", strict=False)`로 구성하고 해당 바인딩 설정을 구조화 출력 호출에 함께 전달 |
| 선택 결과 | 기존 `name`, `arguments_json`, `reason` 유지. 인자 객체의 JSON 문자열 직렬화는 `arguments_json`의 스키마 설명에 지정 |
| 실행 담당 | API의 도구 호출 대신 기존 선택 JSON을 반환받고, 노드가 선택 기록 → 도구·Agent 호출 → 결과 검증 순서로 처리 |
| 형식 검증 | 원본 응답의 `text`를 기존 TypeAdapter로 검증. `strict=False`는 선택 입력을 필수로 바꾸지 않기 위한 설정이며 서버의 엄격한 스키마 보장을 사용하지 않음 |
| 사용량·오류 | 원본 SDK 응답·HTTP 요청·응답을 기존 trace에 기록. 검증 성공 시 모델명·토큰·경과 시간을 기존 `model_usage`로 반환. 검증·통신 오류는 기존 실행 경로로 전파 |
| 실행 자료 | 서버 응답 저장과 이전 응답 ID 자동 연결을 사용하지 않음. 매 호출의 메시지·동적 도구 조건은 현재 State에서 구성 |

`create_model()`은 OpenAI 공식 주소와 Responses API를 사용한다. 현재 모델에서 지원하지 않는 `temperature`는 전송하지 않는다. SDK의 `raw`, `parsed`, `parsing_error` 반환 묶음은 호출 중 지역값이며 State·모델 응답 계약에 필드를 추가하지 않는다.

## 3 노드별 추가 입력

5개 업무 노드에서 6종류의 모델 입력을 사용한다. `act`는 작업 선택과 결과 검증을 각각 호출한다.

| 단계 | 조립 함수 | 추가 입력 | 판단 목적 |
| --- | --- | --- | --- |
| 목적 파악 | `interpret_messages` | 호출 출력을 제외한 이력, 역할별 시각화 뷰 목록 | 목표·조건 구체화, 필수 정보 부족 확인 |
| 작업 선택 | `selection_messages` | 전체 결과 이력, 실행 조건, 조회 자료 목록, 역할별 시각화 입력 조건 | 수행할 도구·Agent와 인자 선택 |
| 결과 검증 | `verification_messages` | 직전 선택·호출, 계산 입력의 원본·검증 기록 | 요구 조건과 호출 결과 대조 |
| 진행 판단 | `decide_messages` | 전체 결과 이력, 실행 조건 | 추가 작업·응답 작성·질문 선택 |
| 응답 작성 | `compose_messages` | 전체 결과 이력, 실행 조건 | 근거·한계를 설명하고 산출물 선택 |
| 사용자 질문 | `ask_messages` | 호출 출력을 제외한 이력 | 사용자가 제공할 필수 정보 질문 |

- **호출 출력 제외:** `decision == "call"`인 기록의 `output`만 제거한다. 호출 ID·인자·이유·성공 여부와 다른 판단 기록은 유지한다.
- **전체 결과 이력:** 성공·실패·검증 거부를 모두 포함한다. 유효한 근거와 공개 가능한 산출물은 검증 기록으로 구분한다.
- **계산 원본:** `input_result_id`로 찾는다. 하위 Agent 결과를 참조하면 이를 포함한 상위 호출·검증도 전달한다.
- **실행 조건:** `execution.event`, `version`, `budget`, `error`를 제공한다.

## 4 역할과 상황별 분기

아래 항목은 **작업 선택 단계**에 제공한다. 역할 지침은 별도로 모든 단계에 적용한다.

| 자료·설명 | 요청 처리 | 데이터 해석 | 데이터 시각화 |
| --- | :---: | :---: | :---: |
| 조회 자료 목록·호출 생략 판단 지침: 메시지 | 제공 | 제공 | 제공 |
| 조회·계산 설명과 입력 명세: 도구 바인딩 | 제공 | 제공 | 제공 |
| 시각화 선택 지침·뷰·입력 조건: 메시지 | 제공 | — | 제공 |
| 시각화 도구 사용 지침·입력 명세: 도구 바인딩 | 제공 | — | 제공 |
| 전문 Agent 설명·목표 입력 명세: 도구 바인딩 | 제공 | — | — |

조회·시각화 입력 명세는 현재 State로 만든 기존 도구의 스키마를 복사한다. 이벤트별 허용 뷰도 같은 명세에 반영된다. 계산 도구의 실제 `data` 입력만 모델이 이미 사용하던 `input_result_id`로 표현하며, 호출 시 노드가 검증된 State 결과에서 자료를 찾는다. 전문 Agent는 기존 `goal`만 받는다. `none`은 호출 생략 선택이며 별도 도구로 등록하지 않는다. 비교표 렌더러도 기존처럼 응답 작성 코드에서 호출한다.

**목적 파악 단계**에서는 요청 처리·시각화 역할에 시각화 선택 지침과 뷰 목록만 제공한다. 상세 입력 프로필과 도구 사용법은 제외한다.

| 상황 | 구성 규칙 |
| --- | --- |
| 시각화 뷰 목록 | `execution.event`에 대응하는 등록 구성 `event_views`의 허용 뷰만 포함 |
| 시각화 입력 조건 | 허용 뷰의 매개변수·날짜 순서·필터 정의 제공. 기존 조건에 해당하는 필터 허용값 추가 |
| 실행 한도 도달 | `compose`에 추가 호출·렌더링 없이 검증된 근거로 종료하고 기존 산출물·한계를 보존하는 지침 추가 |

시각화 컨텍스트의 `selected`는 **기존 산출물과 호출 이력에서 수집한 조건**이다. 화면에서 클릭한 차트 표시가 아니며, 부적합했던 호출 조건도 포함될 수 있다. 이벤트별 뷰 범위에는 배포 등록값 `event_views`가 필요하다.

## 5 이력 가공과 하위 Agent 전달

**이력 가공**은 모델 입력에만 적용하며 State 원본은 유지한다.

- 결과 기록의 `description`과 출력의 `model_usage`를 제외한다. 중첩된 하위 결과에도 적용한다.
- `mime_type == "text/html"`인 객체를 HTML 생성 완료 표시로 대체한다.
- 검증에서 거부된 결과도 판단용 입력에는 남긴다. 산출물 공개 시에는 `accepted_outputs`·`select_artifacts`가 별도로 검사한다.

**하위 Agent**에는 선택한 하위 작업 목표, 상위의 조건·대화·이벤트·누적 예산을 전달한다. 새 실행 ID를 부여하고 `results=[]`, `response=None`으로 시작한다. 따라서 상위의 결과 이력과 공개 산출물은 자동으로 상속되지 않는다. 하위 반환값은 상위 `results`의 호출 결과로 기록한다. [하위 State 생성](C:/ssafy/free_proj/Eumi/ai/src/state.py)

## 6 현재 경계

| 항목 | 현재 상태 |
| --- | --- |
| 화면·선택 차트 | 전용 State 필드가 없음. 실제 대화와 기존 공개 산출물을 사용 |
| 대화·결과 길이 | 자동 요약, 최근 이력 제한, 입력 토큰 예산, 결과 행 수 제한 없음 |
| 요청별 자료 선별 | 조회 자료 목록은 전달받은 전체 목록 사용. 지침은 노드·역할로 선택하며 시각화 뷰는 이벤트로 추가 제한 |
| State의 시스템 메시지 | 원래 API 역할로 전달하지 않고 user 본문 안에 `system` 역할 표시와 원문으로 포함 |
| 보완 호출 식별 | 현재 선택 응답에 `retry_of` 필드와 해당 프롬프트 지침은 없음 |

설계상 보관·연동 기준은 [컨텍스트 명세](C:/ssafy/free_proj/docs/ai-agent-context.md), 필드·쓰기 책임은 [State 명세](C:/ssafy/free_proj/docs/ieumi-agent-state.md)를 따른다.

2026-11-06 사전 호환성 확인에서는 `gpt-6-sol`의 Responses API로 응답 6종과 조회·계산·하위 Agent 선택 3종이 통과했다. 이는 합성 입력을 사용한 모델 경계 확인이다. 이후 구현 변경의 테스트·실제 실행은 사용자 요청에 따라 수행하지 않았으며 테스트 파일도 수정하지 않았다.
