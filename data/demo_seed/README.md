# 시연용 복지자원 · 사례자 seed

시연 기관(R__02) · 시연 회원(R__03)으로 로그인했을 때 복지자원 목록 · 사례자 · 상담 기록이 비어 있지 않도록 넣는 데이터다.
위험 탐지 결과(2025-12)의 고위험 동에 사례자와 동 단위 자원을 몰아 두어 "위험 지역 → 사례자 → 자원 추천" 흐름을 시연할 수 있게 했다.

| 결과 | 내용 |
| --- | --- |
| `db/seed/R__04_welfare_resource.sql` | 복지자원 72건: 강남 실제 복지서비스 26건(강남구 · 서울시 사업) + 춘천 실제 통합돌봄 서비스 14건 + 춘천 전역 가상 서비스 19건 (여기까지 시군구 단위) + 동 단위 가상 자원 13건(강남 7 · 춘천 6) |
| `db/seed/R__05_demo_case.sql` | 사례자 52명(강남 28 · 춘천 24), 담당자 연결, 상담 기록 186건. 모두 가상 인물 |

## 파일

| 파일 | 역할 |
| --- | --- |
| `extract_welfare.py` | 내려받은 복지서비스 상세 CSV 에서 고른 서비스만 `source/welfare_services.csv` 로 저장 (깨진 가운뎃점 복원) |
| `source/welfare_services.csv` | 실제 복지서비스 원본 발췌 (커밋 대상, seed 생성은 이 파일만 읽음) |
| `welfare_picks.py` | 고른 서비스 ID 와 원본에 없는 값(지원 대상 요약 · 연령 · 성별 · 정원 · 참여자 수 · 담당자) |
| `welfare_chuncheon.py` | 춘천시 통합돌봄 안내 자료에서 옮긴 실제 서비스 12종 (돌봄반찬은 제공기관별 3건으로 나눠 14건) |
| `resources_local.py` | 동 단위 가상 자원 (시연 기관이 운영한다고 가정, 실제 사업 아님) |
| `resources_city.py` | 춘천시 전역 가상 서비스 (실제 자료가 어르신 돌봄 위주라 청년 · 한부모 · 청소년 등을 지어 채움. 실제 제도명 · 기관명 · 금액은 쓰지 않고 운영 기관은 시연 기관의 가상 팀) |
| `scenario_hero.py` | 대표 사례자 7명 (고위험 동의 이야기, 사람이 쓴 상담 기록) |
| `scenario_cases.py` | 생성 사례자용 동 목록(위험 단계) · 위기 유형별 상담 문장 · 이름 후보 |
| `make_demo_seed.py` | 위 파일로 R__04 · R__05 생성 (고정 난수, 몇 번 돌려도 같은 결과) |

## 실행

```bash
# 원본 CSV 를 바꾸거나 고른 서비스를 바꿨을 때만
data/.venv/Scripts/python.exe data/demo_seed/extract_welfare.py "<복지서비스 상세 정보 CSV>"
# seed 생성 → 로컬 반영
data/.venv/Scripts/python.exe data/demo_seed/make_demo_seed.py
cd infra && docker compose run --rm flyway
```

생성된 R 파일은 직접 고치지 않는다. 내용이 바뀌면 Flyway 가 다시 실행하는데, 이미 있는 행은 건너뛴다
(자원: 자원명 · 운영 기관 · 시군구 · 행정동, 사례자: 기관 · 관리번호, 상담: 사례자 · 상담일 · 목적). 화면에서 고친 값은 그대로 남는다.

## 규칙

- 기관 · 담당자는 시연 기관 도메인과 시연 회원 이메일로 찾는다. 두 seed 가 없는 DB 에서는 아무것도 넣지 않는다.
- 사례자 이름 · 생년월일은 지어낸 값이다. 팀원 이름은 생성하지 않고, 상담 내용에는 이름 · 생년월일 · 연락처를 쓰지 않는다.
- 관리번호는 기관 · 등록 연도별 순번(2025-0001 …)이라 화면에서 새로 등록하면 다음 번호가 이어서 발급된다.
- 상담일은 2026-11-04 까지(미래 날짜 없음), 진행 중 사례는 마지막 상담이 최근 몇 주 안에 있다.
- 실제 복지서비스의 운영 기간은 올해(2026-01-01 ~ 2026-12-31, 원본 종료일이 더 빠르면 그 날짜)로 둔다.
- 이용자 부담금: 강남 서비스는 0. 춘천 통합돌봄 서비스는 안내 자료의 '일반' 본인부담금(1식 · 월 · 시간 · 회 단위는 지원 내용에 적음)이고,
  비율로만 정해진 방문진료 · 장기요양 재택의료는 0 으로 두고 지원 내용에 비율을 적었다 (화면에는 '무료'로 보이니 내용을 함께 확인).

## 출처

- 한국사회보장정보원 「복지서비스 상세 정보」(서울특별시, 최종수정일 2026-10-16 기준): 서비스명 · 담당 부서 · 시행 기간 · 지원 내용 · 신청 방법.
  공공데이터 이용 조건에 따라 출처를 표시하며, 지원 대상 요약 · 정원 · 참여자 수 · 담당자는 시연용 가정값이다.
- 춘천시 통합돌봄 안내 자료(식생활 · 일상생활 · 주거 · 의료 · 스마트 돌봄): 서비스명 · 대상 · 내용 · 본인부담금 · 제공기관.
  운영 기간 · 정원 · 참여자 수 · 담당자와, 자료에 적혀 있지 않은 신청 방법(읍면동 행정복지센터 통합돌봄 상담)은 시연용 가정값이다.
- 춘천의 나머지(청년 · 한부모 · 청소년 · 위기가구 등)는 가상 서비스(`resources_city.py`)다. 한국사회보장정보원 형식의 강원 자료를 구하면
  `extract_welfare.py` 로 넣고 `welfare_picks.py` 에 고른 ID 와 `SIGUNGU_BY_SIDO` 의 강원 → 51110 을 추가한다.
