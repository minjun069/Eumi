# 기준 문서 (docs/spec)

테이블 정의서 · API 명세 · 기능명세의 기준을 둔다. **md 파일이 원본**이고, 엑셀은 md에서 만든 열람 · 제출용이다.

| 문서 | 원본 (여기를 고친다) | 엑셀 | 판 | 함께 맞출 곳 |
|---|---|---|---|---|
| 테이블 정의서 | [table-definition.md](table-definition.md) | `이음이_테이블_정의서.xlsx` | 2.4.4 (11/17) | 실제 DB 구조는 `db/migration`이 기준이다. V 파일이 바뀌는 MR에서 함께 고친다 |
| API 명세 | [api-spec.md](api-spec.md) | `이음이_API_명세표.xlsx` | 2.6.0 (11/11) | 형식은 `docs/api/openapi.json`, 내부 연동은 `docs/api/*.md`가 기준이다. 계약이 바뀌는 MR에서 함께 고친다 |
| 기능명세 | [requirements.md](requirements.md) | `이음이_기능명세표.xlsx` | 2.4.0 (11/10) | 기능이 바뀌는 MR에서 함께 고친다 |

ERD의 최종 구조는 테이블 정의서에 들어 있다. 그림은 저장소 밖 ERDCloud에 둔다.

## 고치는 순서

1. md를 고친다. 엑셀만 따로 고치지 않는다.
2. 엑셀을 다시 만든다.
   ```bash
   pip install openpyxl                     # 처음 한 번
   python docs/spec/build_xlsx.py           # 엑셀 3개를 다시 만든다
   python docs/spec/build_xlsx.py --check   # 형식만 검사
   ```
3. md와 엑셀을 같은 커밋에 넣는다.
4. 판(파일 맨 위 `- 판:`)과 시트 머리의 요약(개수 등)이 달라졌으면 함께 고친다.

- 같은 md로 만들면 내용이 같은 엑셀이 나온다. 내용이 같으면 파일을 다시 쓰지 않으므로 다른 PC에서 만들어도 변경이 생기지 않는다. 그래서 md가 바뀌지 않았는데 엑셀만 바뀐 커밋이 있으면, 누군가 엑셀을 직접 고친 것이다.
- 형식이 틀리면 `build_xlsx.py`가 어디가 틀렸는지 알려 주고 멈춘다. 예를 들어 열 이름이 틀렸거나, ID가 겹치거나, 테이블 목록의 컬럼 수가 컬럼 정의의 행 수와 다를 때다.

## md 형식

- **시트:** `## 시트 이름`으로 나눈다. 이름은 `build_xlsx.py`의 `DOCS`에 있는 이름과 같아야 한다.
- **시트 머리:** 시트 이름 바로 아래에 둔다.
  - `- 제목:` → 엑셀 2행
  - `- 요약:` → 3행. `- 판:`이 있으면 그 앞에 붙는다
  - 그 밖의 줄 하나(`- 출처:` 등) → 4행
- **표 시트**(테이블 목록, 컬럼 정의 등): 마크다운 표로 적는다.
  - 묶음이 있는 시트(테이블 목록은 영역, 컬럼 정의 · 제약조건 · 인덱스는 테이블, 뷰 컬럼은 뷰)는 `### 묶음 값` 아래에 표를 나눠 둔다.
- **항목 시트**(API 목록, 기능 요구사항 등): `### ID 제목` 다음 줄부터 `- 열 이름: 값`을 한 줄씩 적는다. 값이 비면 `- 열 이름:`만 적는다.
- **칸 안의 줄바꿈:** `<br>`로 적는다.
- **표 칸 안의 `|`:** `\|`로 적는다.
- **SQL 원문 시트:** sql 블록을 줄마다 옮긴다. `-- @MIGRATIONS` 줄 자리에는 `db/migration`의 V 파일이 버전 순서로 들어간다.
- **열을 더하거나 이름을 바꿀 때:** `build_xlsx.py`의 `DOCS`도 같이 고친다.
