# 이음이 공통 응답 및 세션 규칙

API 전체에 적용하는 공통 계약이다. [openapi.json](openapi.json)의 작업 설명이 이 문서를 가리킨다. 작업마다 다른 내용은 openapi.json이 우선한다. 이 문서에 적었다고 해서 그 API가 구현 완료라는 뜻은 아니다.

## 기준과 우선순위

`db/migration`의 V 파일과 afterMigrate.sql은 물리 구조·참조·권한의 기준이다. 인증은 [docs/decisions/login-sse.md](../decisions/login-sse.md)를 따른다. 화면 동작은 기능명세([docs/spec/requirements.md](../spec/requirements.md))를 따른다. 구버전의 JWT·분석 release·outbox·번호 sequence 구조는 사용하지 않는다.

## 전송과 응답

동일 출처 기본 경로는 /api다. 운영 HTTPS, JSON UTF-8, camelCase를 사용한다. GET은 데이터 변경을 수행하지 않는다. 사례자·상담·자원 수정은 PUT, 내 정보는 PATCH다. POST 생성은 201, AI 실행 생성은 202, 본문 없는 성공은 204다. 204는 JSON으로 파싱하지 않는다. /health만 현재 구현대로 {status: UP}이며 공통 envelope의 예외다.

200·201·202의 일반 JSON 성공은 {success:true,data:DTO,meta:{requestId,timestamp}}다. 오류는 {success:false,error:{code,message,fieldErrors:[]},meta:{requestId,timestamp}}다. requestId는 UUID, timestamp는 시간대가 있는 ISO 8601이다. X-Request-Id와 본문 ID를 일치시킨다. 민감 응답은 Cache-Control: no-store를 사용한다. 서버 예외·SQL·암호·인증 코드 원문을 응답이나 로그에 넣지 않는다.

오류 상태는 400 입력·파싱, 401 비로그인·로그인 실패, 403 권한·변경 강제·CSRF, 404 대상 없음, 409 중복·처리 집합 변경, 413 업로드 크기, 415 파일 형식, 429 요청 제한, 500 내부 오류, 503 AI 연동 장애다. 엔드포인트별 코드는 OpenAPI를 따른다. UI는 200 오류 본문을 정상 데이터로 사용하지 않으며 프록시 HTML·빈 오류 본문도 통신 오류로 처리한다.

## 세션과 CSRF

Spring Session JDBC와 PostgreSQL의 spring_session·spring_session_attributes를 사용한다. 쿠키 이름 SESSION, Path=/api, HttpOnly, SameSite=Lax, Domain 미지정, 운영 Secure를 적용한다. session principal은 member_id 문자열이다. 유휴 만료 2시간은 로그인 결정 기록의 권장값을 구현 기준으로 구체화한 값이다. 클라이언트 회원 ID·sessionStorage 값을 인증 근거로 사용하지 않는다. Access·Refresh 토큰 발급·저장·회전·재발급 API는 없다.

새로고침 때 GET /api/auth/me로 복원한다. 401이면 로그인으로 이동하고 업무 캐시·열린 대화를 비운다. 403 PASSWORD_CHANGE_REQUIRED이면 비밀번호 변경 화면으로 이동한다. 임시 비밀번호 제한 세션에서 허용하는 업무 요청은 로그인 상태 조회·로그아웃·비밀번호 변경이다. CSRF 준비와 health는 인증 없이 접근할 수 있다.

GET /api/auth/csrf는 토큰을 실제 생성하고 XSRF-TOKEN 쿠키를 발급하는 신규 설계 경로다. 응답은 204다. 이 쿠키는 화면 경로에서 읽을 수 있게 Path=/, HttpOnly=false로 둔다. FE는 POST·PUT·PATCH·DELETE마다 원문 쿠키 값을 X-XSRF-TOKEN 헤더에 담는다. 로그인·회원가입·임시 비밀번호 발급 같은 비로그인 변경 요청도 포함한다. 세션 쿠키의 HttpOnly 속성과 구별한다. 로그인·로그아웃·비밀번호 변경 뒤 CSRF 토큰을 다시 준비한다. Spring Security의 SPA용 토큰 처리기를 맞춰 raw 쿠키 값과 XOR 토큰 처리가 어긋나지 않도록 한다.

로그인 성공은 세션 ID 교체와 SecurityContext 저장을 포함한다. 로그아웃은 현재 세션을 삭제한다. 비밀번호 변경은 다른 세션을 삭제하고 현재 세션 ID를 교체한다. 임시 비밀번호 발급·탈퇴는 회원의 모든 세션을 삭제한다.

## 입력과 값

내부 BIGINT ID는 JSON에서 1~9007199254740991 정수로 제한한다. conversationId는 UUID 문자열이다. 지역 코드는 문자열이며 시도 2자리·시군구 5자리·행정동 10자리다. 날짜는 YYYY-MM-DD, 월은 YYYY-MM, 일반 일시는 ISO 8601을 쓴다. PostgreSQL TIMESTAMP인 분석 updated_at은 Asia/Seoul 현지 시각으로 해석한 뒤 응답에서 오프셋을 붙인다. TIMESTAMPTZ의 순간값은 유지한다. DB 시간대는 Asia/Seoul이다.

일반 문자열은 trim 후 검증하고 선택 입력의 빈값은 null로 통일한다. 비밀번호는 trim하지 않는다. 문자열 길이는 Unicode 코드 포인트 기준으로 FE·BE를 맞춘다. 이름·회원 직함은 최대 100자, 자원명·수행기관명 50자, 지원 대상 100자, 지원 내용 1000자, 신청 방법 200자, 상담 목적 200자·본문 20000자·기타 20자다. 비밀번호 기본 규칙은 기존 계약의 8~128자와 영문·숫자·특수문자 포함을 유지한다. 비밀번호 해시는 PBKDF2(OPEN-04)이며 128자까지 자르지 않고 처리한다. 해시 계산은 DB 트랜잭션 · 연결 밖에서 한다 (비밀번호 변경 · 임시 비밀번호 발급 · 탈퇴 확인 · 회원가입).

fee·capacity·actualParticipants는 INT 상한 2147483647을 적용한다. fee는 0 이상, capacity는 1 이상, actualParticipants는 null 또는 0 이상이다. 실제 참여자 수의 정원 초과는 경고이며 저장 가능하다. supportAgeGroups는 하나 이상, 무관은 단독, 중복은 정규화한다. 지원 행정동이 있으면 시군구 접두어가 일치하고 dim_region에 있어야 한다. DB에 FK가 없는 시군구·기관 관할도 서비스가 유효성을 확인한다.

연령대는 만 나이 기준 18세 이하 청소년, 19~39세 청년, 40~64세 중장년, 65세 이상 노년이다. current_date는 한국 날짜 기준이다. 생년월일·최초 등록일·상담일의 미래 날짜는 거절한다. 등록 이후 최초 등록일을 바꿔도 기존 관리번호는 유지한다.

## 검색과 페이지

FE의 optional 검색값 null·빈 문자열은 HTTP query에서 생략한다. 문자열 null·undefined를 보내지 않는다. 화면 URL의 sido·sigungu·dir·capMin·capMax·manager·regFrom·regTo·recFrom·recTo를 API의 sidoCode·sigunguCode·direction·capacityMin·capacityMax·managerName·registeredFrom·registeredTo·recordedFrom·recordedTo로 변환한다. 화면 주소와 API query 이름이 다른 것은 어댑터 책임이다.

문자열 검색은 literal 부분 검색이며 %·_·역슬래시를 SQL 와일드카드로 취급하지 않는다. 정렬 키는 허용 목록만 사용한다. 검색 조건 변경 시 page=1, 페이지는 1부터, size 기본 10·최대 100이다. 결과가 없으면 totalCount=0·totalPages=0·page=1·items=[]다. 범위를 넘는 페이지는 마지막 페이지로 보정하고 응답 page에 실제 값을 넣는다. 동률 정렬에는 PK를 추가한다. URL 조건은 상세 복귀·새로고침에 유지한다. 사례자 최근 기록일 null은 양방향 정렬 모두 마지막이다.

사례자 중복 확인은 같은 기관의 본인 담당 사례자만 대상으로 하며 excludeCaseId는 제외한다. 타 담당자 전용 사례자의 존재나 관리번호를 노출하지 않는다. 복지자원은 모든 정렬에서 진행 중 우선 → 선택 sort/direction → 종료일 asc → resource_id asc를 유지하고 퇴사 담당자를 이름 검색에서 제외한다.

## 메일과 가입

가입 기관의 official_domain은 NOT NULL이다. 이메일을 소문자·trim으로 정규화해 도메인과 비교한다. 탈퇴 이메일도 재가입할 수 없다. 이메일 인증은 이메일당 한 행, 재발송 시 이전 행 폐기, 인증 코드와 가입 증명은 해시 저장이다. 코드 유효 10분·가입 증명 10분·재발송 간격 60초·실패 5회는 유지한 문서 구현값이다. 인증 메일 발송 단계부터 탈퇴 포함 기존 이메일은 EMAIL_ALREADY_EXISTS 409로 거절하고, 가입에서도 동시 중복을 다시 검사한다. 가입 성공 시 인증 행을 삭제한다. 인증 코드는 숫자 6자리(앞자리 0 허용), 가입 증명은 32바이트 무작위 값의 base64url(패딩 없음, 43자)이며 SecureRandom으로 만든다. 해시는 HMAC-SHA256(열쇠 eumi.auth.hash-key, 운영 EUMI_AUTH_HASH_KEY)으로 code_hash = HMAC("code:" + 정규화 이메일 + ":" + 코드), proof_hash = HMAC("proof:" + 증명)이고, 비교는 상수 시간으로 한다. 틀린 코드도 실패 횟수를 저장한 뒤 400을 반환한다.

임시 비밀번호는 member.password_hash를 덮어쓰므로 기존 비밀번호가 더 이상 유효하지 않다. temp_password_expires_at이 미래이면 제한 로그인, 지나면 로그인 실패, 유효 기간 중에는 재발급하지 않는다. 만료 24시간은 기존 문서에서 유지한 구현값이다. 임시 비밀번호는 12자이며 영문 대문자 · 소문자 · 숫자 · 특수문자(!@#$%^&*)를 각각 1자 이상 넣고 헷갈리는 글자(0 O o 1 l I)는 쓰지 않는다. 발급하면 그 회원의 세션을 모두 지운다. 비밀번호 변경 후 만료 컬럼은 null로 비운다. 일반 로그인과 임시 로그인 모두 data.user만 반환한다. 비밀번호 변경의 현재 암호 불일치는 CURRENT_PASSWORD_MISMATCH 400, 현재와 같은 새 암호는 NEW_PASSWORD_EQUALS_CURRENT 400이다. 탈퇴 확인의 암호 불일치는 WITHDRAW_PASSWORD_MISMATCH 400으로 구분해 입력창에 표시한다.

현재 DB에는 auth_mail_outbox·요청 제한 이벤트 테이블이 없다. IP당 요청 제한은 Nginx가 맡는다 (로그인 분당 10회 + 순간 10회, 인증 메일 · 임시 비밀번호 발송 합산 분당 3회 + 순간 3회, 초과 시 RATE_LIMITED 429). 이메일별 재발송 간격 60초와 코드 실패 5회는 인증 행으로 관리한다. 메일은 DB 변경과 같은 트랜잭션 안에서 커밋 직전에 보낸다. SMTP와 DB 커밋의 원자성을 보장한다고 적지 않는다. 코드/임시 암호 발급 실패 때 해당 시도의 DB 변경을 되돌리고, 메일 접수 후 DB 실패·SMTP 최종 전달 실패는 별도 운영 처리와 통합 검증 대상이다. 미등록·탈퇴·재발급 제한 계정의 임시 암호 요청도 같은 204를 반환해 존재 여부를 노출하지 않는다.

## 권한과 데이터 변경

사례자는 같은 기관이면서 담당자로 연결된 회원만 접근한다. 다른 기관 또는 없는 사례자는 404, 같은 기관 미담당은 403이다. 상담의 경로 사례자 소속도 검사한다. 담당자 최소 1명·동일 기관·활성 회원 조건은 DB FK만으로 보장되지 않으므로 서비스가 검사한다. 회원 탈퇴와 사례자 담당 수정은 같은 잠금 순서로 경합을 제어한다: 기관 행 → 회원(member_id 오름차순) → 사례자(case_id 오름차순) → 자원(resource_id 오름차순). 잠근 뒤 관련 조회를 다시 한다. 사례자 수정(API-23)은 상세(API-20)에서 받은 updatedAt(소수 6자리 · 오프셋 포함 문자열)을 그대로 돌려받아, 잠근 사례자 행의 updated_at과 마이크로초까지 비교하고 다르면 STATE_CONFLICT 409다. 403 · 404 판단이 409보다 먼저다. 담당자만 바꾼 수정과 탈퇴 인계도 updated_at을 바꾼다. 상세는 담당자 목록과 updatedAt을 한 읽기 스냅샷(REPEATABLE READ)에서 읽는다.

복지자원은 전체 기관이 조회할 수 있고 활성 담당자 본인만 수정·삭제한다. 삭제는 deleted_at 설정이며 조회는 v_resource_summary를 사용한다. 사례자·상담은 물리 삭제다. 관리번호는 기관 행 잠금 아래 next_management_no와 INSERT를 같은 트랜잭션에서 실행한다. 번호 재사용 가능성을 현재 DB 동작대로 반영한다. 9999 초과는 서비스가 409로 차단한다.

탈퇴 전 유일 담당 사례자와 진행 중 담당 복지자원을 모두 후임자에게 인계한다. 후임자는 같은 기관의 활성 회원이며 본인은 제외한다. 안내 조회 후 변동이 생기면 409로 다시 확인한다. 최종 요청의 transfers·resourceTransfers 집합은 현재 대상과 각각 정확히 일치해야 한다. 인계·공동 담당 해제·회원 soft delete·대화 전체 삭제는 원자적으로 수행하고 모든 세션을 폐기한다. 종료 자원 담당 FK와 상담 최초 기록자 FK는 유지한다. 후임자가 없어도 인계 대상 사례자와 진행 중 자원이 모두 없으면 빈 인계 배열로 탈퇴할 수 있다. 인계 대상이 있을 때만 후임자 부재로 거절한다. 탈퇴 안내(API-33)의 soleCases는 본인이 담당이고 본인 말고 활성 담당자가 없는 사례자(관리번호 순), sharedCaseCount는 본인 말고 활성 담당자가 1명 이상인 사례자 수(탈퇴하면 본인 담당만 빠짐), successors는 같은 기관 활성 회원 중 본인 제외(이름 · 회원 ID 순), ongoingResources는 v_resource_summary.status=진행 중인 담당 자원(자원 ID 순, 전부 인계), endedResourceCount는 종료 자원 수(담당 FK 유지, 탈퇴 뒤 퇴사자 표시), conversationCount는 보관 기간 안의 본인 대화 수다.


## 개정 2.2.0 추가 계약

인증 코드는 SMTP 메일로만 전달한다. 가입 증명 verificationToken은 API-06 성공 응답으로 전달하고 API-07 요청에서 한 번 사용한다. 코드와 가입 증명은 DB에 해시로만 저장하며 원문을 로그에 남기지 않는다.

resourceName은 trim 후 최대 50자의 자원명 부분 검색이며 공백만 있으면 조건을 생략한다. 다른 필터와 AND로 결합하고 퍼센트·밑줄·역슬래시는 문자 그대로 처리한다. sort=resourceName은 정렬 조건으로 구분한다.

manager는 정상 응답에서 항상 객체이며 withdrawn은 v_resource_summary.manager_withdrawn을 전달한다. 표시 상태 status=종료이고 withdrawn=true일 때만 name을 퇴사자로, title을 null로 반환하며 memberId와 orgName은 유지한다. 수동 종료와 종료일 경과에 따른 자동 종료 모두 포함한다. 진행 중 자원은 탈퇴 전에 활성 후임에게 인계해 후임 이름을 표시한다. 진행 중인데 탈퇴 담당자가 남으면 정합성 오류로 기록하고 정상 상세 응답 대신 500을 반환한다. manager=null을 퇴사 표시로 사용하지 않는다.

매일 한 번(기본 04:10 Asia/Seoul, 설정 eumi.batch.conversation-cleanup-cron) delete_scheduled_at <= 서울 오늘 날짜인 대화를 물리 삭제하고 메시지(`ai_message`)는 FK CASCADE로 함께 정리한다. 삭제 전에 관련 실행을 무효화해 늦은 답변 저장을 차단한다. 서울 날짜는 앱의 Clock으로 구해 넘기고 SQL current_date는 쓰지 않는다. 답변을 기다리는 질문이 있는 대화는 실행을 취소한 뒤 삭제하고, 삭제에 실패하면 늘어난 보관 기한을 되돌려 다음 실행의 대상으로 남긴다. 삭제는 대화 단위의 원자 처리를 적용하며 실패한 대상은 재실행 또는 다음 예약 실행에서 재시도한다. 반복 실행은 유효 대화를 보존하고 이미 삭제된 대화는 건너뛴다. 실행마다 runId · 기준 날짜 · 삭제 · 건너뜀 · 실패 건수 · 걸린 시간을 한 줄로 기록하고 질문·답변 원문은 로그에 남기지 않는다. 배치 실패 중에도 만료 대화는 목록·상세·후속 실행에서 제외한다.
