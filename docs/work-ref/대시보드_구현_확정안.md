# 이음이 대시보드 구현 기준

임베딩은 Tableau Public 워크북 eumi_tableau_main_dashboard_v_master를 따른다. 기존 eumi의 SVG Mock 화면과 구별하며 화면 레이아웃·URL 조건·업무 화면 이동은 eumi를 기준으로 이식한다. Tableau Public Embedding API v3로 화면 자리마다 같은 워크북의 임베드용 대시보드를 하나씩 띄우고, 매개변수를 첫 요청부터 넘긴 뒤 FirstInteractive 후 실제 값을 재검증한다. 지표 전환은 띄운 인스턴스 안에서 대시보드를 바꾼다. MarkSelectionChanged와 getMarksAsync로 '읍면동 코드'를 받는다.

개정: 11/3 새 워크북 기준으로 교체. 11/5 ④ 제외 · 첫 화면 지도 종합 위험 · ⑥은 읍면동 상세의 새 디테일 대시보드로 변경 · 도구 모음은 FE가 잘라 숨김 (tableau_views.json 3.1.0). 11/5 오후 ⑥ · 보고서 그래프 V01~V08의 상세 워크북 정보 추가 (3.2.0).

## 현재 연결 범위

① 지도는 지표별로 Embed01RiskMap(종합 위험도)·Embed01VulnerabilityMap(배경 취약성)·Embed01BehaviorMap(행동 이상), ②는 Embed02RiskDistribution(월별 종합 위험도 단계 분포), ③은 Embed03Vulnerability(읍면동별 배경 취약성 분포), ⑤는 Embed05BehaviorChange(읍면동별 전월 대비 행동 변화)에 연결했다. 각 임베드용 대시보드는 워크시트 하나를 담은 고정 크기(①·② 640px 폭, ③·⑤ 430px 폭)다. 첫 화면 지도는 종합 위험(Embed01RiskMap)이고 배경 취약성 · 행동 이상은 버튼으로 바꾼다(11/5). ④ 월별 행동 이상 지수 변화는 11/5 결정으로 메인 화면에 넣지 않으며, 오른쪽 열은 ③ 아래에 ⑤를 둔다. ⑥은 읍면동 상세 화면에 상세 워크북 eumi_tableau_main_dashboard_v2_0_6_connection_map_fixed의 EmbedDetailMap(워크시트 DETAIL_MAP_100m, 고정 640×560)을 임베드한다. 같은 워크북에 인사이트 보고서 그래프 후보 EmbedDetailV01~V08(대부분 720폭, V02는 720×560, V06은 900×440)이 있으며, AI가 동 · 월마다 고른 3~4개만 보고서에 임베드한다(보고서 계약 추가 예정). 상세 워크북은 49MB로 메인 v_master(72KB)보다 크므로 메인 화면은 v_master를 계속 쓴다. Tableau Public은 임베드에서 도구 모음 숨김을 받지 않아, FE가 대시보드 높이 + 27px로 띄운 뒤 아래 도구 모음을 잘라 숨긴다. 그래서 임베드용 대시보드는 모두 고정 크기를 유지해야 한다. 게시본 데이터는 강남구(11680)·춘천시(51110)의 2025-07~2025-12다. 인사이트·보고서는 서비스 API(API-11·12)로 연결하며 Tableau 뷰가 아니다. 게시본 데이터 갱신 방식(Google Sheets 자동 갱신 등)은 정해지지 않았다. 11/3 FE가 ①·②·③·⑤의 브라우저 동작(매개변수 적용·재검증, 지도 동 선택)을 확인했고, 11/5 배치 조정(④ 제외 · 종합 위험 기본 · 도구 모음 숨김)을 확인했다.

## 경계

Tableau 지도·그래프 조회는 서비스 REST API로 세지 않는다. Spring은 public.region_result에서 사용 가능 월, public.v_region_insight에서 요약, region_insight_report에서 저장 보고서를 조회한다. 파이프라인과 AI만 analysis에 접근한다. 전월 대비 요인 기여도는 analysis.bh_region_contribution을 데이터 담당이 내보내며 Spring에 analysis 권한을 추가하지 않는다. 격자 색상은 analysis.bh_grid_anomaly.anomaly_score이며 별도 위험 등급 컬럼이 없다.

## 필터와 데이터

지역과 기간은 필터가 아니라 매개변수로 넘긴다. p_city는 시군구 코드 5자리 문자열, p_start·p_end는 날짜이며 그 달 1일(YYYY-MM-01)이다. 기준 월을 쓰는 ①·③·⑤는 p_end, 기간을 쓰는 ②는 p_start~p_end를 쓴다. 모든 임베드용 대시보드가 같은 이름의 매개변수를 가지며, 매개변수는 워크북 단위라 대시보드를 바꿔도 유지된다. 지표는 종합 위험·배경 취약성·행동 이상 세 가지이고 매개변수가 아니라 ① 지도 대시보드를 바꿔 전환한다. 종합 위험(risk_grade)은 bg/bh 단계와 다른 개념이므로 화면에서 '종합 위험'으로 이름을 구분한다. 동 코드는 지도 마크 필드 '읍면동 코드'의 행정동 10자리이며 adm_cd8 통계청 코드와 혼용하지 않는다. ⑤의 마크에는 읍면동 코드가 없어 동 선택에 쓰지 않는다. 상세 워크북은 p_city · p_start · p_end에 더해 p_detail_adm(문자열, '시군구명 행정동명' 예: '강남구 역삼1동')을 쓴다. 행정동 코드가 아니라 이름이므로 API-11 응답의 시군구명과 행정동명으로 만들고, FirstInteractive 뒤 다시 읽어 같은지 확인한다. 대시보드 안쪽 필터(DETAIL_region · DETAIL_scope_* 등)는 화면에서 건드리지 않는다. 지도에서 하나의 유효 동을 선택했을 때만 URL을 바꾸고 빈 선택은 화면 조건을 되돌리지 않는다. 조건 적용은 직렬화하고 오래된 응답이 최신 조건을 덮지 못하게 한다. 갱신 중 이전 결과 표시 안내·클릭 차단·재시도를 유지한다.

## 완료 조건

실제 전용 뷰(①·②·③·⑤와 읍면동 상세의 ⑥)를 각각 확인한다(11/5 기준 ①·②·③·⑤ 확인, ④ 제외, ⑥ · V01~V08은 11/5 게시 확인 · 화면 연결 전). 게시되지 않은 자리에는 다른 뷰를 임시로 넣지 않는다. FE 월 목록(API-10)과 게시본 데이터의 지역·기준월이 일치해야 한다. 데이터 갱신 주체·게시 성공 확인·보고서 재생성 시점을 데이터 담당과 연결한다. 데이터 없음·보고서 준비 중·게시 오류를 구별한다. 기존 release 테이블·manifest 생성 구조가 현재 DB에 있다고 가정하지 않는다. 파일 검증용 버전 정보를 운영 보조 메타데이터로 둘 수 있지만 DB 계약과 구별한다.


## 최종 점검의 미확정 의미

[상세 계약](프로토타입_기능_상세_계약.md)의 대시보드 절을 적용한다. bg/bh 도시 내 등급·데모 고정 컷·종합 riskGrade·③ 상위20%=1분위는 같은 개념이 아니다. ②의 의미와 격자3단계/null/좌표계/SRID/geom은 DE1에서 확정한다. 저장소와 ERD로 산식을 확정했다고 판단하지 않는다. 게시본은 ②를 '월별 종합 위험도 단계 분포'(risk_grade 기준, 값이 없으면 '산출불가')로 만들었으며, 이 의미를 확정으로 볼지 분석 담당이 DE1에서 확인한다.
