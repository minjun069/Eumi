# 이음이 트랜잭션 구현 가이드

기준은 복사한 db/migration V1~V6 원문이다. 기존 JWT·메일 outbox·번호 sequence·트리거 의존 로직을 적용하지 않는다. 모든 서비스 트랜잭션은 eumi_app 권한으로 실행한다.

## 잠금 순서

담당자·탈퇴·회원 활성 상태가 교차하는 변경은 organization 행을 먼저 잠근다. 같은 기관의 변경끼리 직렬화한 뒤 member_id 오름차순, case_id 오름차순, resource_id 오름차순으로 잠근다. 기관별 사용자 수가 적은 현재 서비스에서 정확성을 우선한 문서 구현안이며 모든 관련 서비스가 같은 순서를 사용해야 한다. 관련 조회를 잠금 획득 후 다시 수행한다. 단순 조회 API에 잠금을 남발하지 않는다.

## 관리번호와 사례자 등록

organization FOR UPDATE 획득 후 동일 연도 최대 번호가 9999인지 검사한다. 초과하면 MANAGEMENT_NUMBER_EXHAUSTED 409를 반환한다. next_management_no(orgId, firstRegisteredAt)와 case_record INSERT, case_manager INSERT를 한 트랜잭션으로 묶는다. 등록자는 서버에서 자동 추가한다. 현재 함수는 기관 행 잠금 후 MAX를 읽으므로 무잠금 MAX+1과 다르며 마지막 번호 삭제 후 재사용이 가능하다. 함수 자체의 10000 처리 결함은 API 서비스의 사전 검사로 보완한다. eumi SQL을 이 작업에서 수정하지 않았다.

## 가입과 이메일 인증

이메일 정규화 후 email_verification 행을 잠근다. 코드·실패 횟수·만료·이메일·기관·증명을 검사한다. 회원 생성과 인증 행 삭제를 함께 커밋한다. 유니크 위반은 EMAIL_ALREADY_EXISTS 409로 변환한다. 실패 횟수 증가는 실패 응답이 예외로 반환돼도 롤백되어 사라지지 않도록 별도 짧은 트랜잭션으로 보존한다.

## 비밀번호와 세션

임시 비밀번호 발급은 활성 회원·현재 유효 임시 암호 여부를 잠금 후 재확인하고 password_hash와 temp_password_expires_at을 바꾼다. SMTP 실패 시 DB 변경을 되돌리고 원문을 로그에 남기지 않는다. DB와 외부 메일의 원자성 한계를 운영 기록에 남긴다. 비밀번호 변경은 기존 해시 검증·새 해시 저장·temp 만료 null 설정 뒤 다른 세션을 삭제하고 현재 세션 ID를 교체한다. Spring Session 저장 시점과 서비스 커밋 순서를 통합 테스트한다.

## 복지자원과 상담

자원 수정은 현재 담당자가 맞는지 행 잠금 후 검사한다. 담당자를 바꿀 때 같은 기관 활성 회원을 확인한다. 삭제는 soft delete다. 상담은 사례자 권한 확인과 대상 상담의 case_id 일치를 함께 검사한다. 기록자 ID는 생성 시만 설정하며 수정하지 않는다. 최근 기록일은 뷰의 MAX로 계산하므로 별도 업데이트가 필요 없다.

## 탈퇴와 진행 중 자원 인계

기관·탈퇴 회원·후임자·대상 사례자·자원을 순서대로 잠근다. 유일 담당 사례자 ID와 진행 중 자원 ID의 최신 집합을 재계산한다. 요청 집합·후임 활성 상태가 다르면 STATE_CONFLICT 409로 전부 롤백한다. 유일 담당 사례자에 후임 연결을 추가한 뒤 탈퇴자의 모든 case_manager 연결을 제거한다. 진행 중 자원의 manager_member_id를 후임으로 바꾸고 종료 자원의 담당 FK는 유지한다. 모든 대화와 turn을 삭제하고 member.withdrawn_at을 기록한다. 전체 세션을 삭제하며 실행 중 AI 메모리를 무효화한다. 상담 최초 기록자 FK는 유지한다.

## AI 완료 저장과 대화 삭제 경합

실행 생성 때 Spring이 runId와 conversationId UUID를 만든다. 신규 대화 행은 완료 답변 커밋 시 생성한다. 기존 대화는 소유권·보관 기간·삭제 여부를 잠금 후 재확인한다. ai_conversation_turn에는 마스킹 질문·progress_steps의 마지막 단계 상태·answer_blocks·asked_at·completed_at을 한 번만 저장한다. conversation의 last_message_at과 delete_scheduled_at을 한국 날짜 기준 마지막 완료일부터 3개월로 갱신한다. done은 커밋 후 보낸다. 실패·시간 초과는 turn을 저장하지 않는다. 메모리 run 상태 전이를 원자적으로 제어해 재연결이 중복 저장을 만들지 않게 한다. 대화 삭제와 탈퇴는 진행 중 run을 무효화해 늦은 응답이 행을 다시 만들지 못하게 한다. 단일 서버 재시작 시 run 소실은 410이며 이력 복원과 새 질문을 구분한다.

## 배치

대화 삭제 작업은 delete_scheduled_at <= current_date인 대화를 매일 삭제한다. 파이프라인은 dim_region·dim_grid100을 UPSERT하고 월/연도별 데이터는 해당 범위 DELETE 후 append 또는 UPSERT한다. DROP·전체 TRUNCATE·Spark overwrite를 쓰지 않는다. region_result 월 교체는 보고서·기여도 CASCADE 삭제를 동반하므로 후속 AI 보고서를 재생성한다.
