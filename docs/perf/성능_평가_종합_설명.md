두 번의 성능 평가를 한 번에 확인하는 자료(`이음이_성능_평가_종합.pdf` · `.html`, `dashboard-data-all/`)가 무엇을 담고 있고 어떻게 읽는지 적는다.

## 1. 파일

| 파일 | 내용 |
|---|---|
| `이음이_성능_평가_종합.pdf` · `.html` | 1회차와 2회차를 나란히 놓은 종합본 (A4 6쪽). 같은 내용이고 HTML은 브라우저에서 바로 열린다 |

## 4. 종합본 읽는 법

| 절 | 보는 것 | 읽는 법 |
|---|---|---|
| 맨 위 | 두 회차의 결론과 조건 | 1회차는 목표 9개 모두 충족(fake), 2회차는 12개 중 10개 충족 |
| 1. 실행 요약 | 회차 · 단계별 규모 | 요청 수 · 초당 요청으로 부하 크기를 본다. AI 끝 상태는 측정 구간에 시작한 질문 기준 |
| 2. 목표 대비 | 목표와 회차 · 단계별 가장 나쁜 값 | 2회차 판정이 빨간 줄이 목표 밖. 1회차 AI 값은 fake라 연동 지연만 비교할 수 있다 |
| 3. 화면 대기시간 | Tableau 화면 중앙값 그래프, 구간 전체 표 | 회색 계열 = 1회차(단독 · 동시 · 부하), 파란 계열 = 2회차(단독 · 동시), 빨간 막대 = 중앙값 목표 5초 초과. 표의 칸은 '중앙값 / p95' |

| 5. AI 대화 | 회차별 구간, 2회차 질문별 크레딧 | 1회차 최종 답변 약 4초는 가짜 답의 고정 시간이라 2회차(약 83 ~ 91초)와 비교하지 않는다 |

## 5. 두 회차를 비교할 때 주의할 점

- **AI는 직접 비교할 수 없다.** 1회차는 가짜 답(약 4초), 2회차가 실제 AI의 첫 실측이다. 첫 진행 안내와 연동 지연만 같은 뜻으로 비교된다. 연동 지연은 p95 기준 85ms에서 0.99초로 늘었는데, 둘 다 목표(1.5초) 안이다.
- **Tableau가 느려진 것은 워크북 변경과 시간대 영향이 섞여 있다.** 2회차는 통합 워크북으로 바뀌었고, Tableau Public 서버 응답은 같은 날에도 0.7초에서 2.1초까지 달랐다. 자체 API는 두 회차 모두 0.4초 안에 끝난다.
- **서버 조건이 다르다.** 2회차에는 kafka(CPU 평균 20 ~ 28%)와 Airflow가 같은 서버에서 돈다. 그래도 자체 서비스의 CPU 평균은 9% 이하다.
- **부하 50명은 1회차에만 있다.** 2회차는 서버 API가 바뀌지 않아 다시 재지 않았다.
- **동시 · 부하 단계의 화면 값은 5회 측정**이라 p95가 사실상 최댓값이다. 2회차 Tableau 중앙값 초과(5.20초)도 5회의 결과다.
- **자체 API 시간은 PC에서 본 값**(네트워크 포함)이다.
- **2회차 측정 시각:** 화면 E1 · E2 · E4 · 화면 유지와 탐색 1명은 ai 재배포 전, 화면 E3 · AI 1명 · 동시 20명은 뒤에 쟀다. 그 배포에서 바뀐 것은 ai 이미지뿐이다.

## 6. 용어

| 용어 | 뜻 |
|---|---|
| 중앙값 / p95 | 줄 세웠을 때 가운데 값 / 100번 중 95번째로 느린 값 |
| 단독 / 동시 20 / 부하 50 | 1명 / 탐색 15 + AI 5 / 탐색 40 + AI 10 |
| 사용 가능 | Tableau 그래프가 다 떠서 누를 수 있게 된 때 |
| 시연 동 미리 띄우기 | 시군구 지도가 뜬 뒤 역삼1동 화면을 숨긴 채 미리 띄워 두는 것 |
| 화면 유지 | 다른 화면 · 메뉴로 갔다 와도 Tableau를 다시 불러오지 않는 것 |
| 첫 진행 안내 / 연동 지연 | 질문 뒤 첫 안내가 화면에 오기까지 / AI가 저장한 때부터 화면이 받기까지 |
| GMS 크레딧 | gpt-6-luna 기준 입력 1,000토큰당 1 + 출력 1,000토큰당 5 |
| 실행 기록 | ai가 실행마다 남기는 자세한 기록. 운영 ai는 메모리 공간 512MB에 쓴다 |
| 임시 ai | 보고서를 만들 때만 띄우는 두 번째 ai 컨테이너 (600초 · 재시도 6번) |
