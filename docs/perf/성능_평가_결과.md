## 2. 흐름별 결과 (계획 5절 형식)

### E1 로그인 · 첫 화면
1. **평가 조건:** 단독 20회. 로그인 버튼을 누른 순간부터. 로그인 사이 7초 이상 (Nginx 로그인 제한).
2. **현재 성능:**

   | 구간 | 중앙값 | p95 |
   |---|---|---|
   | 로그인 API | 0.36초 | 0.38초 |
   | 위험 탐색 화면 도착 | 0.40초 | 0.42초 |
   | 자체 API 끝 | 0.49초 | 0.58초 |
   | 첫 그래프 사용 가능 | 2.77초 | 3.27초 |
   | 그래프 4개 사용 가능 | 3.52초 | 3.99초 |

   실패 · 그래프 오류 0.
3. **주요 지연 원인:** Tableau. 자체 API는 0.6초 안에 끝나고 나머지 약 3초가 Tableau 그래프를 기다리는 시간이다. 로그인은 비밀번호 확인(PBKDF2)이 무거워, 동시 · 부하 시험 준비에서 8명이 한꺼번에 로그인한 순간 backend CPU가 95~121%(CPU 한 개 기준)까지 올랐다. 1~2초 안에 끝나는 순간 부하다.
4. **개선 필요 여부:** 개선 불필요 (Tableau 8초 · API 화면 2초 목표 안).

   | Tableau 요청 시작 | 0.21 / 0.23초 | 0.21 / 0.24초 | 0.23 / 0.33초 |
   | 첫 그래프 사용 가능 | 2.35 / 2.72초 | 2.74 / 3.21초 | 2.77 / 3.69초 |

3. **주요 지연 원인:** Tableau. 자체 API가 0.2초에 끝나고 Tableau 요청이 바로 이어서 시작한다. 그 뒤 약 2.7초(단독 중앙값 기준 전체의 약 93%)가 Tableau를 기다리는 시간이다. 사용자가 늘수록 p95가 0.6~1.0초 올랐지만, k6는 Tableau를 부르지 않고 자체 API 끝 · Tableau 시작 시각은 그대로라 우리 서버 부하 때문이 아니다. Tableau Cloud 쪽 응답 편차와 작은 표본(5회)으로 본다.
4. **개선 필요 여부:** 개선 불필요 (최초 8초 · 조건 변경 5초 목표 안).

### E4 사례자 · 복지자원
1. **평가 조건:** 단독 20회. 목록 첫 쪽 → 첫 행 상세. 시연담당 2에게 배정된 사례자 12명.
2. **현재 성능:** 사례자 목록 0.30 / 0.38초, 사례자 상세 0.08 / 0.10초, 복지자원 목록 0.08 / 0.10초, 복지자원 상세 0.10 / 0.12초 (중앙값 / p95). k6 기준 목록 API p95는 단독 34~35ms, 부하 50에서 28~29ms.
3. **주요 지연 원인:** 사례자 목록이 가장 긴 것은 그 창의 첫 화면이라 앱 파일을 내려받는 시간이 들어 있어서다.
4. **개선 필요 여부:** 개선 불필요. 저장(버튼 → 완료 안내)은 이번 회차에서 재지 않았다.

### E5 AI 패널 (fake 모드)
1. **평가 조건:** 질문 → 1초 조회 → 끝 행 → 대화 삭제 → 10~20초 쉼. AI 사용자 단독 1명, 동시 5명, 부하 10명. backend fake 단계(1초 간격 3단계 + 완료).
2. **현재 성능:**

   | 구간 | 단독 (16건) | 동시 20 (77건) | 부하 50 (156건) |
   |---|---|---|---|
   | 질문 → 첫 진행 안내 | 1.04 / 1.06초 | 1.04 / 1.06초 | 1.04 / 1.05초 |
   | 질문 → 최종 답변 | 4.10 / 4.13초 | 4.10 / 4.13초 | 4.09 / 4.12초 |
   | AI 처리 (서버 기록) | 4.02 / 4.02초 | 4.01 / 4.02초 | 4.01 / 4.02초 |
   | 연동 지연 (저장 → 화면) | 53 / 85ms | 53 / 89ms | 49 / 80ms |
   | 질문 · 조회 · 삭제 API p95 | 33 · 23 · 24ms | 39 · 26 · 25ms | 27 · 24 · 24ms |

   질문은 모두 '완료'로 끝났다 (실패 · 시간 초과 0).
3. **주요 지연 원인:** fake 단계 시간(약 4초)뿐이다. AI 사용자가 10명이 돼도 저장 → 화면 전달은 늦어지지 않았다. 단, fake는 정확히 1초마다 저장하고 화면도 1초마다 조회해 박자가 맞으므로, 실제 AI에서는 조회를 기다리는 시간(0~1초)이 연동 지연에 더해진다.
4. **개선 필요 여부:** 지금은 개선 불필요. 실제 AI 처리 시간 · 연동 지연은 http 전환 뒤 E5 실측에서 다시 판단한다.
