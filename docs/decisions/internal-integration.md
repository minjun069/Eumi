# 결정 기록: 내부 연동 (BE · AI · 파이프라인)

- **결정일:** 2026-11-06 (11/7 되묻기 처리 보완)
- **결정:** 파이프라인 · BE · AI 사이의 연동을 아래 13개 항목으로 정했다. 모두 ERD 구조를 바꾸지 않는다.
  - 보고서는 AI가 직접 저장한다.
  - 대화 실행 요청은 `messageId`로 멱등하게 한다.
  - INT-03 · 06을 없애고 INT-07 · 08 알림을 더한다.
- **판단 원칙:**
  1. ERD를 바꾸지 않는 방식을 먼저 고른다.
  2. 둘 다 ERD를 바꾸지 않으면 차이를 비교해 권장안을 고른다.
  3. AI 초안의 나은 점은 ERD를 바꾸지 않는 선에서 받아들인다.
  4. 내부 API JSON은 camelCase로 쓴다.
- **구현 계획 (진행 중):** [docs/work-ref/내부_연동_변경_계획.md](../work-ref/내부_연동_변경_계획.md). 구현이 끝나면 [docs/api](../api/README.md)의 계약 문서에 반영한다.
  - 1번(보고서 저장 주체)은 권한 변경이 운영에 반영돼 11/9에 먼저 반영했다: INT-06 삭제, 저장 문장은 [insight-report.md](../api/insight-report.md) 4절.
- **출처:** 11/6 AI 담당자에게 전달한 'AI 연동 초안 변경 요청 (11/6 결정 반영)'

## 결정에 영향을 준 조건

- AI 쪽 연동 초안(`docs/ai-runtime-api-20261029.md`, 11/6 수정)과 우리 계약(`docs/api`)이 어긋나 있었다.
- 11/6 ERD 논의로 보고서 표 구조(퀵 인사이트 + 그래프 3개)가 정해졌고, 1단계 V 파일이 운영에 반영됐다.
- AI 담당자가 11/6에 요청했다.
  - 보고서 직접 저장
  - INT-05에서 꼬리표 없이 동 목록만 전달
  - 본문 없는 202
  - 완료 알림
  - waiting_input을 완료처럼 다루기
- 개발 마감이 가깝다 (11/8 목표, 늦어도 11/12). 표를 새로 만들거나 상태 값을 늘리는 변경은 일정 위험이 크다.
- 시연 데이터(2025-07~12)는 고정이다.

## 받아들인 한계

- 12 · 13단계만 다시 돌리면 꼬리표가 같다. 그래서 겹친 실행 중 늦게 끝난 쪽이 덮을 수 있다(10번 규칙으로 막음).
- 결과 적재와 보고서 저장이 동시에 진행되면 옛 꼬리표로 저장될 수 있다. 그 행은 조회에서 숨겨지고, 그 달 INT-04를 다시 보내면 복구된다.
- 실행 ID · 배포 버전은 보고서에 남지 않는다. AI 로그로 찾는다.
- 되묻기 뒤의 답은 새 질문이 되어, 원래 질문과 최종 답이 다른 질문 묶음에 들어간다.

## 다시 검토할 조건

- **실제 운영으로 갈 때:** 생성 기록 표(B 방식)를 더해 실행 ID · 버전을 DB에 남긴다.
- **원래 질문과 최종 답을 한 묶음으로 보여 주거나 집계해야 할 때:** `waiting_input` 상태와 답변 행 연결이 필요하다. ERD 변경이다.
- **글자 단위 표시나 실시간 전달이 필요할 때:** INT-07을 화면 전달의 출발점으로 쓴다.
- **화면 문맥 전달(9번)이 일정 안에 어려울 때:** 대안 A로 간다.
