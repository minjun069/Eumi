## 1. 구성 한눈에

```
사용자 ─ https ─> Nginx(443) ─┬─ /api/      → backend   127.0.0.1:8080 ─> postgres (내부망, 포트 없음)
                              │                 └─ http://ai:8000 → ai (내부망, 포트 없음) ─> postgres · LLM API
                              ├─ /jenkins/  → Jenkins   127.0.0.1:9090
                              ├─ /airflow/  → pipeline-web (Airflow 화면) 127.0.0.1:8081
                              ├─ /grafana/  → grafana   127.0.0.1:3001
                              └─ /          → web       127.0.0.1:3000
내부망만: pipeline(Airflow 스케줄러 + Spark) ─> minio · kafka · postgres
master 병합 ─> GitLab 웹훅 ─> Jenkins: Plan → Sync → Build → Migrate(백업 → Flyway) → Deploy(헬스체크 · 실패 시 되돌림) → Pipeline → Monitoring → Cleanup
```

## 3. 환경 변수와 비밀값

### 3-1. 원칙

- 운영 비밀값은 서버 파일 `/srv/eumi/.env.config` 하나에만 있습니다 (소유 jenkins, 권한 600). 저장소 · 문서 · 채팅에 값을 올리지 않습니다.
- 저장소에는 키 이름만 있습니다: `infra/deploy/.env.config.example`
- 운영 compose는 비밀값을 `${키:?…}` 형태로 받아, 값이 비면 배포가 그 자리에서 멈춥니다.
- `application-prod.yml`은 기본값이 없어서, 값이 빠지면 backend가 뜨지 않고 `deploy.sh`가 이전 버전으로 되돌립니다.

### 3-2. 서버에서 비밀값을 만드는 흐름

1. **무작위 값은 서버에서 만듭니다.** 비밀번호류는 `openssl rand -hex 24`(48자), 서명 · 토큰류는 `openssl rand -hex 32`(64자)를 씁니다. `0-9a-f`만 나와서 compose · `.env`에서 깨지지 않습니다.
2. **DB 비밀번호는 postgres를 처음 띄우기 전에 정합니다.** postgres가 빈 볼륨으로 처음 뜰 때 이 값으로 계정을 만들기 때문에, 그 뒤에 파일 값만 바꾸면 접속이 실패합니다.
3. **외부에서 받는 키**(GMS · 공공데이터포털 · Kakao · Mattermost 웹훅)는 화면에 보이지 않게 입력해 파일 끝에 붙입니다.
4. **값을 화면에 출력하지 않고 확인합니다** (키 이름과 길이만).
5. **서버 밖 사본**은 인프라 담당이 개인 보관함에 한 번 저장합니다. 서버가 사라졌을 때 백업을 복원하려면 필요합니다.

무작위 값 한 번에 만들기 (jenkins 계정, 파일이 이미 있으면 덮어쓰지 않음):

```bash
sudo -u jenkins bash <<'EOF'
set -e
umask 077
f=/srv/eumi/.env.config
[ -e "$f" ] && { echo "이미 있습니다. 덮어쓰지 않습니다"; exit 1; }
h24() { openssl rand -hex 24; }
h32() { openssl rand -hex 32; }
cat > "$f" <<CONF
# 운영 비밀값 원본 ($(date +%F) 서버에서 생성). git · 문서 · 채팅에 올리지 않는다
POSTGRES_PASSWORD=$(h24)
EUMI_OWNER_PASSWORD=$(h24)
EUMI_APP_PASSWORD=$(h24)
EUMI_PIPELINE_PASSWORD=$(h24)
EUMI_AI_PASSWORD=$(h24)
EUMI_AUTH_HASH_KEY=$(h32)
EUMI_AI_TOKEN=$(h32)
EUMI_PIPELINE_TOKEN=$(h32)
MINIO_ROOT_USER=eumi_minio
MINIO_ROOT_PASSWORD=$(h24)
AIRFLOW_DB_PASSWORD=$(h24)
AIRFLOW_ADMIN_USER=admin
AIRFLOW_ADMIN_PASSWORD=$(h24)
AIRFLOW_SECRET_KEY=$(h32)
GRAFANA_ADMIN_PASSWORD=$(h24)
EUMI_MONITOR_PASSWORD=$(h24)
CONF
EOF
```

외부에서 받은 키 붙이기 (키마다 두 줄. `read` 줄은 따로 한 줄씩 붙여 넣습니다):

```bash
read -rs -p "EUMI_LLM_API_KEY: " V; echo
printf 'EUMI_LLM_API_KEY=%s\n' "$V" | sudo -u jenkins tee -a /srv/eumi/.env.config > /dev/null; unset V
```

같은 방법으로 `DATA_GO_KR_SERVICE_KEY`, `KAKAO_REST_KEY`, `MATTERMOST_WEBHOOK_URL`(선택)을 붙입니다.

값을 보지 않고 확인하기:

```bash
sudo ls -l /srv/eumi/.env.config                                                   # -rw------- jenkins jenkins
sudo -u jenkins awk -F= '/^[A-Z]/{print $1, length($2)}' /srv/eumi/.env.config     # 키 이름과 길이만
```

### 3-6. 빌드할 때 쓰는 변수

- **frontend**: 빌드 환경 변수가 없습니다. API는 같은 도메인의 `/api`로 부릅니다.
- **backend**: 빌드는 변수 없이 `bootJar`만 합니다. 실행 값은 모두 위 환경 변수로 받습니다.
- **ai**: `uv.lock` 그대로 설치합니다. 실행 값은 `SETTINGS_*` 환경 변수로 받습니다.
- **로컬 개발**: `infra/.env.example`(DB · 파이프라인 · Grafana), `ai/.env.example`(AI)을 `.env`로 복사해 씁니다. 로컬 값을 운영에 쓰지 않습니다.

## 4. 클론부터 배포까지

처음 한 번은 손으로 배포하고, 그 뒤로는 master 병합 때마다 Jenkins가 자동으로 배포합니다.

### 4-1. 서버 기본 설정 (처음 한 번)

```bash
sudo apt update && sudo apt upgrade -y
sudo timedatectl set-timezone Asia/Seoul && sudo systemctl restart cron

sudo ufw allow 22/tcp && sudo ufw allow 80/tcp && sudo ufw allow 443/tcp
sudo ufw status verbose                           # Default: deny (incoming), 22 · 80 · 443 ALLOW

sudo fallocate -l 4G /swapfile && sudo chmod 600 /swapfile && sudo mkswap /swapfile && sudo swapon /swapfile
grep -q '^/swapfile ' /etc/fstab || echo '/swapfile none swap sw 0 0' | sudo tee -a /etc/fstab
echo 'vm.swappiness=10' | sudo tee /etc/sysctl.d/99-eumi-swap.conf && sudo sysctl -p /etc/sysctl.d/99-eumi-swap.conf

sudo usermod -aG docker ubuntu
sudo usermod -aG docker jenkins                   # Jenkins가 이미지 빌드 · 배포 스크립트를 실행
```

### 4-7. DB 기동 · 백업 · Flyway

```bash
sudo -u jenkins /srv/eumi/scripts/migrate.sh
```

- postgres가 빈 볼륨으로 처음 뜨면 `postgres-init/`이 계정(`eumi_owner` · `eumi_app` · `eumi_pipeline` · `eumi_ai` · `eumi_monitor` · `airflow`)과 DB(`eumi` · `airflow`)를 만듭니다.
- 이어서 배포 전 백업 → Flyway가 `db/migration` 스키마와 `db/seed` 시연 데이터를 넣습니다. Flyway만으로 시연 상태(기관 · 시연 회원 · 사례자 · 복지자원 · 분석 결과 · 시연용 보고서)가 만들어집니다.
- 운영과 똑같은 마지막 상태(AI 생성 보고서 · 대화 기록 포함)가 필요하면 Flyway 대신 `exec/3_DB_덤프/`의 덤프를 복원합니다 (그 폴더의 복원 방법 참고).

**처음 만든 볼륨에서는 아래를 한 번 더 실행합니다.** 운영 compose의 postgres에는 `AIRFLOW_DB_PASSWORD` · `EUMI_MONITOR_PASSWORD`가 넘어가지 않습니다. 그래서 처음 기동 때 두 계정이 `.env.config`와 다른 비밀번호로 만들어집니다. 파일 값으로 맞춥니다 (값은 화면에 나오지 않습니다).

```bash
sudo -u jenkins bash <<'EOF'
set -e
cd /srv/eumi
get() { grep -E "^$1=" .env.config | head -1 | cut -d= -f2-; }
AF=$(get AIRFLOW_DB_PASSWORD); MON=$(get EUMI_MONITOR_PASSWORD)
[ -n "$AF" ] && [ -n "$MON" ] || { echo "키 값이 없습니다"; exit 1; }
printf "ALTER ROLE airflow PASSWORD '%s';\nALTER ROLE eumi_monitor PASSWORD '%s';\n" "$AF" "$MON" \
  | scripts/dc.sh exec -T postgres psql -U postgres -v ON_ERROR_STOP=1 -q
EOF
```

## 5. 배포 특이사항

**배포 방식**
- master에 병합될 때만 배포합니다. Jenkins는 바뀐 서비스만 빌드 · 교체합니다(ai → backend → web 순서).
- `ai/` 바로 아래 `.md`와 `ai/docs/`만 바뀌면 ai를 다시 빌드하지 않습니다.
- 운영 compose가 바뀌면 앱 서비스 전체를 다시 배포합니다.
- 무중단 배포가 아닙니다. 교체하는 몇 초 ~ 1분 동안 그 서비스 응답이 끊길 수 있습니다.

**DB**
- Migrate 단계는 배포마다 돌아 백업 → Flyway를 합니다. Flyway가 실패하면 서비스는 바뀌지 않습니다.
- 병합된 마이그레이션 파일은 고치지 않고 새 파일로 추가합니다.
- 컬럼 삭제처럼 이전 코드가 깨지는 변경은 "추가 → 코드 전환 → 다음 배포에서 삭제"로 나눕니다.

**되돌리기**
- 헬스체크가 실패하면 이전 태그로 자동 복귀합니다.
- 서비스마다 최근 이미지 3개를 남겨 롤백 지점으로 씁니다.

**Nginx · 포트**
- Nginx 설정은 Jenkins가 쓰지 않습니다. 병합 뒤 인프라 담당이 서버에 직접 반영하고, 저장소와 다르면 Jenkins가 빌드를 노란색(UNSTABLE)으로 표시합니다.
- 바깥 포트는 22 · 80 · 443뿐입니다. 관리 화면(Jenkins · Airflow · Grafana)은 Nginx 경로로만 들어오고 각자 로그인이 필요합니다.

**메일**
- 실제 SMTP 없이 Mailpit이 메일을 모아 둡니다. 가입 인증 코드와 임시 비밀번호 메일은 서버의 127.0.0.1:8025에서만 볼 수 있어 SSH 터널로 엽니다.
  ```bash
  ssh -i <키 파일> -o ServerAliveInterval=60 -L 18025:127.0.0.1:8025 ubuntu@k15b201.p.ssafy.io     # PC에서 http://localhost:18025
  ```

**AI**
- 운영 모델은 `gpt-6-luna`입니다. 코드 기본값은 `gpt-6-sol`이므로 compose의 `SETTINGS_MODEL`을 빼지 않습니다.
- 실행 기록은 메모리 512 MB에 쌓입니다(질문 하나 14 ~ 34 MB). 시연 전이나 부하 시험 뒤, 진행 중인 질문이 없을 때 재시작해 비웁니다.
  ```bash
  sudo docker exec eumi-ai-1 df -h /app/outputs      # 남은 공간
  sudo docker restart eumi-ai-1                      # 비우기 (수십 초 동안 대화 패널 응답 없음)
  ```
- 인사이트 보고서 생성 요청은 서버 안에서만 보냅니다. Nginx가 `/api/internal/`을 막고, ai는 바깥 포트가 없으며, 월 배치 DAG는 생성 요청을 보내지 않습니다.

**데이터 파이프라인**
- 과거 달 월 배치와 기준 테이블 적재(`load_dim_region.py` · `load_dim_grid100.py`)를 서버에서 다시 돌리지 않습니다. 같은 내용이 `db/seed`로 이미 들어가 있고, 다시 돌리면 결과가 덮입니다.
- Grafana · MinIO · Kafka는 `dc.sh up`으로 직접 띄우지 않고 `deploy.sh pipeline` · `grafana.sh`로만 띄웁니다(비밀값이 비면 기본 비밀번호로 뜨는 것을 막음).

**백업**
- `eumi` DB만 백업합니다(`airflow` DB와 MinIO 볼륨은 제외).
- 매일 04:30(최근 7개)과 배포 직전(최근 10개)에 `/srv/eumi/backups/`에 쌓입니다.
- 위험한 작업 전에는 `backup.sh manual`을 실행합니다.

**정기 작업**
- backend가 매일 04:10에 보관 기간(3개월)이 지난 AI 대화를 지웁니다.

**자원**
- 컨테이너 메모리 상한의 합(16.5 GB)이 실제 메모리(15.7 GB)보다 큽니다. Spark 월 배치가 돌 때가 위험 구간이라, 배치는 사용자가 적은 시간에 돌립니다.

**금지**
- `dc.sh down -v`는 도우미가 막습니다.
- 서비스 교체는 `up` 대신 `deploy.sh`로 합니다. `up`으로 바꾸면 헬스체크 · 되돌림 · 기록이 빠집니다.
